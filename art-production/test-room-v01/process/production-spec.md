# 테스트 방 아트 리소스 생산 규격서

대상: 땅굴 크루 지층 1 디오라마형 최종급 버티컬 슬라이스  
생산 담당: Codex 아트 트랙  
구현 담당: Claude 구현 트랙  
기준 투영: `ReferenceTopDown` 직교 3/4 톱다운  
기준 문서: `docs/unity-visual-overhaul-functional-spec.md`

## 1. 목적과 생산 원칙

이 문서는 첫 테스트 방을 만들면서 확정한 제작 규격과 반복 가능한 생산 절차를 보존한다.
초기 패키지는 작은 방 하나만 완성하지만, 이후 지층별 환경 키트도 동일한 파일·채널·검수 계약을
따른다.

- 레퍼런스의 화면을 복제하지 않고, 깊이층·명암 구조·재질 대비·조명 역할을 땅굴 크루의 고유
  폐광 세계관으로 재해석한다.
- 프로덕션 화면은 무회전·무압축 직교 투영인 `ReferenceTopDown`만 인증한다.
- 바닥은 조용하고 낮은 대비, 벽과 구조물은 큰 실루엣과 수직 면, 상호작용물은 명확한 색·발광으로
  구분한다.
- AI 생성 결과는 즉시 최종 타일로 간주하지 않는다. 콘셉트 승인, 분리·클린업, 채널 제작,
  조립 검수 순서를 거친다.
- Unity 코드·씬·프리팹·프로젝트 설정은 이 아트 트랙에서 수정하지 않는다.

## 2. 테스트 방 비주얼 브리프

작은 폐광 정비실을 한 화면 디오라마로 구성한다. 방 후면 중앙에는 청록빛 심연으로 연결되는
두꺼운 산업 아치가 있고, 한쪽에는 보라 결정 광맥과 고장 난 드릴 설비가 있다. 바닥 중앙은
전투와 이동을 위해 넓고 조용하게 비우며, 앰버 작업등과 청록 외광, 약한 마젠타 광맥광이 서로
겹쳐 재질의 부피를 설명한다. 전면에는 낮은 난간·암반·케이블이 일부 화면을 가려 전경층을 만든다.

목표 깊이층:

1. 검은 공극과 먼 암벽
2. 후면 아치와 높은 벽
3. 벽 상단·정면·기둥·배관
4. 이동 가능한 바닥과 접촉 AO
5. 캐릭터·적·기능 소품
6. 전경 난간·암반·매달린 케이블
7. 안개·먼지·광선·발광 입자

팔레트 기준:

| 역할 | 색상군 | 용도 |
|---|---|---|
| 기본 암부 | 짙은 자주·남청·숯색 | 공극, 후경, 벽의 비조명 면 |
| 구조 중간톤 | 차가운 회보라·청회색 | 바닥, 금속, 암석의 읽히는 면 |
| 주 광원 | 청록·시안 | 아치 너머 외광, 깊이와 진행 방향 |
| 보조 광원 | 앰버·주황 | 작업등, 상호작용물, 따뜻한 국소 초점 |
| 위험·광물 | 마젠타·보라 | 결정, 균열, 위험한 에너지 |

## 3. 좌표·해상도·카메라 계약

- 논리 셀: 1×1 Unity unit.
- 최종 픽셀 밀도: 128 PPU, 즉 1셀 footprint는 128×128px.
- 원화 작업 밀도: 256px/셀 이상. 최종 배포용은 128px/셀 기준으로 축소·샤프닝한다.
- 투영: 화면 X/Y와 월드 X/Y가 평행한 직교 톱다운. 타일 다이아몬드 회전이나 세로 압축을
  원화에 선반영하지 않는다.
- 기본 벽 정면 높이: 96~192px(0.75~1.5셀). 영웅 구조물은 384px(3셀) 이상 허용한다.
- 캐릭터 기준 높이: 약 154~192px, 발점부터 머리까지 1.2~1.5셀.
- 모든 자산은 정수 픽셀 캔버스와 정수 픽셀 피벗을 사용한다.
- 기본 안전 패딩: 8px. Bloom이 강한 Emission은 16px.

## 4. 파일과 폴더 규격

```text
art-production/test-room-v01/
  reference/      분석용 레퍼런스 프레임
  concept/        키아트와 모듈 보드
  source/         분리·보정 전 고해상도 원본
  working/        클린업 및 채널 제작 중간물
  approved/       Unity 구현에 인계 가능한 승인본
    albedo/
    normal/
    emission/
    mask/
    ao/
    vfx/
  metadata/       manifest, 피벗, footprint, 소켓, 검수 결과
  prompts/        생성 프롬프트와 반복 이력
```

파일명은 소문자 영문과 숫자, 밑줄만 사용한다.

`tr01_<category>_<name>_<variant>_<channel>.png`

예:

- `tr01_wall_front_rock_a_albedo.png`
- `tr01_arch_gate_a_emission.png`
- `tr01_prop_worklamp_b_normal.png`
- `tr01_vfx_dust_motes_a.png`

채널 접미사: `albedo`, `normal`, `emission`, `mask`, `ao`. 개념 보드는 `_concept`, 배치 보드는
`_layout`을 사용한다. 기존 승인본은 덮어쓰지 않고 manifest의 revision과 상태를 갱신한다.

## 5. 이미지·채널 스펙

| 채널 | 형식 | 색 공간 | 알파 | 제작 규칙 |
|---|---|---|---|---|
| Albedo | PNG RGBA 8-bit | sRGB | 실제 실루엣 | 방향광·강한 투사광을 굽지 않고 재질 고유색과 약한 자체 음영만 포함 |
| Normal | PNG RGB(A) 8-bit | Linear | Albedo와 동일 권장 | Unity 2D Lit용 탄젠트 공간, 평면 중립값 `(128,128,255)` |
| Emission | PNG RGB(A) 8-bit | Linear | 발광 실루엣 | 비발광 검정, 광원 중심은 흰색 고정이 아니라 고유 발광색 유지 |
| Material Mask | PNG RGBA 8-bit | Linear | 채널 데이터 | R=금속, G=거칠기 역값/광택, B=습윤·결정 반응, A=효과 강도 |
| AO | PNG Gray/R 8-bit | Linear | 선택 | 흰색=차폐 없음, 검정=강한 차폐. 접점과 깊은 틈만 사용 |

모든 채널은 동일한 캔버스 크기, 실루엣, 피벗, 패딩을 유지한다. Normal·Mask·AO에는 색 보정,
손실 압축, 알파 트리밍을 적용하지 않는다. 생성형 이미지에서 얻은 가짜 노멀 컬러 이미지는 납품하지
않으며, 승인된 Albedo의 형태를 기준으로 수작업·전용 도구 검수 후 제작한다.

## 5-1. 광원 방향 계약 — 지층당 고정 방향 1개 (확정 2026-09-09)

### 규칙

아트에 굽는 **약한 자체 음영의 광원 방향을 지층마다 하나로 고정한다.** 자산마다 방향이 다르면
런타임 광원을 얹어도 요철이 서로 싸워서, 광원을 켤수록 화면이 지저분해진다.

| 지층 | 방향 | 톤 근거 |
|---|---|---|
| 지층 1 · 표층 | **화면 좌상단 35°** | 아치 너머 외광(§2 "주 광원 청록·시안, 깊이와 진행 방향") |
| 지층 2 · 균열대 | **화면 우상단 35°** | 지층이 바뀐 것을 실루엣으로 읽히게 한다(수용 기준 §15.1 "HUD 없이 스크린샷만으로 지층 구분") |
| 지층 3 · core | **화면 정상단 90°(수직)** | 중심부는 위에서 내리누르는 압력 — 그림자가 짧고 대비가 세다 |
| 이상지대 · abyss | **화면 하단 −55°(아래에서 위로)** | 광원이 바닥의 균열에서 온다. 위아래가 뒤집힌 불안 |

방향이 정해지면 **볼록·오목 모서리 자산을 회전 복제로 만들 수 없다** — 회전하면 음영 방향이
따라 돌아간다. 모서리는 방향별로 따로 그린다(벽 세트 요청서 §4 에 이미 명시).

### 이 방향이 무엇을 하지 않는가

**빛을 굽는 것이 아니다.** §5 Albedo 규칙("방향광·강한 투사광을 굽지 않고 재질 고유색과 약한
자체 음영만")은 그대로다. 굽는 것은 **약한 자체 음영뿐이고, 그 음영의 방향만 통일**한다.
런타임 광원은 그 위에 **강조로만** 얹는다.

### 왜 이렇게 정했는가 — Ori 원리의 축약

Ori 는 에셋 7,000개에 대해 손칠 라이트맵 30,000장으로 룩을 만들었다(에셋마다 라이트 방향을
안다). 그 원리를 우리 규모로 줄이면 **"에셋 7,000 × 방향 4~5" 가 아니라 "지층 4 × 방향 1"** 이다.
계약서에 한 줄 넣는 것으로 끝나고, 아트 인력이 여러 명이어도 방향이 갈리지 않는다.

반대로 **Katana ZERO 식 "알베도에 빛을 굽는" 방식은 채택하지 않는다.** 그쪽은 제한 네온
팔레트 + 전체화면 후처리로 무드를 만드는 전략이고, 우리는 파괴로 벽이 사라지는 게임이라
알베도에 구운 빛이 파괴 후 남는다. 다만 **지층별 제한 팔레트**(색 3~4개)는 가져온다 —
그건 아트가 아니라 `AtmosphereProfile`·Volume 프로파일이 담는다.

[../../../docs/urp-2d-lighting/09-tunnel-crew-application.md](../../../docs/urp-2d-lighting/09-tunnel-crew-application.md) §B-4

## 6. 피벗·footprint·오클루전

- 바닥 자산 피벗: 셀 또는 footprint 사각형의 기하학적 중심.
- 벽·기둥·문·소품 피벗: 지면과 닿는 실루엣의 중앙 하단, 즉 발점.
- 벽 정면은 점유 셀의 경계선에 발점을 둔다. 위로 솟은 픽셀은 footprint에 포함하지 않는다.
- 전경 자산은 별도 `occluderGroup`과 페이드 가능 영역을 metadata에 기록한다.
- 다중 셀 자산은 `footprintWidth`, `footprintHeight`, `pivotPxX`, `pivotPxY`, `visualHeightCells`를
  필수로 기록한다.
- 그림자 캐스터는 Albedo 알파를 자동 복사하지 않고 지면에 닿는 구조의 단순한 별도 윤곽으로 제공한다.

## 8. 생산 절차

1. 레퍼런스 영상에서 깊이층, 실루엣, 광원 역할만 추출한다.
2. 테스트 방 키아트 한 장으로 화면 밀도, 벽 높이, 초점과 팔레트를 잠근다.
3. 동일 디자인의 모듈 배치 보드로 분해 가능성과 셀 배율을 확인한다.
4. 자산 하나씩 투명 배경 원본을 생성하거나 페인트한다.
5. 256px/셀 원본에서 가장자리, 접선, 반복 무늬와 광원 bake를 클린업한다.
6. Albedo 승인 후 Normal, Emission, Mask, AO를 제작한다.
7. 모든 채널의 캔버스·알파·피벗을 픽셀 단위로 대조한다.
8. 128px/셀로 축소한 승인본과 metadata manifest를 만든다.
9. 6×6셀 최소 조립 테스트와 어두운 환경·밝은 환경 비교 캡처를 검수한다.
10. `approved/`만 Claude 구현 트랙에 인계한다.

## 9. 생성형 이미지 기록 규칙

각 생성 호출은 같은 폴더의 `generation-log.md`에 다음을 남긴다.

- 날짜와 자산 ID
- 사용 모드와 use-case 분류
- 입력 이미지의 역할
- 최종 프롬프트 전문
- 생성 결과 원본 경로
- 선택·폐기 이유
- 필요한 수작업 보정
- 승인 상태: `concept`, `working`, `approved`, `rejected`

생성 결과에 글자, 로고, 워터마크, UI, 캐릭터, 임의의 테두리가 들어가면 제거 전에는 승인하지 않는다.
키아트의 조명은 최종 Albedo에 그대로 굽지 않으며, 구조와 재질을 분리해 다시 제작한다.

## 10. 구현 인계 manifest 필수 필드

```json
{
  "assetId": "TR01-ARC-001",
  "revision": 1,
  "status": "approved",
  "footprintCells": [3, 1],
  "sourcePixelsPerCell": 256,
  "deliveryPixelsPerCell": 128,
  "pivotPixels": [192, 416],
  "visualHeightCells": 3.25,
  "sortingLayerHint": "WorldStructure",
  "localOrder": 0,
  "occluderGroup": null,
  "fadeTargetAlpha": null,
  "lightSockets": [],
  "shadowCasterPath": null,
  "channels": {}
}
```

`pivotPixels`는 구현 인계의 기준값이며 좌표계는 **이미지 좌상단 원점, X 오른쪽 증가, Y 아래
증가**로 고정한다. 따라서 128×128 바닥 중앙은 `[64,64]`, 남쪽 벽 정면의 발점은
`[64,128]`이다. `pivotNormalized`는 Unity Sprite의 좌하단 원점 값과 대조 검수하기 위해 함께
유지한다.

피벗 Y의 실제 이미지 좌표 원점은 슬라이스 도구와 함께 확정하되, manifest에서는 항상 지면 기준점을
의미한다. 좌표계 변환 규칙은 구현 담당이 정하고 문서에 역기록한다.

## 11. 승인 체크리스트

- 100% 크기와 게임 예상 축소 크기에서 모두 형태가 읽힌다.
- 바닥·벽·전경이 서로 다른 높이층으로 즉시 구분된다.
- 바닥 중앙의 전투 가독성을 장식이 방해하지 않는다.
- 아치와 대형 설비가 방의 초점을 만들되 캐릭터보다 상호작용 우선순위를 빼앗지 않는다.
- 알파 가장자리에 밝거나 어두운 프린지가 없다.
- 타일 경계, 반복, 피벗 흔들림, 채널 위치 오차가 없다.
- 조명을 꺼도 재질과 구조가 읽히고, 조명을 켜면 부피가 강화된다.
- 레퍼런스의 깊이 원리는 따르되 고유 캐릭터·로고·UI·구조를 복제하지 않는다.

## 12. 변경 관리

이 문서는 테스트 방 제작 과정에서 확인된 실제 규격에 맞춰 계속 갱신한다. 셀 크기, 벽 높이,
채널 의미, 피벗 규칙처럼 구현과 연결되는 값을 바꿀 때는 기능명세서와 manifest를 같은 변경에서
수정한다. 개별 파일 이름에 `final`, `final2`를 붙이지 않고 manifest revision으로 이력을 관리한다.
