# 테스트 방 V01 주 키아트 레퍼런스 분석

기준일: 2026-09-08  
분석 대상: `../reference/tr01_primary_style_target.png`  
용도: 새 방 전체 키아트와 이후 환경 프랍·모듈 제작의 최우선 시각 기준

## 0. 결론

이 이미지는 앞으로 테스트 방의 **주 스타일 타깃(primary style target)** 으로 사용한다. 기존
`concept/tr01_room_maintenance_a_concept.png`는 생산 이력으로 보존하되, 새 키아트의 색·공간·재질·
조명 판단 기준으로 사용하지 않는다.

새 키아트가 보존해야 할 핵심은 특정 문·수정·캐릭터 배치의 복사가 아니라 다음 시각 시스템이다.

1. 축 정렬 직교 3/4 화면과 높은 벽 정면이 만드는 얕은 2.5D 무대
2. 검보라 암부를 넓게 유지하고 시안·마젠타·앰버 광원을 국소적으로 배치하는 색 구조
3. 픽셀아트의 덩어리감과 고해상도 페인팅의 재질 묘사를 결합한 `pixel-painted` 표현
4. 알베도 자체 음영, 접촉 AO, 동적 광원, 발광, Bloom, 투사 그림자를 겹치는 하이브리드 조명
5. 큰 캐릭터와 큰 프랍, 높은 벽, 좁은 가시 방이 만드는 밀도 높은 협동 액션 화면
6. 레일·배관·문틀·램프·광물·잔해가 같은 굵기와 베벨 언어를 공유하는 산업 판타지 키트

이 기준에서는 “더 현실적인 그림”, “더 깔끔한 3D 렌더”, “더 넓은 방”이 개선이 아니다. 새
키아트는 레퍼런스처럼 **작고 밀도 높은 플레이 공간**, **짙은 유색 암부**, **국소 고휘도 광원**,
**굵은 픽셀 덩어리**를 유지해야 한다.

## 1. 분석 신뢰도와 증거 구분

### 1.1 직접 확인한 사실

- 원본은 2944×1648px, 약 1.786:1의 16:9 계열 화면이며 알파가 없는 24-bit RGB PNG다.
- 바닥의 주 축은 화면 가로·세로와 거의 평행하고, 평행선의 소실점이나 거리별 크기 감소가 없다.
- 화면 전체의 명도 표본은 10백분위 6/255, 중앙값 37/255, 90백분위 84/255다.
- 전체 화면 표본의 채도 중앙값은 약 0.658이다. 즉 대부분은 매우 어둡지만 색은 회색으로 죽지 않는다.
- 색상 표본은 보라·마젠타 계열이 가장 넓고, 시안과 주황이 작은 고휘도 초점으로 사용된다.
- 4×4 표본 블록이 완전히 같은 색인 비율은 약 7.2%뿐이다. 해상도가 736×412의 정확한 4배이지만,
  단순 최근접 확대 이미지처럼 모든 픽셀이 큰 정사각형으로 반복되지는 않는다.
- HUD 문자열이 `MUISSION RROCESS`처럼 깨져 있고 일부 아이콘·세부 구조도 생성형 이미지 특유의
  비일관성을 보인다.

### 1.2 따라서 확정할 수 없는 것

이 파일은 실제 실행 중인 게임의 원본 프레임이라고 검증할 수 없다. 오히려 파일명과 깨진 HUD를
보면 생성형 “게임플레이 스크린샷” 컨셉 이미지일 가능성이 높다. 그러므로 아래 엔진 분석은
“이 이미지에서 실제로 사용된 기술”의 판독이 아니라 **Unity에서 같은 결과를 만들기 위한 재현
설계**다.

문서의 기술 표기는 다음처럼 해석한다.

| 표기 | 의미 |
|---|---|
| 관찰 | 픽셀에서 직접 확인 가능 |
| 강한 추론 | 화면 결과를 설명하는 가장 경제적인 구현 |
| 선택 구현 | 같은 결과를 낼 수 있으나 원본 사용 여부는 알 수 없음 |

## 2. 화면 구성과 공간감

### 2.1 카메라와 투영

**관찰:** 정통 아이소메트릭이나 2:1 다이메트릭이 아니다. 바닥 통로, 레일, 벽의 기본 축이
화면 X/Y에 정렬되고 소실점이 보이지 않는다. 문과 캐릭터, 기계는 3/4 방향으로 그려졌지만 바닥
좌표계 자체는 회전하지 않았다.

**재현 계약:**

- 카메라: Orthographic
- 월드 투영: `ReferenceTopDown`
- `Ground XY = Sim XY`
- 타일 회전 0°, XY 축척 1:1
- 깊이 표현: 카메라 원근이 아니라 스프라이트의 정면 높이, 피벗, Y 정렬, 오클루전으로 제작
- 프로덕션 키아트에서 원근 수렴, 광각 왜곡, 다이아몬드 그리드를 금지

현재 프로젝트의 `IsometricProjection`과 `WorldVisualProfile`이 이미 이 계약을 지원한다.
Unity의 2D 기본 카메라도 직교 투영을 사용하며, 2D 장면에서 Z를 무시하거나 2.5D 용도로 제한해
사용할 수 있다.

### 2.2 프레이밍

화면은 넓은 월드를 보여 주기보다 하나의 방과 그 안의 전투를 꽉 채운다.

- 상단 약 30~38%: 높은 후면 벽, 문, 파이프, 수정 광맥
- 중단 약 35~45%: 캐릭터·적·대형 프랍이 겹치는 주 전투 무대
- 하단 약 20~30%: 가까운 바닥, 전경 암반·난간·HUD가 만드는 프레임
- 이동 바닥은 넓지만 비어 있지 않다. 밝은 파편, 균열, 레일과 그림자가 가장자리에서 중앙으로
  침투하며 시선을 안내한다.
- 화면 중심은 가장 밝은 지점이 아니다. 밝은 초점은 좌상단 마젠타 광맥, 상단 시안 문광,
  중앙~하단 앰버 전투광으로 삼각 분산된다.

이 분산 덕분에 화면 전체가 화려하면서도 캐릭터가 배경에 묻히지 않는다. 새 키아트에서도 광원을
중앙 한곳에 몰지 말고 **시안·마젠타·앰버 세 역할을 서로 떨어진 위치에 배치**해야 한다.

### 2.3 깊이층

레퍼런스는 최소 다음 층을 동시에 사용한다.

1. 완전한 검정에 가까운 외곽 공극
2. 보라빛 먼 암벽과 후면 구조물
3. 높은 벽 정면, 문틀, 파이프, 기둥
4. 플레이 가능한 바닥과 레일
5. 바닥 프랍과 접촉 그림자
6. 캐릭터·드론·전투 이펙트
7. 화면 하단과 측면의 전경 구조
8. 안개, 광선, 발광 입자, Bloom
9. 화면 고정 HUD

환경 키아트에서는 HUD를 제거하되 1~8번의 층은 보존한다. 캐릭터를 완전히 제거하면 크기와
조명 반응을 판단하기 어려우므로, 새 키아트에는 땅굴 크루 캐릭터를 스케일 기준으로 포함한
`gameplay target` 버전과 환경만 남긴 `clean plate`를 같은 구도로 확보하는 것이 가장 안전하다.

## 3. 그래픽 스타일 분석

### 3.1 스타일 명칭

이 화면은 순수 저해상도 픽셀아트도, 매끈한 디지털 페인팅도 아니다. 생산 언어는 다음처럼 정의한다.

> 굵은 픽셀 클러스터와 제한된 단계 명암을 기반으로 하되, 표면에는 손으로 칠한 듯한 작은 색 변화,
> 베벨 하이라이트, 유색 반사광과 부분적인 부드러운 발광을 더한 고해상도 `pixel-painted` 2D 게임 아트.

생성 프롬프트에서 `pixel art`만 단독으로 쓰면 지나치게 저해상도·평면·복고풍으로 흐를 위험이
있다. 반대로 `polished painterly 2D`만 쓰면 기존 실패 키아트처럼 매끈하고 어두운 디지털
페인팅이 된다. 항상 다음 두 성질을 함께 잠근다.

- 실루엣과 음영 경계: 굵고 계단진 픽셀 클러스터
- 재질과 조명: 풍부한 수작업 색 변화와 제한된 소프트 글로우

### 3.2 형태 언어

- 캐릭터·기계·문틀은 실제 비율보다 짧고 굵다.
- 철판 모서리는 넓은 베벨로 처리해 작은 화면에서도 밝은 가장자리가 읽힌다.
- 암석은 작은 자갈의 나열보다 중대형 덩어리 3~7개가 먼저 보인다.
- 파이프·레일·케이블은 배경선이 아니라 두께 있는 프랍으로 표현한다.
- 산업 구조에는 사각 패널, 굵은 프레임, 큰 리벳, 반복 홈을 사용한다.
- 수정은 날카로운 다각 실루엣과 내부의 밝은 코어로 금속·암석과 구분한다.
- 손상은 미세 노이즈가 아니라 깨진 실루엣, 휜 보강판, 큰 균열로 전달한다.

### 3.3 선과 표면

- 외곽선은 완전한 단색 검정 라인이 아니라 주변보다 1~3단계 어두운 유색 가장자리다.
- 위쪽·광원 쪽 모서리는 청회색, 자주색, 주황색의 얇은 림으로 분리된다.
- 바닥은 넓은 명암 덩어리가 우선이며, 균열과 잔해는 가장자리와 사건 지점에 집중한다.
- 표면 노이즈는 모든 픽셀에 균등하지 않다. 시선이 머무는 캐릭터·프랍·광원 주변이 더 조밀하다.
- 발광 경계만 부드러운 블러를 허용하고 구조물 외곽은 비교적 단단하게 유지한다.

## 4. 색과 명도 설계

### 4.1 기본 팔레트

| 역할 | 근사 색군 | 화면 기능 |
|---|---|---|
| 공극 | `#080808`, `#080818` 계열 | 방 밖과 화면 프레임을 닫음 |
| 기본 암부 | `#180818`, `#180828`, `#281828` 계열 | 검보라 환경 통일 |
| 구조 중간톤 | 어두운 회보라·청보라 | 바닥·암석·철판의 읽히는 면 |
| 마젠타 광물 | `#9030D0`~`#F030F0` | 위험·광물·지층 정체성 |
| 시안 문광 | `#107070`~`#10F0F0` | 깊이·진행 방향·차가운 외광 |
| 앰버 전투광 | 주황~황백 코어 | 캐릭터·상호작용·전투 초점 |
| 캐릭터 국소색 | 주황, 청록, 녹색 | 배경에서 역할을 구분 |

수치는 이미지 전체를 일정 간격으로 샘플한 진단값이며, UI와 캐릭터 색도 포함한다. 최종 팔레트는
키아트 승인 뒤 환경 영역만 다시 샘플해 확정한다.

### 4.2 명도 구조

- 화면의 절반 이상이 37/255 전후의 매우 낮은 명도다.
- 밝은 영역은 넓은 흰색 면이 아니라 램프 코어, 레이저, 수정 끝, 베벨 같은 작은 면적에 집중된다.
- 암부가 검정에 가깝더라도 보라·남청의 색상 정보가 남는다.
- 배경 구조는 중저대비, 캐릭터 얼굴·무기·발광 프랍은 고대비다.
- 시안과 주황이 만나는 곳은 서로를 중화하지 않고 분리된 색 덩어리로 유지된다.

따라서 생성·후처리 시 전역 노출을 올려 암부를 회색으로 펴거나, Bloom으로 모든 밝은 면을 같은
흰색으로 만드는 것을 금지한다.

## 5. 조명과 셰이딩의 역설계

### 5.1 알베도에 남겨야 하는 것

**강한 추론:** 레퍼런스의 모든 입체감을 실시간 라이트만으로 만들 수는 없다. 프랍 자체에 다음이
그려져 있어야 한다.

- 넓은 상면/정면 명도 차이
- 금속·암석 베벨의 기본 하이라이트
- 홈과 겹침부의 짧은 자체 음영
- 재질 고유의 차가운/따뜻한 색 변화
- 광원이 꺼져도 실루엣을 설명하는 최소 명도

그러나 특정 방의 긴 투사 그림자, 시안·마젠타·앰버 광원색, 넓은 빛 번짐은 Albedo에 굽지 않는다.
프랍 원본은 중립 조명 아래에서도 이 스타일의 덩어리와 재질이 읽혀야 한다.

### 5.2 Unity에서의 권장 광원 구성

| 화면 효과 | 재현 기술 | 판정 |
|---|---|---|
| 전체 검보라 최저 조도 | 약한 Global Light 2D 또는 표면별 최소광 | 강한 추론 |
| 램프·전투광의 국소 원형광 | Point Light 2D, Additive blend | 강한 추론 |
| 상단 문의 시안 탐색광 | Spot Light 2D 또는 콘형 Additive 스프라이트 | 강한 추론 |
| 수정 자체 발광 | Emission map + 선택적 비그림자 Light 2D | 강한 추론 |
| 벽·캐릭터 투사 그림자 | Shadow Caster 2D | 강한 추론 |
| 발·바퀴·프랍 접지 | 별도 접촉 AO 스프라이트/맵 | 관찰 + 강한 추론 |
| 밝은 코어 주변 번짐 | HDR 값 + URP Volume Bloom | 강한 추론 |
| 저층 보라 안개 | 화면/깊이 그룹 안개 패스 + VFX 스프라이트 | 선택 구현 |
| 광선 속 먼지와 불꽃 | Particle System, Additive/Alpha 혼합 | 강한 추론 |
| 외곽 암부 | Vignette + 방 밖 검정 오클루전 | 관찰 + 선택 구현 |

Unity의 Light 2D는 색·강도·블렌드 스타일·그림자 강도·노멀맵 품질과 거리를 제어할 수 있고,
Shadow Caster 2D는 광원이 사용할 그림자 윤곽을 정의한다. Bloom은 임계값보다 밝은 영역의
가장자리 밖으로 빛 번짐을 만들며 Volume에서 조정한다. 이 조합은 레퍼런스의 결과를 재현하는 데
적합하다.

### 5.3 노멀과 재질 마스크

- 노멀은 큰 베벨, 원통, 수정 면, 돌출 철판에만 명확한 방향 반응을 준다.
- 바닥 미세 노이즈를 강한 노멀로 만들면 캐릭터보다 표면이 반짝이므로 낮은 강도로 제한한다.
- 금속은 좁고 선명한 하이라이트, 암석은 넓고 무딘 반응을 갖는다.
- 수정·젖은 광물은 별도 Material Mask로 Additive 반응을 선택한다.
- Emission은 보이는 색 면의 형태를 보존하고 주변광은 Light 2D가 담당한다.
- AO는 접점과 깊은 틈에만 사용하며 전체 알베도를 검게 덮지 않는다.

## 6. 대기, 후처리, 화면 효과

### 6.1 필요한 효과

- 청보라색의 얇은 저층 안개
- 문과 강한 램프 주변의 제한된 광선
- 마젠타 광물 주변의 부유 입자
- 전투 시 짧은 주황 HDR 펄스와 불꽃
- 화면 외곽의 짙은 비네트와 방 밖 검정
- 매우 약한 그레인 또는 디더로 암부 밴딩 완화
- Tonemapping으로 발광 코어를 보존하면서 주변 표면의 색을 유지

### 6.2 과용 금지

- 전 화면 안개로 픽셀 실루엣을 흐리지 않는다.
- Bloom 반경을 크게 잡아 수정·램프가 하나의 보라 안개 덩어리가 되지 않게 한다.
- 컬러 그레이딩으로 모든 재질을 같은 보라색으로 덮지 않는다.
- 필름 그레인은 100% 확대에서 픽셀 클러스터를 깨지 않을 정도만 사용한다.
- 실제 렌즈 심도(Depth of Field), 모션 블러, 색수차는 기본 화면에서 사용하지 않는다.

## 7. 프랍과 환경 리소스에 적용할 스타일 계약

### 7.1 모든 프랍의 공통 규칙

1. 100% 게임 크기에서 먼저 큰 실루엣과 용도를 읽을 수 있어야 한다.
2. 프랍 하나는 3~7개의 큰 덩어리로 구성하고, 미세 부품은 보조 정보로 둔다.
3. 어두운 자주/청회색 본체에 차가운 림 또는 제한된 따뜻한 베벨을 사용한다.
4. 외곽은 단단한 픽셀 클러스터, 내부 표면은 손으로 칠한 색 변화로 처리한다.
5. 색광과 큰 투사 그림자는 Albedo에서 분리한다.
6. 모든 발광부는 경계가 분명한 Emission 원형을 제공한다.
7. Normal은 실루엣을 바꾸지 않고 큰 면과 베벨만 설명한다.
8. 바닥 접점과 피벗이 명확해야 하며, 별도 접촉 AO와 캐스터 윤곽을 제공한다.
9. 투명 배경에 회색 막·체커보드·흰 프린지를 허용하지 않는다.
10. 같은 자산군은 베벨 폭, 리벳 크기, 외곽선 굵기와 광원 방향을 공유한다.

### 7.2 자산군별 강조점

| 자산군 | 스타일 핵심 |
|---|---|
| 바닥 | 넓고 조용한 보라회색 덩어리, 가장자리 중심의 균열·잔해 |
| 벽 정면 | 높은 수직 면, 깊은 받침 그림자, 굵은 프레임과 반복 홈 |
| 벽 상단 | 밝은 림과 두꺼운 cap, 바닥보다 무겁고 거친 실루엣 |
| 문·아치 | 화면 높이 2~3셀 이상의 큰 프레임, 시안 진행광 소켓 |
| 기둥 | 큰 베이스/몸통/cap 세 덩어리, 캐릭터를 일부 가리는 높이 |
| 레일·배관 | 화면 축 정렬, 일정 굵기, 큰 연결부, 바닥과의 짧은 AO |
| 기계 | 원통과 사각 프레임의 조합, 주황 작업광, 읽기 쉬운 작동부 |
| 광물 | 날카로운 다각 실루엣, 마젠타 코어, 암석과 명확한 분리 |
| 소형 소품 | 색보다 실루엣으로 구분, 한 셀 안에 지나친 부품 금지 |
| 전경 | 가장 어둡고 크게, 캐릭터를 일부 가리되 페이드 마스크 제공 |

## 8. 현재 Unity 프로젝트와의 대응

### 8.1 이미 갖춘 기반

현재 프로젝트는 Unity 6.3 LTS 계열 계획과 URP 17.3.0 2D Renderer를 사용한다. 저장소에서
확인한 구현은 다음과 같다.

- `ReferenceTopDown` 직교 투영과 1:1 Ground XY
- 128 PPU 환경 자산 계약
- `WorldLit`/`CharacterLit`의 Albedo, Normal, Emission, Material Mask, AO 채널
- Multiply·Additive를 포함한 4개의 2D Light Blend Style
- Light 2D와 Shadow Caster 2D
- 발점 기반 정렬, SortingGroup, Visual Height Anchor
- 접촉 그림자, 전경 페이드, 가려진 실루엣
- 지층 Volume의 Color Adjustments, Tonemapping, Bloom, Vignette, Film Grain
- 화면 쿼드 기반 저층 안개·깊이 색 분리·비네트·그레인
- LOS/탐색 기억을 합성하는 어둠 패스

즉 새 엔진 구조를 처음부터 설계할 필요는 없다. 현재 실패의 주원인은 기능 부족보다 **기준
키아트와 생성 자산의 스타일 불일치**, 그리고 실제 조립에서의 수치 튜닝 문제에 가깝다.

### 8.2 현재 값에서 다시 확인할 항목

- `Renderer2D.asset`의 Light Render Texture Scale은 0.5다. 부드러운 광원에는 유리하지만 작은
  픽셀 광원과 그림자의 경계가 과도하게 흐려지는지 실제 캡처로 비교한다.
- 지층 1 Bloom은 threshold 0.7, intensity 0.6, scatter 0.72다. 레퍼런스와 비슷한 강한 코어를
  만들 수 있으나 마젠타가 넓게 번지면 intensity보다 scatter와 Emission 면적을 먼저 줄인다.
- 지층 1 Color Adjustments는 exposure +0.55, contrast +6, saturation +6이다. 키아트의 암부
  중앙값이 매우 낮으므로 전역 노출로 맞추지 말고 Albedo·환경광·국소광을 함께 조정한다.
- 기본 Renderer Feature는 비어 있다. 현재의 화면 쿼드 대기 패스가 Ground/Entity/Foreground를
  실제로 충분히 분리하는지 Visual Lab에서 검증해야 한다.
- 프로젝트 manifest에는 전용 `com.unity.2d.pixel-perfect` 패키지가 명시되지 않는다. 이 그림은
  순수 최근접 픽셀아트가 아니므로 무조건 도입할 필요는 없지만, 카메라 이동 중 픽셀 떨림이 생기면
  Pixel Perfect Camera 또는 동등한 정수 스냅/내부 해상도 정책을 검토한다.
- 기본 투명 정렬 모드는 저장된 Y축 값과 별개로 `Default`다. 현재 커스텀 발점 정렬이 실제 모든
  캐릭터·프랍·전경에 적용되는지 회귀 캡처로 확인한다.

## 9. 새 키아트 생성 시 잠글 조건

다음 생성에서는 입력 이미지를 **편집 대상이 아니라 스타일·공간·색·조명·밀도 레퍼런스**로
지정한다. 특정 캐릭터, HUD 문구, 문 형태를 복제할 필요는 없지만 아래 항목은 강하게 보존한다.

### 필수 보존

- 16:9 실제 게임플레이 프레이밍
- 축 정렬 직교 3/4 톱다운, 무소실점
- 화면 높이 약 13~18%의 굵은 캐릭터 스케일
- 높은 후면 벽과 전경 가림
- 검보라 저명도 환경, 마젠타·시안·앰버 삼색 조명
- 굵은 픽셀 클러스터 + 손으로 칠한 재질 디테일
- 큰 문틀, 레일, 배관, 기계, 수정, 램프가 만드는 산업 광산 언어
- 밝은 전투 이펙트가 있어도 중앙 이동 영역의 판독성 유지
- UI가 없어도 실제 플레이 화면처럼 보이는 공간 밀도

### 금지

- 기존 컨셉처럼 매끈한 고해상도 디지털 페인팅으로 변화
- 사실적인 3D/PBR 렌더, 미니어처 렌더, 과도한 금속 반사
- 다이아몬드 아이소메트릭, 원근 카메라, 광각 왜곡
- 넓고 비어 있는 전시장형 방
- 균일한 보라색 오버레이 또는 전 화면 안개
- 너무 작은 캐릭터와 얇은 프랍
- UI·로고·읽을 수 없는 문자·워터마크
- 레퍼런스 캐릭터와 HUD의 직접 복제

## 10. 승인 루브릭

새 키아트 후보는 아래 100점 기준으로 비교한다. 80점 미만은 프랍 생산 기준으로 사용하지 않는다.

| 항목 | 배점 | 합격 질문 |
|---|---:|---|
| 투영·프레이밍 | 15 | 같은 직교 3/4 시점과 밀도 높은 한 방으로 보이는가 |
| 픽셀 표현 | 20 | 굵은 픽셀 클러스터와 페인터리 재질이 함께 있는가 |
| 명도 구조 | 15 | 넓은 어둠과 작은 고휘도 초점이 분리되는가 |
| 색 구조 | 15 | 검보라 바탕에서 시안·마젠타·앰버가 역할별로 분리되는가 |
| 깊이·오클루전 | 15 | 높은 벽, 접촉부, 전경, VFX가 별도 층으로 읽히는가 |
| 모듈 분해 가능성 | 10 | 벽·문·기둥·레일·기계·광물을 독립 자산으로 추출할 수 있는가 |
| 게임 가독성 | 10 | 캐릭터·적·이동 바닥·상호작용물이 즉시 구분되는가 |

스타일 점수만 높고 모듈 분해가 불가능한 그림은 키아트가 아니라 무드 페인팅으로 분류한다.
