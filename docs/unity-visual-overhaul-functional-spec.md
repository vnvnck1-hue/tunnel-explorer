`source/`는 방향 설정 및 재가공 원본으로 취급한다. 구현 중 규격 변경이 필요하면 아트 원본을
임의 보정하지 않고 규격서의 변경 이력과 산출물을 함께 갱신한다.

## 1. 목적

현재 Unity 버전의 게임 규칙과 시뮬레이션은 유지하면서, 월드 표현 계층을 레퍼런스 영상 수준의
회화적 2.5D 공간으로 전면 교체한다.

이번 작업은 기존 50px 타일을 늘리거나 현재 조명 수치만 조정하는 리스킨이 아니다. 다음 요소를
하나의 시스템으로 다시 설계한다.

- 월드 좌표의 화면 투영
- 바닥·벽·천장·전경으로 이어지는 환경 구조
- 캐릭터·적·소품의 깊이 정렬과 가림
- 재질별 조명, 그림자, 발광, 환경광
- 안개·먼지·광선·후처리를 포함한 대기 원근
- 카메라 거리와 화면 내 피사체 비율
- 신규 환경·캐릭터·소품 아트의 규격과 제작 파이프라인
- 파괴 가능한 절차 맵에서 위 요소들을 실시간 재구성하는 기술

핵심 목표는 단순히 “입체적으로 보인다”가 아니라, 다음 인상을 동시에 달성하는 것이다.

1. 바닥 위에 캐릭터가 서 있고 벽은 실제로 솟아 있는 것처럼 읽힌다.
2. 좁고 깊은 지하 공간이 전경·중경·후경으로 나뉜다.
3. 빛이 장식이 아니라 재질의 부피와 통로의 구조를 설명한다.
4. 어두운 화면에서도 이동 가능 영역, 위협, 자원, 상호작용 대상이 즉시 구분된다.
5. 채굴과 파괴로 지형이 바뀌어도 시각 구조와 그림자가 한 프레임 안에 함께 갱신된다.

## 2. 범위

### 2.1 포함

- 제작 기준 투영과 카메라 프로파일 확정
- 월드 렌더러의 다층 2.5D 구조 전환
- 절차 맵 경계에서 벽 정면·상단·모서리·전경을 만드는 표면 생성기
- 발 위치 기반 깊이 정렬
- 전경 오클루전과 플레이어 가시성 보정
- 바닥·벽·소품·캐릭터용 통합 Lit 셰이더
- 노멀·발광·재질 마스크·AO 제작 규격
- Light2D, 동적 그림자, 접촉 음영, Volume, 안개·먼지 시스템 재구성
- 신규 환경 키트, 구조물, 소품, 캐릭터·적 보조 맵 제작
- 비주얼 검증용 전용 씬, 캡처, 디버그 오버레이, 임포트 검사기
- 그래픽 품질 단계와 성능 예산

### 2.2 제외

- 이동·충돌·채굴·전투·AI·맵 생성 규칙 변경
- 시뮬레이션의 1셀 = 1유닛 규칙 변경
- 밸런스 수치 변경
- HTML 프로토타입 수정
- 원근 카메라를 사용한 실제 3D 전환
- 전 지형을 3D 메시·3D 캐릭터로 다시 제작하는 작업

### 2.3 유지해야 하는 불변 조건

- `WorldGrid`와 모든 충돌·길찾기·LOS 판정은 기존 직교 XY 셀을 사용한다.
- 화면 아트가 셀 밖으로 돌출돼도 게임 판정은 발 위치와 footprint를 기준으로 한다.
- 같은 시드의 맵 구조와 게임 결과는 비주얼 오버홀 전후에 같아야 한다.
- 화면 좌표 역변환이 필요한 조준·배치·UI 포인터는 기존 정밀도를 유지한다.
- Windows 데스크톱 단일 빌드가 1차 출시 대상이다.

## 3. 레퍼런스 영상 분석

### 3.1 투영

레퍼런스는 정통 아이소메트릭이나 2:1 다이메트릭이 아니다.

- 바닥의 두 축이 화면 가로·세로에 정렬된다.
- 수평선과 소실점이 없고 거리별 크기 감소가 거의 없다.
- 바닥 좌표는 직교 탑다운에 가깝다.
- 캐릭터, 벽 정면, 문, 기둥은 3/4 측면으로 그려 깊이를 만든다.

따라서 제작 기준은 `ReferenceTopDown`의 회전 0°, XY 축척 1:1을 사용한다. 깊이는 투영 행렬에
추가 압축을 넣어 만들지 않고, 별도의 시각 높이와 레이어로 만든다.

### 3.2 깊이감을 만드는 실제 요소

| 요소 | 레퍼런스의 특징 | 현재 Unity의 차이 |
|---|---|---|
| 벽 | 상단과 1~3셀 높이의 정면이 분리됨 | 대부분 한 셀 평면 타일 |
| 경계 | 바닥→받침 그림자→벽 정면→벽 상단 순서가 보임 | 바닥과 벽이 같은 평면에서 겹침 |
| 전경 | 기둥·문틀·암반이 캐릭터를 부분적으로 가림 | 캐릭터가 거의 항상 벽보다 앞에 표시됨 |
| 구조물 | 아치·레일·배관·기계가 여러 셀을 가로지름 | 한 셀 단위 반복이 중심 |
| 화면 밀도 | 큰 캐릭터와 큰 구조물이 방 하나를 채움 | 더 넓은 맵과 작은 피사체를 보여 줌 |
| 명암 | 넓고 조용한 어둠과 작은 고휘도 광원이 대비됨 | 셀마다 비슷한 텍스처·명암 빈도 |
| 색 | 차가운 청록 환경광과 따뜻한 주황 조명이 교차함 | 지층 틴트와 손전등 중심 |
| 그림자 | 접촉 AO, 페인팅된 자체 음영, 투사 그림자가 함께 있음 | 동적 투사 그림자 중심 |
| 대기 | 먼지·연무·광선이 깊이층마다 다른 농도로 존재 | 시야 어둠과 일부 파티클 중심 |

### 3.3 화면 구성 목표

레퍼런스 영상에서 피사체 비율은 장면마다 달라지지만 다음 범위를 제작 기준으로 삼는다.

- 일반 캐릭터의 화면 높이: 기본 카메라에서 화면 높이의 13~18%
- 대형 적: 18~30%
- 보스: 30~50%
- 기본 전투 화면의 가시 월드 높이: 약 10.5~12.5셀에서 시작
- 협동 인원이 벌어질 때 동적 줌 최대: 약 16~18셀
- 플레이 가능 바닥은 화면 면적의 45~70%를 차지하고 나머지는 벽·전경·어둠으로 구성

이 값은 버티컬 슬라이스에서 게임 플레이 가독성과 함께 확정한다. 수치 달성보다 레퍼런스와 같은
피사체 위계가 우선이다.

## 4. 현재 구현의 구조적 한계

### 4.1 월드 레이어

현재 `WorldRenderer`는 주로 다음 세 Tilemap을 사용한다.

1. `Floor`
2. `Walls`
3. `CoreTop`

바닥은 모든 셀에 먼저 깔리고, 벽 타일이 그 위에 표시된다. 이 방식은 셀 단위 파괴에는 효율적이지만,
벽 정면과 전경 높이를 표현할 별도 표면이 없다.

`TileSetAsset`에는 `coreBottomShadow`, `coreSideByBand`, `seams`가 연결돼 있지만 현재 월드 렌더러에서
사용되지 않는다. 이 자산은 새 시스템 검증용 참고가 될 수 있으나 신규 아트 규격의 한계가 되어서는
안 된다.

### 4.2 정렬과 가림

- 프로젝트 Sorting Layer는 사실상 `Default` 하나다.
- 바닥·벽·캐릭터가 고정 `sortingOrder` 묶음으로 나뉜다.
- 캐릭터와 소품을 발 위치에 따라 상호 정렬하는 공통 시스템이 없다.
- 남쪽 벽·문틀·기둥이 전경 오클루더로 전환되지 않는다.
- 전경이 플레이어를 가렸을 때 반투명·외곽선으로 보정하는 시스템이 없다.

### 4.3 아트 해상도와 구조

- 기존 월드 타일의 기본 크기는 50×50px이다.
- 벽 변형은 많지만 대부분 한 셀 내부의 표면 변화와 손상 상태다.
- 여러 셀을 아우르는 건축 실루엣, 높은 벽 정면, 대형 문, 천장 립, 전경 암반이 부족하다.
- 바닥의 미세 무늬가 셀마다 반복돼 큰 형태보다 격자가 먼저 읽힌다.

### 4.4 조명

현재 구현에는 Light2D, 벽 노멀 아틀라스, ShadowCaster2D, 지층별 Volume, Bloom, Tonemapping,
Vignette, Film Grain이 존재한다. 문제는 기능 부재보다 조명이 설명할 입체 표면이 부족하다는 점이다.

- 벽 노멀은 존재하지만 바닥·캐릭터·대부분의 소품에는 동등한 재질 정보가 없다.
- 벽 그림자는 셀 footprint로 만든 평면 캐스터이며 시각적 벽 높이를 표현하지 않는다.
- 접촉 AO와 자체 음영이 충분하지 않아 물체가 바닥에서 뜬다.
- Renderer Feature가 없어 깊이층별 안개·색 분리·실루엣 보정을 수행하지 않는다.
- 후처리는 존재하지만 평평한 알베도와 구조를 입체로 바꿀 수는 없다.

## 5. 최종 비주얼 원칙

### 5.1 직교 2.5D 무대

월드는 다음 세 좌표를 구분한다.

- `Sim XY`: 이동·충돌·채굴·AI가 사용하는 기존 좌표
- `Ground XY`: 화면에 투영된 발 위치 또는 지면 접점
- `Visual Height`: 판정에는 영향을 주지 않고 스프라이트를 지면 위로 솟게 하는 표현 높이

`ReferenceTopDown`에서는 `Ground XY = Sim XY`다. 벽 정면·기둥·비행 물체·천장 잔해는
`Visual Height`와 피벗을 사용해 지면 위로 표현한다.

### 5.2 큰 형태 우선

한 화면은 다음 순서로 읽혀야 한다.

1. 이동 가능한 방과 통로의 큰 실루엣
2. 벽과 바닥의 높이 차이
3. 캐릭터·적·목표·자원
4. 레일·배관·잔해 같은 환경 서사
5. 표면의 미세 질감

셀마다 강한 무늬를 넣지 않는다. 디테일 밀도는 중요한 지점과 벽 가장자리에 집중한다.

### 5.3 하이브리드 조명

레퍼런스의 깊이는 완전한 실시간 조명이 아니라 다음 조합으로 만든다.

- 알베도에 포함된 재질 자체 음영과 베벨
- 별도 AO 맵 또는 접합부 데칼
- 노멀맵 기반 동적 Light2D
- 발광 마스크와 Bloom
- 접촉 그림자
- 벽·캐릭터가 만드는 방향성 투사 그림자
- 지층별 환경광과 화면 후처리

실시간 조명만으로 모든 음영을 만들지 않는다. 광원이 꺼진 상태에서도 형태가 읽히는 중립 조명을
알베도와 AO에 남긴다.

## 6. 목표 기술 아키텍처

### 6.1 모듈 구조

```text
Presentation/Visual/
├ Projection/
│  ├ WorldProjection
│  └ WorldVisualProfile
├ Environment/
│  ├ SurfaceTopologyBuilder
│  ├ EnvironmentChunkRenderer
│  ├ SurfaceRuleSet
│  ├ SetPieceSpawner
│  └ EnvironmentOcclusionSystem
├ Depth/
│  ├ FootpointSorter
│  ├ VisualHeightAnchor
│  └ ForegroundFadeController
├ Lighting/
│  ├ WorldLightingDirector
│  ├ LightSocketRenderer
│  ├ ContactShadowRenderer
│  ├ ShadowGeometryBuilder
│  └ AtmosphereRendererFeature
├ Materials/
│  ├ WorldLit.shadergraph 또는 동등 HLSL
│  └ CharacterLit.shadergraph 또는 동등 HLSL
└ Debug/
   ├ VisualLabController
   ├ DepthDebugOverlay
   └ ReferenceCaptureRunner
```

정확한 파일 분리는 구현 시 조정할 수 있지만 책임 경계는 유지한다.

### 6.2 `WorldVisualProfile`

제작 기준 값은 코드 여러 곳에 흩어놓지 않고 프로파일 하나에서 관리한다.

필수 필드:

- 제작 투영 ID
- X/Y 투영 기저
- 기준 PPU와 셀당 소스 픽셀
- 기본·전투·협동 카메라 월드 높이
- 캐릭터 시각 배율
- 기본 벽 정면 높이와 지층별 범위
- 깊이 정렬 단위와 Sorting Layer 매핑
- 전경 페이드 알파·시간·반경
- 접촉 그림자 크기·농도
- 환경광 색·세기
- 동적 광원과 그림자 품질 예산
- 지층별 Volume 프로파일
- 대기 원근 프로파일

프로덕션 프로파일은 `ReferenceTopDown` 하나를 인증 대상으로 한다. 기존 다이메트릭·아이소메트릭
프리셋은 개발 비교 도구로 유지하되, 신규 2.5D 아트가 다른 프리셋에서도 정상 형태를 유지한다고
보장하지 않는다.

### 6.3 월드 표면 생성

`WorldGrid`의 셀을 그대로 한 장씩 그리지 않고, 각 청크에서 주변 셀 관계를 분석해 시각 표면을 만든다.

입력:

- 셀 타입과 파괴 단계
- 상하좌우 및 대각 이웃의 고체 여부
- 밴드·지층·표면 시드
- 방·통로·출입구·보스 공간 태그
- 램프·출구·소품·세트피스 소켓

출력:

- 바닥 중심면
- 바닥 경계·균열·젖은 영역·잔해 데칼
- 벽 상단 cap
- 북·남·동·서 벽 정면 또는 측면
- 안쪽·바깥쪽 모서리
- 바닥-벽 접합 AO
- 전경 오클루더
- 그림자 캐스터 윤곽
- 조명·발광·소품 소켓

청크 크기는 기존 시스템과 맞춰 16×16셀을 기본으로 한다. 타일 파괴 시 해당 청크와 인접 경계
청크만 dirty 처리한다.

### 6.4 렌더 레이어

신규 Sorting Layer를 다음 순서로 만든다.

| 순서 | 레이어 | 내용 |
|---:|---|---|
| 0 | `WorldVoid` | 화면 외 암흑, 먼 후경, 지하 공극 |
| 1 | `GroundBase` | 큰 바닥 덩어리 |
| 2 | `GroundDetail` | 경계 블렌드, 균열, 레일 바닥부 |
| 3 | `GroundDecal` | 먼지, 액체, 파편, 접촉 AO |
| 4 | `BackStructure` | 북쪽 벽 정면, 후경 기둥, 배경 구조물 |
| 5 | `WallTop` | 벽 상단과 고체 셀 표면 |
| 6 | `WorldEntity` | 캐릭터, 적, 드롭, 설치물, 중경 소품 |
| 7 | `FrontStructure` | 남쪽 벽, 문틀 전면, 전경 기둥·암반 |
| 8 | `WorldFX` | 총구 화염, 충돌, 먼지, 광선 일부 |
| 9 | `VisionAndGrade` | LOS 어둠, 안개, 깊이 색보정 |
| 10 | `WorldOverlay` | 핑, 텔레그래프, 월드 라벨 |
| 11 | `UI` | HUD와 메뉴 |

`Default` 하나에 숫자만 크게 벌려 쓰는 방식은 폐기한다.

### 6.5 발 위치 정렬

동적 오브젝트는 스프라이트 중심이 아니라 지면 footprint의 가장 아래 접점으로 정렬한다.

- 캐릭터·적·소품 루트에 `VisualHeightAnchor`와 `SortingGroup`을 둔다.
- 정렬값은 투영된 발 위치 Y에서 결정한다.
- 머리·무기·이펙트는 같은 `SortingGroup` 내부 로컬 순서를 사용한다.
- 여러 셀을 차지하는 구조물은 가장 앞쪽 footprint 경계를 정렬 기준으로 사용한다.
- 공중 물체는 정렬 기준은 지면 그림자에 두고 본체만 시각 높이만큼 올린다.
- 보스처럼 큰 개체는 몸체를 여러 깊이 슬라이스로 나눌 수 있다.

### 6.6 전경 오클루전

남쪽 벽·천장 립·기둥이 캐릭터 앞에 그려져야 공간이 생긴다. 동시에 플레이어가 보이지 않아서는
안 된다.

필수 동작:

- 전경 오클루더와 로컬 플레이어 footprint가 겹치면 0.18~0.28초 동안 목표 알파로 페이드한다.
- 기본 목표 알파는 0.28~0.45 범위에서 아트별로 설정한다.
- 가려진 캐릭터에는 얇은 팀 색 실루엣 또는 림을 표시한다.
- 플레이어가 벗어나면 0.25~0.4초 동안 복원한다.
- 적은 완전 투명 처리하지 않고 위협 실루엣만 보장한다.
- 협동 플레이에서는 모든 로컬 관심 캐릭터를 기준으로 페이드 영역을 합친다.
- 시야 밖 구조물은 기존 LOS 어둠 규칙을 우선한다.

### 6.7 파괴 연동

한 셀이 파괴되면 다음 변경이 같은 dirty 작업 단위에서 완료돼야 한다.

1. 고체 셀과 바닥 상태 갱신
2. 주변 벽 cap·정면·모서리 재선택
3. 접합 AO와 파편 데칼 갱신
4. 전경 오클루더 갱신
5. 그림자 윤곽 갱신
6. 조명 소켓과 발광 오브젝트 갱신
7. LOS 업로드와 시각 표면의 불일치 해소

일반 파괴는 다음 렌더 프레임까지, 대량 파괴는 중요 셀 우선으로 2~3프레임 안에 완료한다. 갱신 중
빈 틈이나 한 프레임짜리 옛 그림자가 보이지 않아야 한다.

## 7. 조명·재질 명세

### 7.1 통합 월드 재질

환경 아트는 최소 다음 채널을 제공한다.

| 채널 | 용도 |
|---|---|
| Albedo RGBA | 중립 조명과 자체 음영을 포함한 기본 색 |
| Normal XY/Z | Light2D 방향 반응과 표면 굴곡 |
| Emission | 수정, 램프, 기계 표시등, 용암, 스킬 장치 |
| Material Mask | 금속·암석·습기·발광 그룹과 Light Blend Style 선택 |
| AO 또는 Height Mask | 접합부·틈·돌출 높이와 후처리 보조 |

`WorldLit` 셰이더는 다음을 지원한다.

- URP 2D Shape Light의 Multiply·Additive 블렌드
- 노멀 강도와 재질별 반응 조절
- 발광 색과 세기
- AO 곱연산
- 피격·채굴·보스 상태 틴트
- 전경 페이드와 가려진 실루엣 패스
- 지층별 습기·먼지·광물 반짝임 파라미터
- 아틀라스 패딩과 알파 가장자리에서 빛 번짐 방지

캐릭터는 별도의 `CharacterLit` 변형을 사용해 얼굴·헬멧·무기가 환경광 속에서도 읽히도록 최소광을
보장한다.

### 7.2 환경광

- Global Light 하나로 화면 전체를 동일하게 밝히지 않는다.
- 지층별 기본 환경광과 방·통로별 로컬 Ambient Zone을 둔다.
- 환경광은 형태를 읽을 수 있는 최저 조도만 제공한다.
- 미탐색 영역은 LOS 어둠이 우선하며 발광 물체도 게임 규칙이 허용하는 범위에서만 보인다.
- 벽 상단, 벽 정면, 바닥, 캐릭터에 서로 다른 최소광 계수를 허용한다.

### 7.3 광원 분류

| 분류 | 예 | 요구사항 |
|---|---|---|
| 탐색광 | 플레이어·크루 손전등 | 방향성, 벽 그림자, 노멀 반응, 부드러운 가장자리 |
| 작업등 | 랜턴, 문, 기계 | 고정 소켓, 색 온도, 미세 깜빡임, 주변 AO 완화 |
| 생체·광물광 | 수정, 식생, 광맥 | Emission 중심, 저비용 비그림자 Light2D 선택 |
| 전투광 | 총구, 폭발, 보스 | 짧은 HDR 펄스, Bloom, 피격 틴트와 노출 보호 |
| 환경광선 | 문틈, 천장 균열 | 메시 또는 셰이더 콘, 먼지 입자와 함께 표시 |

차가운 청록·보라 환경광과 따뜻한 주황 작업광을 기본 대비로 사용하되, 지층마다 주조색을 바꾼다.

### 7.4 그림자

그림자는 세 종류로 분리한다.

1. **접촉 AO**: 발·바퀴·기둥·상자와 바닥이 닿는 짧고 부드러운 그림자
2. **자체 음영**: 알베도·AO·노멀에 포함된 형태 설명
3. **투사 그림자**: 손전등과 강한 광원 반대편으로 뻗는 동적 그림자

기존의 “고정 발밑 그림자 없음” 결정은 이번 비주얼 목표에 맞춰 수정한다. 접촉 AO는 방향성 투사
그림자를 대신하는 검은 타원이 아니라, 물체가 바닥에 붙어 있음을 보여 주는 작고 부드러운 음영으로만
사용한다.

벽 그림자 캐스터는 셀 사각형이 아니라 생성된 벽·기둥·문 footprint 윤곽에서 만든다. 시각 높이가
큰 세트피스는 별도 캐스터 프로파일을 가진다.

### 7.5 대기 원근과 후처리

신규 `AtmosphereRendererFeature` 또는 동등한 전체화면 패스를 추가한다.

필수 기능:

- `Ground`, `Entity`, `Foreground` 세 깊이 그룹의 약한 색·대비 분리
- 지층별 저층 안개와 먼지 농도
- 광원 주변의 제한된 글로우와 광선
- 화면 가장자리 암부와 방 외곽의 검은 깊이
- 피격·보스·탈출 상태의 일시적 색 변화
- HDR Bloom의 하이라이트 보존과 과노출 클램프
- 720p~4K에서 동일한 체감 크기를 유지하는 필름 그레인

후처리는 형태를 대체하지 않고 이미 존재하는 깊이층의 분리를 강화하는 용도로만 사용한다.

## 8. 환경 아트 명세

### 8.1 제작 해상도

- 기준 footprint 1셀의 최종 소스 해상도: 128×128px
- 원화·생성·페인팅 작업 해상도: 최소 256×256px/셀
- Unity PPU: 128을 기본으로 하되 월드에서 1셀 = 1유닛 유지
- 다중 셀 자산은 셀 경계 밖 돌출을 허용한다.
- 월드 아틀라스는 최대 4096×4096 단위로 재질 채널별 동일 배치를 유지한다.
- 알파 패딩은 최소 4px, 강한 Bloom 자산은 8px 이상 확보한다.
- 월드 텍스처는 축소 시 떨림을 줄이도록 밉맵 사용 여부를 버티컬 슬라이스에서 확정한다.
- UI와 월드 텍스처의 임포트 규칙을 분리한다.

### 8.2 필수 출력물

모든 환경 자산은 다음 메타데이터와 함께 납품한다.

- footprint 크기와 점유 셀
- 발 또는 바닥 접점 pivot
- 시각 높이
- 기본 Sorting Layer와 로컬 순서
- 오클루더 여부와 페이드 그룹
- 그림자 캐스터 윤곽
- 조명 소켓 목록
- 파괴 단계와 파괴 후 대체 자산
- Albedo, Normal, Emission, Mask/AO 채널 경로

### 8.3 지층별 환경 키트

각 지층은 같은 타일의 색상 변경이 아니라 서로 다른 구조 언어를 가져야 한다.

| 지층 | 구조 언어 | 주조명 | 주요 재질 |
|---|---|---|---|
| 지층 1 | 폐광·작업장·노출된 자연 동굴 | 앰버 작업등 + 청록 외광 | 흙, 목재, 철, 보라 암석 |
| 지층 2 | 균열 지대·무너진 레일·불안정한 기계 | 보라·적색 균열광 | 갈라진 암석, 녹슨 금속, 먼지 |
| 지층 3 | 코어 시설·거대 수정·고대 산업 구조 | 마젠타·청록 고휘도 | 결정, 검은 암반, 황동·강철 |
| 이상지대 | 비정상 공간·뒤틀린 구조·생체 광물 | 지층별 팔레트 변형 + 불안정 펄스 | 변이 암석, 생체막, 발광 균열 |

### 8.4 지층당 최소 모듈 세트

| 분류 | 최소 구성 |
|---|---|
| 바닥 큰 면 | 저빈도 기본 6종, 재질 구역 4종, 큰 얼룩·균열 8종 |
| 바닥 경계 | 직선 4방향, 안쪽·바깥쪽 코너, T·십자 접합, 문턱 |
| 벽 상단 | 기본·손상·광맥·암반 재질별 직선·코너·끝단 |
| 벽 정면 | 낮음·중간·높음 3단계, 4방향, 손상 단계 |
| 전경 구조 | 남쪽 벽, 천장 립, 돌출 암반, 매달린 구조물 |
| 문·아치 | 일반 통로, 산업 문, 보스 문, 출구 게이트 |
| 기둥·받침 | 최소 8종, 파손 변형 포함 |
| 레일·배관·케이블 | 직선·곡선·분기·단절·고저 연결 최소 16모듈 |
| 대형 세트피스 | 방당 1개를 배치할 수 있는 2×2~6×6 구조물 최소 8종 |
| 기능 소품 | 램프, 콘솔, 캐시, 보급품, 발전기, 표지, 상자 |
| 장식 소품 | 잔해, 돌, 종이, 공구, 식생, 뼈, 광물 조각 최소 24종 |
| 후경·공극 | 검은 심연, 먼 암벽, 천장 실루엣, 안개 레이어 최소 8종 |

이 수량은 색상 교체를 제외한 실루엣 기준 최소치다. 반복이 눈에 띄면 세트피스와 데칼을 우선 추가한다.

### 8.5 바닥 제작 규칙

- 한 셀 안에 완결된 액자형 테두리를 넣지 않는다.
- 기본 바닥은 저대비·저빈도로 제작한다.
- 균열·자갈·종이·액체는 별도 데칼로 분리한다.
- 2×2, 3×3, 4×4 매크로 변형으로 큰 패턴 반복을 끊는다.
- 이동 가능 영역의 평균 명도와 벽의 평균 명도를 명확히 분리한다.
- 광원 없이도 바닥 경계가 읽히는 최소 AO를 유지한다.

### 8.6 벽 제작 규칙

- 벽 상단과 정면을 별도 자산 또는 별도 슬라이스로 제공한다.
- 기본 정면 높이는 0.75~1.5셀, 세트피스는 3셀 이상 허용한다.
- 남쪽 벽은 전경 오클루더 자산을 추가로 제공한다.
- 벽 정면의 하단에는 접촉 AO, 상단에는 얇은 림을 둔다.
- 코너는 단순 회전으로 처리하지 않고 빛 방향과 실루엣을 고려해 별도 제작한다.
- 파괴 단계마다 상단·정면·그림자 윤곽이 함께 변해야 한다.

### 8.7 세트피스와 환경 서사

레퍼런스의 깊이는 타일 수보다 큰 구조물에서 나온다. 맵 생성 결과에 다음 소켓을 추가한다.

- 방 후면 중심: 문, 아치, 거대 수정, 기계벽
- 방 측면: 기둥, 배관, 레일, 저장고
- 방 전면: 낮은 난간, 전경 암반, 케이블
- 통로: 레일, 조명 간격, 방향 표지, 붕괴 흔적
- 목표 공간: 출구·보스·보급품을 위한 고유 세트피스

세트피스는 충돌 셀을 바꾸지 않는 장식형과 footprint를 예약하는 구조형으로 구분한다.

## 9. 캐릭터·적·소품 아트 명세

### 9.1 공통

- 모든 개체는 발 위치 pivot과 별도 접촉 그림자를 가진다.
- 캐릭터 실루엣은 배경 명도와 무관하게 직업별로 구분돼야 한다.
- 머리·상체·주무기 방향이 8방향에서 일관돼야 한다.
- Albedo, Normal, Emission/Mask를 동일 프레임 배치로 제공한다.
- 헬멧 램프, 무기 발광부, 피해 상태는 발광 마스크로 분리한다.
- 과도한 자체 발광으로 LOS와 어둠 규칙을 무력화하지 않는다.

### 9.2 플레이어와 AI 크루

4직업 모두 최소 다음 애니메이션을 새 기준으로 제작한다.

- idle
- walk/run
- aim 또는 무기 방향 유지
- 기본 공격/채굴
- Q/E 스킬
- dash
- hit/stun
- down/revive
- 승리·탈출·시네마틱용 포즈

프레임 수보다 큰 실루엣과 접지감이 우선이다. 기존 프레임을 확대 보정해 최종 자산으로 사용하지 않는다.

### 9.3 적과 보스

- 소형 적도 바닥 접점·몸체 높이·그림자 크기를 데이터로 가진다.
- 대형 적은 머리·몸체·전경 팔/무기 등 여러 깊이 슬라이스를 허용한다.
- 보스는 방 구조와 조명 프리셋을 함께 전환하는 전용 비주얼 세트로 취급한다.
- 예고 공격은 바닥 텔레그래프와 공중 효과의 깊이층을 분리한다.

### 9.4 소품

- 높이가 있는 소품은 Y 정렬과 전경 가림에 참여한다.
- 낮은 바닥 소품은 GroundDecal 또는 GroundDetail에 남긴다.
- 램프·콘솔·수정은 LightSocket과 Emission을 함께 제공한다.
- 파괴 가능한 소품은 온전함·손상·파괴 잔해 상태를 가진다.

## 10. 카메라와 화면 연출

### 10.1 기본 카메라

- Orthographic 유지
- 제작 투영 `ReferenceTopDown`
- 기본 가시 높이 10.5~12.5셀 범위에서 검증
- 플레이어 세로 앵커는 화면 아래에서 52~60% 범위
- 조준 룩어헤드는 유지하되 큰 전경 구조물을 보여 줄 수 있도록 완만하게 조정
- 카메라 경계는 시각적으로 솟은 벽과 전경의 여백까지 포함해 계산

### 10.2 동적 줌

- 솔로·좁은 전투에서는 캐릭터가 크게 보이는 근접 줌을 유지한다.
- 크루가 벌어지거나 대형 보스가 등장하면 서서히 줌 아웃한다.
- 줌 전환 중 월드 PPU와 후처리 효과의 체감 크기가 급변하지 않아야 한다.
- 중요한 스킬 텔레그래프가 화면 밖으로 잘리지 않도록 최소 여백을 보장한다.

### 10.3 카메라 효과

- 이동 추종, 데드존, 룩어헤드
- 충격 방향을 반영한 Impulse
- 보스 등장 시 세트피스 중심 구도
- 대형 구조물 통과 시 짧은 전경 패럴랙스
- 광원 플래시 중 자동 노출 또는 Bloom 상한 보호
- 멀미·광과민 옵션에서 흔들림·플래시·Bloom을 줄이는 설정

## 11. 대기·배경·VFX

### 11.1 배경

플레이 가능한 셀 바깥을 단순 검정으로 비우지 않고 여러 깊이층으로 구성한다.

- 가까운 전경 암반 실루엣
- 먼 암벽 또는 산업 구조
- 심연의 색 안개
- 희미한 먼 광원
- 천장 낙진·먼지·수증기

배경은 이동 가능한 바닥보다 낮은 대비를 유지하며 게임 오브젝트처럼 보이면 안 된다.

### 11.2 지속 환경 VFX

- 깊이층별 부유 먼지
- 조명 안에서만 강해지는 미세 입자
- 천장 낙진과 작은 돌가루
- 배관 증기와 균열 연무
- 광물 미세 반짝임
- 바닥을 스치는 낮은 안개

입자는 화면 전체에 균일하게 뿌리지 않고 방 태그와 LightSocket 주변에서 생성한다.

### 11.3 상호작용 VFX

채굴·사격·폭발 효과는 다음 층으로 분리한다.

- 바닥 데칼과 균열
- 접점 파편과 불꽃
- 공중 먼지·연기
- 발광 플래시
- 전경을 지나가는 큰 파편
- 광원과 그림자에 반응하는 잔류 연무

## 15. 수용 기준

### 15.1 시각

- 기본 장면에 최소 `후경/바닥/중경 개체/전경` 네 깊이층이 식별된다.
- 벽은 상단과 정면이 구분되고 바닥과의 접합부에 AO가 있다.
- 캐릭터가 기둥·문틀·남쪽 벽 뒤를 지나갈 때 자연스럽게 가려진다.
- 가려진 플레이어와 위험한 적은 실루엣 보정으로 계속 식별된다.
- 광원이 꺼져도 알베도와 AO만으로 주요 형태가 읽힌다.
- 광원을 켜면 Normal과 Emission이 재질별로 다른 반응을 보인다.
- 이동 가능한 바닥이 벽·공극·전경보다 먼저 읽힌다.
- 2×2 이상의 큰 형태와 데칼이 셀 반복을 끊는다.
- 기본 카메라에서 캐릭터와 주요 구조물의 화면 비율이 레퍼런스 목표 범위에 들어온다.
- 레퍼런스 비교 캡처에서 단순한 밝기·Bloom 증가가 아니라 실제 깊이층 차이가 확인된다.

### 15.2 기능

- 채굴·폭발·보스 지형 변경 뒤 표면·오클루더·그림자·LOS가 함께 갱신된다.
- 화면 좌표 조준, 핑, 제작 배치, 텔레그래프가 신규 투영에서 정확하다.
- 캐릭터·적·소품의 발 위치 정렬이 모든 이동 방향에서 뒤집히지 않는다.
- 전경 페이드가 전투 판정과 네트워크 상태에 영향을 주지 않는다.
- 기존 시뮬레이션 EditMode 패리티 테스트가 모두 유지된다.
- 신규 표면 생성과 정렬 규칙은 같은 시드에서 결정적이다.

### 15.3 해상도와 화면비

- 1280×720, 1920×1080, 2560×1440, 3840×2160에서 타일 경계와 광원 패딩 오류가 없다.
- 16:9, 16:10, 21:9에서 카메라 경계와 전경 오클루전이 정상이다.
- 줌 인·아웃과 카메라 이동 중 텍스처 떨림과 seam이 눈에 띄지 않는다.
- HUD 안전 영역 때문에 핵심 피사체가 지속적으로 가려지지 않는다.

### 15.4 성능

- 기준 PC 1080p High에서 전체 런 60fps 목표를 만족한다.
- 대량 파괴·4인 크루·보스·폭발이 겹친 스트레스 장면이 초기 성능 예산을 넘지 않는다.
- dirty 청크 갱신이 프레임 스파이크와 런타임 GC를 지속적으로 만들지 않는다.
- 품질 단계 변경 뒤 시각적으로 필수적인 깊이층과 가독성은 유지된다.

## 16. 테스트 계획

### 16.1 EditMode

- 투영 정·역변환
- surface topology 직선·코너·섬·좁은 통로 fixture
- 셀 파괴 전후 모듈 선택
- footprint 기반 sorting key
- 같은 시드에서 세트피스와 데칼 결정성
- 누락 채널·PPU·pivot 임포트 검사
- 오클루더 윤곽 생성

### 16.2 PlayMode

- 캐릭터가 4방향 벽과 문을 통과할 때 정렬
- 전경 페이드 진입·복원·다중 캐릭터 합성
- 손전등과 램프가 벽·캐릭터·소품 노멀에 반응
- 광원 반대편 투사 그림자와 접촉 AO 동시 표시
- 셀 파괴·폭발·보스 벽 생성 중 시각 동기화
- LOS 경계와 솟은 벽 아트의 불일치 여부
- 카메라 줌·흔들림·시네마틱 중 깊이 정렬

### 16.3 시각 회귀

고정 시드와 카메라 위치로 다음 캡처를 자동 생성한다.

- 지층별 일반 방
- 좁은 통로
- 문·아치 통과
- 4직업 전투
- 광원이 많은 방
- 거의 어두운 방
- 대량 파괴 직전·직후
- 보스 등장·전투·사망
- 전경 뒤 플레이어
- 16:9·21:9 비교

픽셀 완전 일치는 요구하지 않는다. 대신 누락 레이어, 잘못된 정렬, 조명 소실, seam, 과노출을
자동 또는 리뷰 체크리스트로 검출한다.

## 17. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 신규 아트를 기존 한 셀 구조에 억지로 넣음 | 고정 방 버티컬 슬라이스에서 다층 렌더러를 먼저 완성 |
| 조명 수치만 반복 조정하며 구조 문제를 가림 | Albedo-only, Normal-only, AO-only 캡처를 승인 절차에 포함 |
| 높은 벽이 플레이를 가림 | 전경 그룹, 관심 캐릭터 합성 페이드, 실루엣 패스 |
| 파괴 가능한 모든 경계 조합의 아트 폭증 | topology 규칙과 모듈 조합, 매크로 세트피스 분리 |
| 투명 스프라이트 오버드로 증가 | 아틀라스 여백 축소, 청크 컬링, 전경 그룹 비활성화, 품질 단계 |
| 동적 광원·그림자 비용 증가 | shadowed/non-shadowed 광원 분리, 화면 컬링, 품질 예산 |
| 새 아트가 다른 투영 프리셋에서 왜곡 | 프로덕션은 `ReferenceTopDown`만 인증하고 나머지는 개발 비교용으로 제한 |
| 어두운 화면이 게임 가독성을 해침 | 캐릭터 최소광, 위협 실루엣, 텔레그래프 별도 레이어 |
| 카메라를 가까이해 전투 정보가 잘림 | 상황별 동적 줌과 보스·협동 전용 프로파일 |
| 지층별 아트 생산량 과다 | 지층 1 완성 후 모듈·셰이더·툴 재사용성을 검증한 뒤 확장 |

## 18. 완료 정의

비주얼 오버홀은 다음 조건을 모두 만족할 때 완료다.

- 신규 월드 아트가 기존 50px 타일의 확대·왜곡에 의존하지 않는다.
- `ReferenceTopDown`에서 바닥·벽 정면·상단·전경·캐릭터가 하나의 공간으로 읽힌다.
- 지층 1~3과 이상지대가 독립적인 환경 키트와 조명 프로파일을 가진다.
- 캐릭터·적·소품이 발 위치로 정렬되고 전경 오클루전이 작동한다.
- Albedo·Normal·Emission·Mask/AO 파이프라인이 모든 주요 자산군에 적용된다.
- 파괴 가능한 절차 맵에서 표면·그림자·오클루더·LOS가 동기화된다.
- 카메라와 피사체 크기가 레퍼런스의 밀도와 가독성 목표를 충족한다.
- 자동 시각 회귀와 성능 검증이 빌드 전 과정에 포함된다.
- 기존 게임 규칙과 시뮬레이션 패리티가 유지된다.

## 19. 착수 우선순위

첫 구현 배치는 다음 순서를 지킨다.

1. 스타일 바이블과 신규 128px/셀 템플릿 확정
2. 한 개 고정 방용 최종급 환경 아트 제작
3. Sorting Layer·발 위치 정렬·전경 오클루전 구현
4. 벽 상단·정면·바닥 AO를 포함한 다층 환경 렌더러 구현
5. 통합 Lit 재질과 조명·그림자·대기 패스 구현
6. 카메라 거리와 캐릭터 화면 비율 확정
7. 레퍼런스 비교 승인
8. 승인된 결과를 절차 맵과 파괴 시스템으로 확장

고정 방이 레퍼런스 수준에 도달하기 전에는 전 지층 타일 양산을 시작하지 않는다. 이 순서를 지켜야
기술 구조가 확정되지 않은 상태에서 대량의 아트를 다시 만드는 일을 피할 수 있다.

### 19.1 현재 착수 범위

첫 생산 단위는 지층 1의 작은 디오라마형 테스트 방 하나다. 전 지층 양산이나 캐릭터 전체
애니메이션보다 다음 순서를 우선한다.

1. 레퍼런스 대표 프레임과 테스트 방 비주얼 타깃 고정
2. 방 키아트와 모듈 배치 보드 제작
3. 바닥·벽 상단·벽 정면·전경 벽의 최소 조립 세트 제작
4. 아치 1종, 기둥 2종, 조명 소품 3종, 장식 8~12종 제작
5. 대형 초점 구조물 1종과 안개·먼지·광선 VFX 제작
6. Albedo 승인 후 Normal·Emission·Material Mask·AO 파생 및 검수
7. `approved/` 패키지를 Claude 구현 트랙에 인계

최초 키아트와 모듈 보드는 최종 게임 파일 그 자체가 아니라 시각적 계약이다. 개별 리소스는
동일한 계약을 유지하면서 투명 배경, 정확한 footprint, 피벗, 패딩과 채널 정합성을 갖춘 파일로
분리 생산한다.
