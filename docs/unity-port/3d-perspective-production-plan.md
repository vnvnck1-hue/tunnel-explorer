# 3D 원근 메인 런 완성 계획

## 1. 목적

TunnelCrew 메인 런을 `실제 높이의 3D 벽 + 원근 카메라 + 2D 빌보드 액터`로 표시한다.
기존 시뮬레이션·충돌·저장·전투 규칙은 변경하지 않고 Presentation 계층만 이주한다.

현재 `codex/gungeon-perspective-spike` 브랜치에는 메인 런에서 기본 활성화되는 구조 검증판이 있다.
단색 3D 벽·바닥과 일반 `SpriteRenderer` 빌보드 미러링까지 검증했으며,
이 문서는 이를 실제 자산·조명·연출·입력까지 연결된 완성형 본선으로 만드는 계획이다.

## 2. 완료 정의

다음 조건을 모두 만족해야 완성판으로 본다.

- 플레이어 4직업의 방향·이동·대시·피격·다운 표현이 실제 스프라이트로 정상 작동한다.
- 크루, 일반 적, 광란종, 보스의 애니메이션·반전·색상·점프 높이가 3D 공간에서 정확하다.
- 바닥, 벽 윗면, 벽 정면, 광맥, 균열, 소품에 기존 본선 자산이 적용된다.
- 손전등, 횟불, 크루, 보스, 플레어 광원과 그림자가 새 월드 표현과 일치한다.
- 투사체, 선딜, 폭발, 파편, 드릴, 텔레그래프, 전리품이 바닥과 높이에 맞게 표시된다.
- 마우스 조준, 핑, 설치, 세트피스 상호작용이 원근 카메라 좌표와 일치한다.
- HUD, FTUE, 일시정지, 관전, 보스 인트로, 휴식·결과 화면이 기존 흐름대로 작동한다.
- 카메라와 벽 사이에 액터가 가려져도 플레이 정보를 잃지 않는다.
- 대상 해상도와 화면비에서 목표 프레임을 유지하며 런타임 할당이 안정적이다.
- EditMode 전체 테스트, 핵심 PlayMode 스모크, 스탠드얼론 빌드 검증을 통과한다.

## 3. 기본 원칙

- 시뮬레이션 좌표가 단일 출처다. 렌더 좌표를 다시 역변환해 게임 규칙에 사용하지 않는다.
- 액터 뷰가 스프라이트 프레임·반전·색·크기·높이를 3D 렌더러에 명시적으로 전달한다.
- 기존 `SpriteRenderer` 전체 검색은 검증용으로만 사용하고 완성판에서 제거한다.
- 하나의 셀 크기는 3D 월드에서도 1 단위로 유지한다.
- 2D HUD와 월드 내 3D/빌보드 요소를 분리한다.
- `_perspectiveWorld` 폴백을 최종 전환 승인 전까지 유지한다.
- 카메라 각도·FOV·거리·벽 높이는 단일 설정 소스에 두고 코드에 흐트러뜨리지 않는다.

## 4. 단계별 작업

### 1단계. 액터 렌더 계약 설계

#### 작업

- `PerspectiveActorRenderState` 또는 동등한 표현 계약을 만든다.
- 계약에 시뮬레이션 바닥 좌표, 시각 높이, 스프라이트, 피벗, 틴트, 스케일, 투명도, 렌더 그룹을 포함한다.
- `PlayerView`, `CrewView`, `EnemyView`가 이 계약을 생성하거나 갱신하도록 한다.
- 액터 생성·사라짐을 이벤트 또는 풀 등록으로 처리한다.
- `FindObjectsByType<SpriteRenderer>` 기반 스캔을 제거한다.

#### 완료 기준

- 청록색 대체판 없이 플레이어 실제 프레임이 나온다.
- 플레이어 4직업의 8방향 반전과 애니메이션이 정상이다.
- 적 생성·사망·재사용, 보스 프레임, 크루 직업 외형이 정상이다.
- 발 피보가 바닥에 고정되고 점프·바운스는 높이로만 표현된다.

### 2단계. 원근 입력 좌표 연결

#### 작업

- 원근 카메라의 화면 좌표를 바닥 평면에 레이캐스트한다.
- 명중점을 시뮬레이션 XY 좌표로 변환하여 조준·핑·설치·공작에 사용한다.
- 기존 2D 카메라의 `ScreenToWorld` 의존성을 입력에서 제거한다.
- 카메라 흔들림, 줌, 보스 초점, 관전 추적을 원근 카메라에 연결한다.

#### 완료 기준

- 마우스 커서와 조준·투사체 방향이 일치한다.
- 화면 모서리, 레터박스, 다른 화면비에서도 입력 오차가 없다.
- 핑과 설치물이 선택한 셀에 생성된다.

### 3단계. 환경 자산과 3D 메시 연결

#### 작업

- `EnvironmentKit`의 바닥, 벽 윗면, 벽 정면, 림, 모서리 스프라이트를 3D 표면에 매핑한다.
- `SurfaceMaterialSet`의 Normal·Emission·Mask·AO 채널을 사용하는 3D 월드 머티리얼을 구성한다.
- Dirt, Stone, Ore, Gem, Crys, Core 표면과 손상 단계를 구분한다.
- 지층별 환경 키트, 보스 벽, 광맥 정면, 균열, 유기적 암반 장식을 연결한다.
- 타일 변경은 dirty 셀이 포함된 청크만 다시 생성한다.

#### 완료 기준

- 단색 임시 벽이 사라지고 기존 환경 자산이 모든 표면에 들어간다.
- 채굴 전·중·후의 벽 표시가 시뮬레이션과 동기화된다.
- 지층 전환 시 잘못된 재질이나 이전 청크가 남지 않는다.

### 4단계. 조명·그림자·시야 이주

#### 작업

- 기존 `Light2D` 정보를 새 3D 표면에 적용할 방식을 확정한다.
- 우선순위는 기존 광원 데이터를 버퍼로 전달하는 하이브리드 월드 셰이더다.
- 전역광, 손전등, 플레이어 후광, 횟불, 크루, 플레어, 보스 광원을 연결한다.
- 캐릭터 접지 그림자와 벽 차폐 그림자를 3D 바닥 기준으로 만든다.
- 암흑, LOS, 안개, 지층 색보정, Volume 효과를 새 카메라에 적용한다.

#### 완료 기준

- 광원 이동·깜빡임·세기·색상이 기존 게임 상태와 동기화된다.
- 벽 윗면·정면·바닥·캐릭터의 최소 조도 정책이 유지된다.
- 암부에서도 플레이 필수 정보가 사라지지 않는다.

### 5단계. 전투·연출·월드 정보 이주

#### 작업

- 투사체의 Body·Core·Aura·Accent 계층과 우선순위 광원을 3D 공간에 옮긴다.
- 총구 화염, 기관총 길이, 선딜, 폭발, 연기, 파편, 드릴 충격을 높이와 바닥 표면에 맞춘다.
- 적 선딜 텔레그래프와 조준선을 바닥 평면에 표시한다.
- 전리품, 설치물, 작업등, 크래프트 표시를 연결한다.
- HP바, 이름표, 핑, 보스 표시, 월드 라벨을 스크린 공간 오버레이로 다시 투영한다.

#### 완료 기준

- 모든 주요 공격의 발사·이동·명중·소멸이 표시된다.
- 적 선딜과 실제 판정 영역이 일치한다.
- 개체 정보가 벽 뒤에 있거나 카메라가 이동해도 흔들리지 않는다.

### 6단계. 오클루전·카메라·구도 완성

#### 작업

- 카메라와 플레이어 사이의 벽을 감지한다.
- 벽 상단 투명화, 상단 절단, 액터 실루엣 중 투녕성과 아트에 맞는 정책을 선택한다.
- 보스 인트로, 관전 모드, 카메라 킥, 히트스톱, 흐들림을 원근 카메라에 연결한다.
- 최종 pitch, FOV, 거리, 벽 높이, 화면 중심 오프셋을 확정한다.
- 16:9, 16:10, 21:9 및 주요 해상도에서 구도를 검증한다.

#### 완료 기준

- 플레이어와 즉시 피해야 할 위험 표시가 벽에 완전히 숨지 않는다.
- 카메라 연출 중에도 HUD와 입력이 변형되지 않는다.
- 최종 카메라 설정이 단일 프로필에 저장된다.

### 7단계. 최적화와 임시 구조 제거

#### 작업

- 액터 빌보드를 풀링하고 생성·파괴 할당을 제거한다.
- 스프라이트 메시와 머티리얼을 아틀라스·셰이더 기준으로 재사용한다.
- 월드 메시를 청크 단위로 캐시하고 변경된 청크만 갱신한다.
- 절두체 실시간 스캔을 등록 구조로 바꾸고 화면 밖 액터를 컬링한다.
- RenderTexture 해상도와 필터 정책을 최종 품질 프로필에 맞춘다.
- 검증용 이름·디버그 폴더·대체판 코드를 본선 이름과 구조로 정리한다.

#### 완료 기준

- 정상 플레이에서 지속적인 GC 할당이 발생하지 않는다.
- 보스·다수 적·다수 투사체 상황에서 목표 프레임을 유지한다.
- 스파이크 전용 스캔·라벨·청록색 대체판이 제거된다.

### 8단계. 통합 QA와 본선 전환

#### 검증 범위

- 4직업 각각의 시작, 이동, 채굴, 전투, 대시, 다운, 교대
- 일반 적, 원거리 적, 광란종, 보스, 보스 사망
- 광맥·보석·크리스털·코어 채굴과 벽 파괴
- 지층1·2·3·심연 환경 전환
- 손전등, 횟불, 플레어, 어두운 구역, LOS
- FTUE, 일시정지, 관전, 크래프트, 휴식, 결과, 재시작
- 키보드·마우스 입력과 주요 해상도·화면비
- Development Build와 스탠드얼론 배포 빌드

#### 필수 검증

- Unity 컴파일 오류 0건
- 런타임 Console 오류 0건
- EditMode 전체 테스트 통과
- 핵심 PlayMode 스모크 통과
- 지층별 Game View 스크린샷 비교
- Profiler 기준 CPU, GPU, GC, 메모리 확인
- 스탠드얼론 빌드에서 타이틀 → 미션 진입 → 전투 → 지층 전환 실행

## 6. 위험과 대응

| 위험 | 대응 |
|---|---|
| 액터가 벽에 가려져 전투 정보를 잃음 | 벽 투명화·절단·실루엣 프로토타입을 초기에 비교 |
| 마우스 조준과 화면 표시가 불일치 | 2단계에서 입력 좌표를 먼저 이주하고 자동 테스트 추가 |
| 2D 조명 자산이 3D 표면에 바로 적용되지 않음 | 기존 광원 데이터를 공유하는 하이브리드 셰이더를 우선 검증 |
| 다중 카드·광원·투사체로 GPU 비용 증가 | 아틀라스, 머티리얼 공유, 광원 예산, 화면 밖 컬링 적용 |
| 스파이크와 기존 2D 본선이 동시에 유지되어 복잡도 증가 | 단계별 완료 후 소유권을 3D 모듈로 이전하고 최종 QA 후 중복 경로 제거 |
| 특정 직업·보스·지층에서만 누락 | 직업×지층×전투 종류 매트릭스로 스크린샷·스모크 검증 |

## 7. 폴백과 전환 정책

- 개발 중에는 `RunBootstrap._perspectiveWorld` 플래그를 유지한다.
- 에디터와 Development Build에서 F3으로 2D/3D를 즉시 비교한다.
- 단계별 완료 조건을 통과하지 못하면 기존 2D 표시를 배포 기본값으로 유지할 수 있다.
- 통합 QA와 스탠드얼론 빌드 승인 후에만 폴백 코드 제거 여부를 결정한다.

## 8. 권장 실행 순서

1. 액터 렌더 계약과 플레이어·적·크루 정식 연결
2. 원근 카메라 입력 좌표 이주
3. 환경 스프라이트·재질 채널과 3D 메시 연결
4. 조명·그림자·시야 이주
5. 전투 VFX·텔레그래프·월드 정보 이주
6. 오클루전 정책과 최종 카메라 값 확정
7. 최적화·임시 구조 제거
8. 전체 QA·빌드 검증·본선 전환 승인

1~2단계 완료 시 `실제로 플레이 가능한 3D 표시`, 3~6단계 완료 시
`자산과 연출이 연결된 본선 후보`, 7~8단계 완료 시 `배포 가능한 완성판`으로 판정한다.

## 9. 진행 기록

### 1단계 — 액터 렌더 계약 (2026-09-16 완료)

- `Presentation/Visual/Perspective/PerspectiveActorRegistry.cs` 신규.
  `PerspectiveActorSample`(시뮬 바닥 좌표 · 높이 · 스프라이트 · 틴트 · 스케일 · 반전 · 롤 ·
  발 피벗 정렬 · 렌더 그룹 · 깊이 보정)과 슬롯 등록 테이블 `PerspectiveActors`.
- 생산자: `PlayerView`(플레이어 + `CrewView` 가 재사용하는 크루 4직업),
  `EnemyView`(일반 · 광란종 · 보스 · 보스 사망 연출). 풀 반납·비활성은 제출을 멈추면
  자동으로 화면에서 빠지므로 소비자가 생사를 추적하지 않는다.
- 소비자: `GungeonPerspectivePreview` 가 계약을 먼저 소비하고, 아직 이주하지 않은
  투사체·이펙트·소품만 레거시 `SpriteRenderer` 미러로 그린다. 계약으로 올라온 원본은

### 2단계 — 원근 입력 좌표 (2026-09-16 완료)

- `Presentation/Visual/Perspective/PerspectiveViewport.cs` 신규. 원근 월드가 화면을 소유할 때의
  카메라·레터박스 사각형·좌표 변환의 단일 출처다. 저해상도 RenderTexture 를 `ScaleToFit` 로
  확대하므로 화면 좌표를 그대로 카메라에 넣으면 어긋난다 — 입력과 월드 라벨은 반드시 여기를 거친다.
- `CameraRig.ScreenToWorld` · `TeamOverlay.ScreenToWorld/WorldToGui` · `RunBootstrap` 의 이동 입력이
  원근이 켜져 있으면 바닥 평면 레이캐스트를 쓴다. 꺼져 있으면 기존 2D 경로 그대로다.
- 구도는 <b>기존 2D 리그가 단일 출처</b>다. 리그의 화면 중심을 시뮬 좌표로 되돌려 원근 카메라에 넘기므로
  데드존·룩어헤드·흔들림·킥·보스 시네마틱 줌·관전 추적이 자동으로 따라온다.
- 카메라 거리는 리그의 `TargetViewCells` 에서 계산한다. 기준은 <b>바닥이 몇 칸 보이는가</b>가 아니라
  <b>캐릭터가 2D 와 같은 크기로 읽히는가</b>다 — 액터는 카메라를 마주보는 빌보드라
  `d = N / (2·tan(fov/2))` 이면 초점 위의 액터가 2D 직교와 정확히 같은 비율을 차지한다.
  처음에 `sin(pitch)` 를 곱해 바닥 span 을 맞췄더니 화면이 1/sin(55°)≈1.22 배 좁아져
  캐릭터가 커 보였다(사용자 지적 2026-09-16). 원근에서는 카메라 쪽 액터가 더 크므로
  `_framingPullback` 만큼 더 물러선다. 실측(2026-09-16): 배율 1.35 → 캐릭터가 2D 본선의 0.72배,
  1.8 → 0.54배, 2.4 → 0.40배. **기본값은 1.8** 로 정했다(사용자 비교 요청).
  2.4 는 방이 넓게 읽히지만 전투 가독성이 떨어져 후보에서 뺐다. 최종 확정은 6단계 구도 검증에서 한다.

"자연스럽게 이식되었는가" 를 눈대중으로 판정하지 않기 위해, 스모크가 <b>같은 런·같은 위치에서</b>

### 구도와 밝기의 맞물림 (기록)

카메라를 물릴수록 손전등 원뿔이 화면에서 차지하는 비율이 줄어 <b>같은 조명값인데 화면이 어두워 보인다</b>.
2D 본선은 카메라가 가까워 밝은 웅덩이가 화면을 지배한다. 배율 1.8 에서 실측하면 배경보다 밝은 픽셀이
69% · 평균 휘도 0.185 로 월드는 정상적으로 그려지고 있다. 구도를 더 넓히기로 정하면
`PerspectiveLightBuffer.intensityGain` 또는 전역광을 원근 전용으로 조금 올려야 2D 와 같은 가독성이 난다 —
다만 그 순간 2D 와 밝기가 갈라지므로 6단계 구도 확정과 함께 결정한다.
