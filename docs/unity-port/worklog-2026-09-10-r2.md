## 11. 2026-09-11 — 공간감: 다이내믹 레인지 클램프 해제 + 벽 윗면 암전

## 12. 2026-09-11 — 벽 파괴 충격파 (셰이더 정점 변위)

사용자 요청: "코어키퍼는 벽을 부수면 주변 벽이 흔들린다. 이미지가 깨지지 않고 아주 부드럽게.
단순히 타일을 흔드는 방법 말고."

### 12.1 왜 트랜스폼으로는 안 되는가

타일맵 청크는 **메시 하나**다. 청크를 통째로 흔들면 이웃 청크와의 경계가 찢어지고,
타일을 각자 움직이면 타일 사이가 벌어진다. 어느 쪽이든 "이미지가 깨진다".

해법은 변위를 **월드 좌표만의 연속 함수**로 두는 것이다. 청크 메시에서 맞닿은 두 타일의 정점은
같은 월드 좌표에 있으므로 같은 변위를 받는다 — 벌어질 수가 없다. 정점이 움직여도 위상학은 그대로다.

### 12.2 구현

| 파일 | 역할 |
|---|---|
| `Shaders/TunnelCrewImpact.hlsl` (신규) | 충격 8개를 받는 전역 배열 + `TCApplyImpact(positionOS, wobble)` |
| `Shaders/TunnelCrewLit2DProps.hlsl` | 공용 CBUFFER 에 `_ImpactWobble`(표면별 추종 배율) |
| `Shaders/WorldLit.shader` · `Tilemap-Lit-Normal.shader` | 세 패스(Universal2D · Normals · Unlit) 정점에서 `UnityFlipSprite` 직후 변위 |
| `Presentation/Juice/ImpactWaveDirector.cs` (신규) | 링 버퍼 8슬롯 · 만료 정리 · `Shader.SetGlobalVectorArray` 업로드 |
| `RunBootstrap.cs` | `Sim.TileBroken` 에서 `Add(ToRender(셀 중심), 세기)`. 암반·코어 1.35 · 원석 0.8 · 그 외 1.0 |

파동식: `dir * sin(dist*k - age*v) * (1-dist/R)² * (1-age/T)² * saturate(dist/0.35)`.

- **공간 감쇠가 반경에서 정확히 0** 이어야 한다. 0 이 아니면 그 원 둘레에 눈에 보이는 단차가 생긴다.
- 시간 감쇠도 끝에서 정확히 0 — 충격이 끊기지 않고 사라진다.
- 중심에서는 방향이 정의되지 않으므로 `saturate(dist/0.35)` 로 특이점을 없앤다.
- 변위는 월드에서 계산하고 `TransformWorldToObject` 로 돌려놓는다 — 어떤 트랜스폼에서도 맞다.

기본값: 진폭 0.085셀 · 반경 4.2셀 · 지속 0.42초 · 속도 26셀/초 · 파수 3.1rad/셀.
전부 `ImpactWaveDirector` 인스펙터에서 조절한다.

### 12.3 검증

`timeScale = 0` 으로 구도를 고정하고 충격 유무 두 프레임을 비교했다.

- 변화 픽셀 **23,428** · 변화 중심 (966,489) · 반경 평균 128px 최대 329px — 충격점 중심의 원형 영역.

### 12.4 고친 것 (구현 중)

- `positionOS` 는 이 셰이더들에서 `float3` 다 — `float4` 로 만들었다가 세 패스 전부 컴파일 실패.
- include 를 `TunnelCrewLit2D.hlsl` 옆에 한 번만 넣었더니 **패스 0 에만** 들어갔다. HLSL 패스는 각자
  독립 컴파일 단위이므로 **패스마다** `Core2D.hlsl` 직후에 넣어야 한다.
- `IsometricProjection` 은 `TunnelCrew.Presentation` 이지 `...Presentation.Visual` 이 아니다.
- **플레이 모드 중에는 새 파일이 임포트되지 않는다.** 새 `.cs`/`.hlsl` 을 만든 뒤 플레이 중에 refresh 를
  불러서 한참 "타입 없음" 을 쫓았다. 새 파일은 플레이를 끄고 임포트할 것.

### 12.5 남은 것

- **그림자 캐스터·드롭섀도는 파동을 따라가지 않는다.** 진폭이 작아 지금은 티가 안 나지만,
  진폭을 키우면 그림자만 제자리에 남는 것이 보인다.
- 바닥도 `_ImpactWobble = 1` 이라 같이 출렁인다. 벽만 흔들고 싶으면 바닥 재질을 0.3 정도로 낮춘다.
- 화면 흔들림(`Feedback.BlockBroken`)과 이 파동이 겹친다 — 둘의 세기 배분은 눈으로 보고 조정할 것.

### 12.6 강화 + 벽 윗면 경계 그라데이션 (같은 날, 사용자 피드백 2차)

"거의 티가 안 난다. 모든 값을 매우 강력하게" · "벽면과 윗면 경계가 어색하게 잘린다. 맞닿는 쪽은
그라데이션으로 풀려야 입체로 읽힌다."

**충격파 강화**

| 값 | 전 | 후 |
|---|---:|---:|
| 진폭(셀) | 0.085 | **0.34** |
| 반경(셀) | 4.2 | **8.5** |
| 지속(초) | 0.42 | **0.78** |
| 속도(셀/초) | 26 | **15** |
| 파수(rad/셀) | 3.1 | **1.8** |

속도와 파수를 낮춘 것이 중요하다. 잔물결이 촘촘하면 큰 진폭도 "지글거림" 으로 보인다 —
파장을 늘려야 **면이 통째로 출렁이는** 그림이 된다.

측정(정지 프레임 A/B): 변화 픽셀 23,428 → **129,305** · 최대 반경 329 → **602px** · 차이 p99 9.3 → **25.3**.

**벽 윗면 경계 그라데이션**

기존에는 고체 칸 전부가 `_solidVisibility` 하나로 평평하게 눌렸다. 그래서 벽면(밝음)과 윗면(검정)
사이에 셀 경계를 따라 직선이 생겼다 — 사용자가 첨부한 그림의 그 선이다.

`DarknessOverlay.SolidEdgeFactor(c, r)` 를 넣어 고체 칸을 굴착 경계와의 관계로 나눈다.

| 위치 | 배율 | 실효 가시도 |
|---|---:|---:|
| **남쪽이 열린** 고체(정면과 이어지는 윗면) | ×2.6 | 0.57 |
| 다른 방향이 열린 고체 | ×1.88 | 0.41 |
| 사방이 막힌 안쪽 | ×0.35 | 0.077 |

남쪽을 가장 크게 보는 이유는 탑다운에서 우리가 마주 보는 면이 남향이고, 그 위의 윗면이
정면과 이어지는 부분이기 때문이다. 셀 단위 세 단계지만 `Darkness.shader` 의 **1.35칸 9탭 필터**가
이를 부드러운 경사로 푼다 — 새 블러를 만들 필요가 없었다.

검증: 컴파일 오류 0 · 캡처 `impact-strong-compare.png` · `walltop-gradient-zoom.png`.

**함정** — `AddComponent` 로 붙는 컴포넌트의 기본값을 바꿔도 **실행 중인 세션은 옛 어셈블리**를 쓴다.
플레이를 끄고 refresh 한 뒤 다시 들어가야 새 기본값이 적용된다. 타입에서 직접 읽어 확인하는 편이 빠르다.

### 12.7 반경 절반 (사용자 지시)

"충격파의 범위를 절반으로 줄이고 강도는 그대로."

`_radiusCells` **8.5 → 4.25**. 나머지는 손대지 않았다(진폭 0.34 · 지속 0.78 · 속도 15 · 파수 1.8).

공간 감쇠가 `(1 - 거리/R)²` 이라 **중심 진폭은 반경과 무관하다** — `거리 → 0` 이면 계수가 1 이므로
진폭 0.34 가 그대로 나온다. 반경은 "어디까지 번지는가" 만 정한다. 그래서 지시대로 범위만 줄고
타격점의 세기는 유지된다.

실행 중 실측: `amplitude=0.34 radiusCells=4.25 duration=0.78 waveSpeed=15 waveNumber=1.8`.

**측정 메모** — 정지 프레임 A/B 로 반경 전후를 비교하려 했으나 두 가지가 방해했다.
① `ImpactWaveDirector.LateUpdate` 가 매 프레임 자기 값을 전역에 올리므로 수동 주입이 즉시 덮인다.
② `timeScale = 0` 으로 멈춰도 채굴로 이미 들어온 슬롯이 여럿 살아 있어 한 충격만 분리되지 않는다.
단일 충격을 재려면 디렉터를 잠시 비활성화하고 주입해야 한다.

### 12.8 벽만 출렁이게 · 손전등을 캐릭터 아래로 (사용자 지적 3차)

"캐릭터·바닥 등 주변 화면이 다 흔들려서 벽이 피격받는 느낌이 안 산다. 벽만 물결치고 나머지는
전혀 영향 없게." · "후레쉬 빛이 캐릭터보다 아래로 소팅되게."

**진범은 셰이더가 아니라 카메라 킥이었다.** `Feedback.BlockBroken` 이 `Kick(7.6 / 6.2 / 18.2)` 로
화면 전체를 흔들고 있었다. 화면이 움직이면 캐릭터·바닥·HUD 까지 같이 움직이므로, 벽만 정점
변위를 줘도 "벽이 맞았다" 가 아니라 "화면이 흔들린다" 로 읽힌다. 킥을 걷고 타격감을 충격파에
넘겼다. 히트스톱은 유지한다(시간 정지는 화면을 움직이지 않는다).

| # | 변경 | 파일 |
|---|---|---|
| 1 | 카메라 킥 제거(히트스톱 유지) | `Juice/Feedback.cs` |
| 2 | `_ImpactWobble` 을 **슬롯에서 자동 결정** — WallTop·WallFront 만 1, 바닥·소품·캐릭터는 0 | `Visual/Materials/SurfaceMaterialSet.cs` |
| 3 | `LitWorldOnly` · `LitGroundWorldOnly`(개체 대역 제외) | `Visual/VisualLayers.cs` |
| 4 | `LightSocket.worldSurfacesOnly` + `ApplyLitLayers` 3번째 인자 | `Visual/Lighting/LightSocketRenderer.cs` |
| 5 | 손전등·크루 손전등 소켓에 `worldOnly = true` | `Bootstrap/RunBootstrap.cs` |

**슬롯에서 자동 결정한 이유** — 재질 에셋 12종(레퍼런스+지층 3계열)에 값을 손으로 박으면 키트를
다시 생성할 때 날아간다. `minLightSlot` 이 이미 표면 종류를 들고 있으므로 거기서 파생시키면
새 지층 키트도 자동으로 맞는다.

**소켓 플래그가 필요한 이유** — `LightSocketRenderer.ApplyLitLayers` 가 매 프레임 대상 레이어를
덮어쓴다. `Light2D.targetSortingLayers` 에 직접 대입하면 다음 프레임에 사라진다.

**검증(플레이 실측)**

- `_ImpactWobble`: WallTop 1.0 · WallFront 1.0 · OreFront 1.0 · WallCrack 1.0 · **Floor 0.0**
- 손전등·크루 손전등 대상 레이어 = `GroundBase·GroundDetail·GroundDecal·BackStructure`
  (`Default`·`WorldEntity` 빠짐) · 플레이어 후광은 개체 대역 유지 — 캐릭터 가독성은 후광이 맡는다
- `BlockBroken` 호출 전후 화면 흔들림 0.817 → 0.817 (킥 없음)
- EditMode **401/401** · 컴파일 오류 0 · 캡처 `wall-only-flash-under.png`

**남은 것** — 드릴 타격 비트(`DrillBeat`, 킥 6)는 그대로다. 채굴 중 화면이 계속 미세하게 흔들리므로,
충격파만으로 충분하다고 판단되면 이것도 걷는다.
