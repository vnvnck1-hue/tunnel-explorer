# 모듈러 거너 비주얼 후속 작업 로드맵

작성일: 2026-09-16  
대상: `unity/TunnelCrew/Assets/_Project/Scenes/ModularGunnerPrototype.unity`  
상태: Codex 아트 트랙 ↔ Claude Unity 구현 트랙 인계 기준

## 1. 목표와 레퍼런스 경계

현재 모듈러 거너 테스트 씬을 기능 확인용 프로토타입에서 실제 게임 화면에 가까운 수준으로 끌어올린다.

- **Enter the Gungeon 참고 범위:** 전투 가독성, 총구 반응, 피격·사망 연출, 탄환 표현, 카메라 주스, 물리적으로 보이는 소형 파편.
- **환경 방향:** 본편에서 확정한 Core Keeper식 굴착 공간과 땅굴 크루 고유 팔레트를 유지한다. Enter the Gungeon의 방·타일 디자인을 그대로 모사하지 않는다.
- **픽셀 규격:** URP 2D, 16 PPU, 320×180 기준 해상도, Point 필터, Mip Map 비활성, 무압축, MSAA/AA 비활성 기준을 유지한다.
- **구현 원칙:** 낮은 해상도에서도 실루엣과 효과의 시작점이 즉시 읽혀야 한다. Bloom이나 화면 흔들림으로 불명확한 원화를 감추지 않는다.

### 1.1 역할 분리 — 이 문서의 최우선 규칙

이 로드맵은 한 에이전트가 전부 구현하는 계획이 아니다. 아래처럼 **이미지 제작과 Unity 구현을 분리**한다.

| 담당 | 수행 범위 | 수행하지 않는 범위 |
|---|---|---|
| **Codex — 아트 트랙** | 이 문서에서 신규 이미지가 필요하다고 확정된 픽셀 PNG·스프라이트 시트·데칼·VFX 프레임 제작 | C#·셰이더 작성, Unity 임포트 설정, Sprite Editor 슬라이스, Animator, 프리팹·씬·머티리얼 수정, 물리·조명·카메라·풀링 구현 |
| **Claude — Unity 구현 트랙** | 기존 코드 진단, 아트 요청 규격 확정, 이미지 임포트·슬라이스·피벗, 코드·셰이더·파티클·조명·카메라·물리·소팅·풀링, 씬·프리팹 연결, Play Mode 검증 | Codex가 맡은 최종 픽셀 이미지의 임의 재제작·덮어쓰기 |
| **사용자 — 승인** | 아트 방향 승인, 선택형 이미지의 제작 여부 결정, 최종 플레이 감각 승인 | 구현 세부 절차 작성 |

역할이 섞인 항목은 **이미지 파일 제작만 Codex**, 그 이미지를 사용하는 모든 런타임 작업은 **Claude**가 맡는다. Codex는 Unity 프로젝트의 코드·씬·프리팹을 수정하지 않고, Claude는 이미지 문제가 확인되면 임시로 덮어 그리지 않고 필요한 수정 내용을 Codex에 요청한다.

### 1.2 인계 순서

1. Claude가 현재 구현과 기존 자산을 확인해 정말 새 이미지가 필요한지 먼저 판정한다.
2. 새 이미지가 필요하면 Claude가 용도, 픽셀 크기, 프레임 수, 방향, 피벗, 연결 규칙을 **아트 요청 카드**로 적는다.
3. Codex가 요청 카드 범위의 이미지만 제작한다. Unity 코드나 임포트 작업은 하지 않는다.
4. 사용자가 이미지 방향을 승인한다.
5. Claude가 승인 이미지를 Unity에 임포트·슬라이스·연결하고 Play Mode에서 검증한다.
6. 실패 원인이 그림이면 Codex로, 임포트·정렬·셰이더·동작이면 Claude로 되돌린다.

이미지 파일은 Unity `Assets/`에 바로 넣지 않고 기존 아트 계약인 `art-production/test-room-v01/`의 `concept/`, `source/`, `approved/` 단계를 따른다. Unity 프로젝트로 복사하고 `.meta`를 생성하는 작업은 Claude가 담당한다.

## 2. 현재 확보된 기반

- 총알 탄착군 분산과 연속 사격
- 탄피 배출 및 짧은 수명의 2D+높이 물리
- 벽 피격 불꽃·석재 파편·충격 버스트
- 적 피격 플래시·압축 변형·파편·사망 버스트
- 총구 순간광과 카메라 흔들림
- 파편 전용 물리 레이어와 충돌 관계 정리
- Y 기반 캐릭터·벽 소팅과 캐릭터 뒤 탄피 소팅
- 높은 벽 정면과 벽 옆면 충돌 차단
- Pixel Perfect Camera와 런타임 조절·저장 가능한 카메라 프로파일

## 3. 아트 산출물 표시

| 표시 | 의미 |
|---|---|
| **필수** | 새 픽셀 이미지 또는 애니메이션 프레임이 있어야 목표 품질에 도달한다. |
| **선택** | 코드만으로도 구현 가능하지만 전용 이미지가 있으면 품질이 크게 올라간다. |
| **불필요** | 기존 스프라이트와 코드·셰이더·파라미터 작업만으로 구현한다. |

이 표시는 **Codex 작업 여부**를 판단하기 위한 것이다.

- **필수:** Claude가 규격을 전달하면 Codex 아트 작업을 먼저 진행한다.
- **선택:** Claude가 기존 자산으로 1차 구현한 뒤 이미지 부족이 확인될 때만 Codex에 요청한다.
- **불필요:** 전부 Claude 작업이다. Codex 작업 목록에 넣지 않는다.

## 5. 이미지 제작이 필요한 작업 요약

### 반드시 새 이미지가 필요한 묶음

## 7. 이미지 제작 방식

- 이미지 생성 도구는 **스타일 탐색, 변형안, 큰 형태의 콘셉트**에 사용할 수 있다.
- 최종 게임용 픽셀 자산은 16 PPU 격자, 제한 팔레트, 방향별 피벗, 외곽선 두께를 수작업으로 정리한다.
- 애니메이션은 프레임마다 실루엣과 발 위치가 흔들리지 않는지 확인한다.
- Claude가 임포트할 때 Point 필터, Mip Map 비활성, 무압축, 동일 PPU를 강제한다.
- 환경 이미지를 만들기 전에 타일 연결 규칙과 필요한 셀 목록을 먼저 확정해 불필요한 재생성을 피한다.

## 8. 권장 착수 순서

1. **Claude:** 환경 타일·애니메이션·데칼 아트 요청 카드 확정
2. **Codex:** 환경 타일 아트 1차 세트 제작 후 사용자 승인
3. **Claude:** 환경 아트 임포트·연결·자동 타일 구현 및 검증
4. **Codex:** 플레이어 사격 반동과 적 피격·사망 프레임 제작 후 사용자 승인
5. **Claude:** Animator·히트 스톱·방향성 카메라 킥·피격 프리셋 통합
6. **Codex:** 탄흔·잔흔 데칼 제작 후 사용자 승인
7. **Claude:** 데칼 풀링, 조명, 총알, 포스트 프로세싱 마감
8. 같은 방식으로 적별·방별 시각 언어 확장

첫 제작 배치는 **환경 타일 세트, 플레이어 사격 반동, 적 피격·사망 프레임**의 세 묶음으로 잡는다. 이 세 묶음이 현재 화면의 임시 자산 인상을 가장 크게 줄인다.

## 9. Claude 전달용 착수 지시

> 이 문서를 최우선 작업 분담 기준으로 사용한다. Unity 코드·셰이더·씬·프리팹·임포트·애니메이션·물리·조명·카메라·검증은 Claude가 담당한다. 신규 픽셀 이미지가 필요한 경우 바로 대체 이미지를 만들지 말고 §6.3 형식의 아트 요청 카드를 작성해 Codex에 전달한다. Codex가 전달한 승인 이미지만 Unity에 연결하며, 기존 Core Keeper식 굴착 환경 방향과 16 PPU·320×180 Pixel Perfect 기준을 유지한다.

구현한 Unity 작업:

- `BuildModularGunnerPrototype` 이 신규 자산을 임포트·슬라이스한다.
  시트 슬라이스는 `SpriteDataProviderFactories` + `ISpriteNameFileIdDataProvider` 를 쓴다.
- 바닥은 가중치 기반 저빈도 변형 배치, 벽 캡·정면은 변형 무작위 선택(고정 시드 `0x7A11E5`).
- 결정이 박힌 정면 변형에는 약한 보라 점광원을 붙였다.
- **벽 외곽 림** — 승인 타일에 코너·끝단 변형이 없어 덩어리가 평평한 판으로 읽혔다.
  노출된 모서리 안쪽만 어둡게 누르는 3px 림 스프라이트를 절차적으로 만들어
  캡 좌·우·상과 정면 좌·우에 붙였다. 덩어리 내부에는 넣지 않아 하나의 암반으로 읽힌다.
- `ModularGunnerDecals` — 96칸 링 버퍼 데칼 풀. 오래된 흔적부터 회수하고 수명 끝 1.4초에만 페이드한다.
- `ModularGunnerHitStop` — 20~55ms 타임스케일 정지. 카메라는 언스케일 시간을 쓴다.
- `ModularGunnerEffects` — 약/강/치명타/사망 4프리셋. 하나의 프리셋이 히트 스톱 · 셰이크 ·
  방향성 킥 · 줌 펀치 · 파편 수 · 데칼 크기를 함께 정하고, 불꽃 → 파편 → 연기 → 바닥 흔적을
  시간차로 재생한다.
- `ModularGunnerCameraRig` — `AddKick`(충돌 법선 방향), `AddZoomPunch` 추가.
  프로파일에 `kickDistance` · `kickRecovery` · `zoomPunch` · `zoomPunchRecovery` 를 넣었다.
- `ModularGunnerEnemy` — 6프레임 상태 기계. 체력 절반 아래에서 균열 프레임을 유지하고,
  사망 시 충돌·추적을 끄고 3→4→5 프레임을 55ms 간격으로 재생한 뒤 파괴된다.
  백색 플래시는 즉시 꺼지지 않고 곡선으로 복귀한다.
- `ModularGunnerController` — 발사 시 반동 프레임 2 → 1 → 0 을 35ms 간격으로 되돌린다.

| 방향 | 4변 + 외곽 4코너 + 내측 4코너 |
| 피벗 | (0.5, 0.5) 격자 중앙 |
| 연결 규칙 | 8이웃 비트마스크. 이웃이 벽인 변은 이음매 없이 이어지고, 비어 있는 변에만 암반 외곽선이 온다 |
| 팔레트 | 2026-09-16 승인 `env_wall_cap_00` 과 동일 톤(평균 휘도 ≈ 70) |
| 채널 | 컬러만 |
| 런타임 제약 | 16 PPU 타일맵 셀. 콜라이더는 셀 단위 Grid 이므로 외곽선이 셀 밖으로 나가면 안 된다 |
| 완료 기준 | 무작위 벽 덩어리를 깔았을 때 덩어리 경계가 하나의 암반 실루엣으로 읽히고, 내부에 가로 줄이 생기지 않을 것 |

**사유:** 현재는 절차적 3px 림으로 실루엣을 대신하고 있다. 기능은 하지만 균일한 직선 모서리라
콘셉트의 울퉁불퉁한 암반 외곽과 다르다.

### 11.3 선택 요청 — 데칼 톤

현재 승인 데칼은 밝은 자갈 림이 강해 어두운 벽 정면에서는 자갈만 반짝여 보인다.
런타임에서 톤을 눌러 쓰고 있으나, 어두운 표면 전용으로 **중심부 파임이 또렷한 탄흔 3종**이
추가되면 가독성이 확실히 올라간다. 급하지 않다.
