## 0. 문서의 위치

이 문서는 기존 `tunnel-crew-gdd.md`의 초기 데모 방향을 삭제하지 않고, 실제로 발전한 프로토타입과 새로 합의한 행성 원정 구조를 기준으로 **본편의 상위 구조**를 다시 정의한다.

이 문서는 대화에서 나온 아이디어를 결과만 압축한 문서가 아니라, 방향이 바뀐 이유와 아직 해결되지 않은 위험까지 보존하는 누적 기준 문서다. 문장과 표에는 다음 상태를 구분한다.

- **확정:** 현재 본편 설계의 기준으로 사용한다.
- **부분 확정:** 방향과 금지선은 정했지만 정산 방식, 수치 또는 세부 동작은 아직 결정하지 않았다.
- **검증 필요:** 설계 방향은 정했으나 현재 프로토타입의 실제 연결 상태나 플레이 감각을 확인해야 한다.
- **미결정:** 복수의 선택지가 남아 있어 추가 논의와 선택이 필요하다.
- **보류:** 지금 확정하면 다른 설계를 불필요하게 제한하므로 추후 논의한다.

기존 GDD의 다음 요소는 유지한다.

- 탑다운 2D 타일 채굴과 어둠 탐험
- 드릴러, 거너, 스카우트, 엔지니어의 4역할 협동
- 채굴, 전투, 목표 달성, 생환의 긴장
- 솔로 플레이 보조 수단
- 한 판 안에서 역할과 빌드가 체감되는 설계

다음 요소는 본편 구조에 맞게 재배치한다.

- 미션 및 바이옴 선택은 행성 선택에 흡수한다.
- 무한 모드는 본편의 기본 메뉴가 아니라 행성 원정 구조 또는 엔드게임으로 재정의한다.
- 실시간 특성 노드 구매안은 폐기한다.
- 스테이지 안에서는 3특성 카드로 성장하고, 영구 노드는 귀환 후 메인 기지에서만 성장시킨다.

### 0.1 현재 게임과 통합 기획이 필요한 이유

현재 프로젝트에는 이미 서로 강한 개별 시스템이 존재한다.

- 탑다운 타일 채굴, 시야와 어둠, 전투
- 드릴러, 스카우트, 엔지니어, 거너의 역할별 장비와 스킬
- 채취·회수·소탕 미션과 탈출
- 여러 심층을 내려가는 무한 모드
- 장악도에 따른 보스 출현과 붉은 화염룡
- 레벨업 시 제시되는 3특성 카드
- 펄프·블룸·암반 코어와 직업별 특성 노드
- 솔로 보조 드론과 LAN 코옵 기반

하지만 이 요소들은 미션 모드, 바이옴 선택, 무한 모드, 특성 트리, 보스 테스트처럼 각각 별도의 메뉴와 목적에 놓여 있었다. 플레이어가 왜 다음 판을 해야 하는지, 왜 더 깊이 내려가야 하는지, 왜 친구와 함께해야 하는지, 보스를 잡고 무엇을 향해 성장하는지 설명하는 상위 플롯이 부족했다.

행성 원정 구조는 새 게임을 덧붙이는 아이디어가 아니라, 이미 만든 시스템들을 하나의 본편 경험으로 묶는 프레임이다.

### 0.2 행성 원정 아이디어의 출발점

메인 게임을 시작하면 우주 배경에 흩어진 여러 행성을 보고 목적지를 선택한다. 행성은 스테이지이자 장기 진행 지도다. 아직 갈 수 없는 행성까지 미리 보여주어 앞으로의 플레이를 기대하게 하고, 서로 다른 테마의 행성을 통해 탐험의 설렘을 만든다.

행성을 고른 뒤 캐릭터를 선택하고, 크루가 로켓을 타고 해당 행성으로 날아가는 출격 연출을 거쳐 게임을 시작한다. 네 명은 지하를 파고 내려가며 살아남고, 마침내 행성 중심부의 고유 보스를 만나 싸운다. 보스를 쓰러뜨린 뒤 전리품을 가지고 탈출해 메인 기지로 돌아온다.

장기적으로 플레이어는 다음 목표를 가진다.

- 캐릭터별 성장을 누적하고 원하는 캐릭터를 골라 플레이한다.
- 여러 행성의 고유 광물과 희귀 유물을 수집한다.
- 성장한 플레이어들과 최고 난도 행성에 도전한다.
- 초보 친구와 함께 낮은 난도의 행성을 플레이하며 성장을 돕는다.
- 우주 지도에서 아직 남은 행성과 보스를 보며 다음 탐험을 기대한다.

### 0.3 성장 구조 논의와 변경 이유

성장은 한 판 안의 즉각적인 성장과 여러 판에 걸친 영구 성장으로 분리한다.

초기 특성 노드 기획은 스테이지 진행 중 Tab을 열고, 채굴한 펄프·블룸·암반 코어를 직접 소비해 54개 노드를 점진적으로 여는 런 전용 구조였다. 그러나 코옵 원정 중 거대한 노드 화면을 반복해서 열면 다음 문제가 발생한다.

- 채굴, 전투, 길 찾기와 동료 상태에 대한 집중이 끊긴다.
- 한 사람이 노드를 고르는 동안 다른 팀원이 기다리게 된다.
- 3특성 카드와 노드가 동시에 런 빌드를 담당해 역할이 겹친다.
- 행성 탐사보다 메뉴 체류 시간이 커져 몰입이 약해진다.

따라서 다음처럼 역할을 분리했다.

- **런 특성 또는 전술 카드:** 원정 중 경험치로 3개 중 하나를 반복 선택한다. 해당 원정에서만 유지되고 매 판 새로운 빌드를 만든다.
- **캐릭터 영구 노드:** 원정에서 광물을 확보해 살아 돌아온 뒤 메인 기지에서 성장시킨다. 캐릭터별로 누적되고 다음 원정에도 유지된다.

영구 성장은 초반에 채굴·전투·생존 수치가 좋아지는 체감을 주고, 중후반에는 새로운 카드, 스킬 변형, 프리셋과 전문 분야를 여는 수평 확장의 비중을 높이는 혼합형으로 결정했다.

### 0.4 원정 길이와 실패 구조 논의

한 행성은 여러 번의 출격으로 진척도를 쌓는 방식이 아니라, 한 번의 연속 원정에서 착륙부터 중심부 보스와 탈출까지 완료한다. 초반 행성은 보스를 빠르게 만나지만 후반 행성은 훨씬 많이 파고 내려가야 한다.

- 초반 행성: 15~20분
- 일반 행성: 25~30분
- 최고 난도 행성: 35~45분

긴 원정에서 전멸했다고 모든 장기 성장이 사라지면 새로운 행성에 도전하기 어려워진다. 반대로 모든 자원이 자동 보존되면 생환과 탈출의 의미가 약해진다. 이에 따라 일반 광물 일부는 기본적으로 보존하되, 추가 일반 광물·희귀 광물·보스 코어는 생환 가치가 더 크도록 한다.

후반부에는 영구 성장으로 일반 광물 확보율, 희귀 광물 보호, 안전 주머니와 원격 전송 능력을 강화할 수 있게 한다. 단, 이 노드가 없으면 도전 자체가 손해가 되는 필수 세금이 되지 않도록 기본 보존량을 제공한다.

### 0.5 코옵 채굴 경제에서 발견된 맹점

**상태: 핵심 원칙 확정 · 세부 정산 규칙 검토 중**

게임의 직업과 역할은 명확히 나뉘어 있다. 그런데 광물과 경험치를 오직 암반을 직접 파괴한 사람에게만 주면 드릴러가 다른 직업보다 훨씬 빠르게 성장한다. 이를 해결하기 위해 모든 광물을 단순 팀 공유하면 반대 문제가 생길 수 있다.

- 드릴러만 반복 채굴 노동을 하고 다른 직업은 같은 보상을 받는다고 느낄 수 있다.
- 다른 플레이어가 드릴러의 채굴을 기다리는 수동적인 플레이를 할 수 있다.
- 팀에 필요한 드릴러를 서로 기피해 누군가 억지로 맡는 현상이 생길 수 있다.
- 드릴러에게 추가 광물을 지급하면 재미가 아니라 효율 때문에 드릴러가 필수 선택이 된다.
- 개인 경험치에서 굴착만 주요 획득처라면 드릴러만 런 빌드가 빨라지고, 경험치를 단순 공유하면 다른 직업이 드릴러의 노동으로 성장하는 인상이 생긴다.

이 문제는 보상 배율만으로 해결할 수 없다. 드릴러가 재미없는 노동 담당이라면 추가 보상은 문제를 가릴 뿐이며, 땅굴을 파는 행위 자체와 역할별 기여 구조를 다시 설계해야 한다.

현재 확정한 원칙은 다음과 같다.

1. **모든 직업이 각자의 방식으로 굴착할 수 있다.** 어떤 직업 구성으로도 기본 진행이 가능하지만, 단단한 암반과 장거리 통로 개척에는 드릴러가 가장 유리하다.
2. **경험치는 개인별로 획득하고 성장한다.** 각자의 채굴, 탐사, 전투, 방어, 구조와 설치물 운용이 자신의 경험치에 기여하며 파티가 경험치와 레벨을 공유하지 않는다.
3. **레벨업 시점과 3특성 선택은 모두 개인별이다.** 역할과 행동에 따라 성장 속도와 선택 시점이 달라지고, 각자 독립적인 런 빌드를 만든다.
4. **영구 광물은 마지막 타격 경쟁 없이 정산한다.** 동일 지급, 팀 공용 적재 후 개인 지급, 개인 가방과 팀 보너스의 혼합 등 정확한 정산 단위는 아직 결정하지 않았다.
5. **역할별 기여를 채굴 과정에 배치한다.** 스카우트는 광맥과 위험을 먼저 찾고, 드릴러는 통로를 만들며, 엔지니어는 채굴 거점과 전송을 지원하고, 거너는 습격으로부터 작업 구역을 확보한다.
6. **일반 광맥은 간단하게, 대형·희귀 광맥은 협동 사건으로 만든다.** 모든 광맥에서 네 역할의 절차를 강요하지 않는다.

개인 경험치 문제는 새로운 공용 경험치 시스템으로 해결하지 않는다. 현재 기획과 프로토타입이 사용해 온 **직업별 역할 행동 가중치**를 유지한다. 드릴러는 굴착, 스카우트는 발견과 정찰, 거너는 전투와 구역 방어, 엔지니어는 설치물 운용과 지원처럼 자신의 역할을 잘 수행할수록 개인 경험치를 더 효율적으로 얻는다. 따라서 네 직업의 레벨업 속도가 항상 같아야 할 필요는 없지만, 정상적인 역할 수행을 한 플레이어가 보스전에 도달했을 때 빌드 완성도에서 과도하게 뒤처져서는 안 된다.

현재 역할 장비에도 이 방향의 기반이 있다. 드릴러는 고압 드릴, 거너는 파쇄 발사기, 스카우트는 휴대 절삭기, 엔지니어는 공학 커터와 전력 장비를 가진다. 모든 직업이 기본 굴착은 가능하되 드릴러가 경로 설계와 대규모 지형 파괴에서 가장 뛰어난 구조로 확정한다. 다른 직업도 굴착 관련 영구 노드와 3특성을 가질 수 있지만, 굴착 성능의 성장 폭과 최종 고점은 드릴러보다 낮게 제한한다.

드릴러의 재미는 보상 우대가 아니라 행동에서 나와야 한다. 단순히 벽 앞에서 버튼을 오래 누르는 대신 다중 타일 관통, 연쇄 균열, 과열 관리, 적과 벽의 동시 파괴, 고속 통로 생성과 보스전 지형 재구성처럼 **길을 창조하는 선봉 역할**을 강화한다.

## 1. 게임 비전

### 1.1 한 줄 정의

> 네 명의 땅굴 크루가 여러 행성에 착륙해 지하를 파고 성장하며, 행성 중심부의 고유 보스를 쓰러뜨리고 전리품을 가지고 살아 돌아오는 협동 채굴 액션 게임.

### 1.2 플레이어에게 줄 핵심 감정

1. **탐험의 설렘**<br>
   우주 지도에 펼쳐진 미지의 행성과 그 내부를 상상하고, 새로운 환경과 생명체를 발견한다.

2. **한 판 안의 성장감**<br>
   채굴과 전투로 경험치를 얻고 3개의 특성 중 하나를 반복 선택하며 이번 원정만의 빌드를 완성한다.

3. **오래 이어지는 축적감**<br>
   살아서 가져온 광물과 보스 전리품으로 캐릭터별 영구 성장 노드를 차근차근 활성화한다.

4. **협동의 필요와 보람**<br>
   각 직업이 길, 시야, 전투, 공간 제어를 담당하며 혼자보다 함께할 때 더 깊고 위험한 행성에 도전할 수 있다.

5. **발견과 수집의 기쁨**<br>
   희귀 유물, 행성 도감, 보스 전리품과 아직 잠긴 행성을 통해 다음 플레이의 기대를 만든다.

### 1.3 핵심 설계 문장

> 광물을 캐며 지금 강해지고, 살아서 광물을 가져오며 영원히 강해진다.

## 2. 본편 전체 플로우

```text
[메인 기지]
  → 캐릭터 상태·성장·유물 확인
  → [우주 지도]
  → 행성 선택 및 위험·보상 확인
  → 파티 구성
  → 캐릭터/직업 선택
  → 로켓 출격 연출
  → [행성 원정]
      탐사·채굴·전투
      → 경험치 획득
      → 3특성 선택
      → 광물·유물 수집
      → 심층 진입
      → 최종 보스
      → 탈출
  → [귀환 정산]
  → 광물·유물·보스 전리품 보관
  → [메인 기지]
  → 캐릭터 영구 노드 성장
  → 다음 행성 또는 더 높은 난도 선택
```

이 흐름에서 행성은 단순한 배경이 아니라 한 원정의 환경, 적, 광물, 특성 선택, 보스와 보상을 규정하는 **스테이지 단위**다.

## 3. 우주 지도와 행성 진행

### 3.1 우주 지도의 역할

- 아직 가지 못한 행성을 미리 보여주어 장기 목표를 만든다.
- 행성의 외형만으로 내부 환경과 보스를 상상하게 한다.
- 현재 파티의 성장 수준에 맞는 다음 도전을 제시한다.
- 친구와 함께 도전할 목표를 쉽게 공유하게 한다.
- 클리어 경로와 남은 탐험 범위를 시각적으로 보여준다.

### 3.2 행성 정보

행성 선택 시 최소한 다음 정보를 제공한다.

- 행성 이름과 대표 비주얼
- 주요 지층 또는 환경 키워드
- 권장 성장 단계 및 난도
- 예상 원정 시간
- 주요 위험 요소
- 발견 가능한 광물과 유물
- 보스 정보의 일부 또는 실루엣
- 클리어 여부와 최고 기록
- 현재 파티에서 부족한 역할에 대한 안내

보스의 전체 모습과 패턴은 첫 진입 전에 모두 공개하지 않는다. 행성 설명, 흔적, 소리, 실루엣과 지층 변화로 존재를 예고한다.

### 3.3 행성 해금

기본 구조는 이전 행성 클리어 또는 특정 보스 코어 확보로 다음 경로가 열리는 방식으로 한다. 일부 구간은 두 개 이상의 행성 중 다음 목적지를 선택할 수 있게 하여 탐험 경로의 주도권을 준다.

세부 해금 조건과 행성 분기 수는 결정이 필요하다.

## 4. 행성 원정의 기본 구조

### 4.1 원정의 기승전결

1. **착륙과 적응**<br>
   행성의 기본 환경, 주요 광물과 위험 요소를 짧게 학습한다.

2. **굴착과 빌드 형성**<br>
   경로를 선택하며 광물을 채굴하고, 경험치로 3특성을 선택해 각자의 플레이 스타일을 만든다.

3. **심층 압박**<br>
   지형과 적이 강해지고, 희귀 광물과 유물이 등장한다. 계속 전진할지 안전한 경로를 만들지 팀이 판단한다.

4. **행성 중심부 진입**<br>
   보스의 흔적과 전용 환경이 강해지고, 마지막 준비 구간을 거친다.

5. **고유 보스전**<br>
   채굴과 네 직업의 도구가 전투에서도 의미를 가지는 행성 전용 보스와 싸운다.

6. **탈출과 생환**<br>
   보스 처치만으로 원정을 완료하지 않는다. 전리품을 확보하고 정해진 방법으로 귀환해야 영구 자원 정산이 완성된다.

### 4.2 지층 구조

현재 무한 모드의 심층 이동과 절차 생성 구조를 행성 내부 진행의 기반으로 활용한다. 각 행성은 여러 지층 또는 구역으로 구성될 수 있다.

한 행성은 **한 번의 연속 원정으로 착륙부터 중심부 보스와 탈출까지 완료**한다. 여러 번의 짧은 원정으로 행성 진척도를 쌓아 보스를 해금하는 구조는 기본 캠페인에 사용하지 않는다.

지층마다 다음 중 일부가 변화한다.

- 암반 강도와 굴착 경로
- 적 구성과 밀도
- 광물 분포
- 환경 위험
- 시야 조건
- 중간 목표
- 보스의 흔적과 전조

초반 행성은 적은 수의 지층을 빠르게 통과해 보스를 일찍 만나고, 후반 행성은 더 많은 지층과 위험 구간을 지나야 중심부에 도달한다. 후반 행성의 길이는 단순히 암반 체력과 적 체력을 늘려 만들지 않고, 지층 수, 경로 판단, 중간 수호자, 환경 변화와 팀 운영의 누적으로 만든다.

### 4.3 행성 등급별 목표 시간

| 행성 단계 | 목표 원정 시간 | 경험 목표 |
|---|---:|---|
| 초반 행성 | 15~20분 | 기본 조작과 성장 루프를 익히고 비교적 빠르게 보스를 만난다. |
| 일반 행성 | 25~30분 | 런 빌드가 뚜렷해지고 여러 지층과 팀 역할을 충분히 경험한다. |
| 최고 난도 행성 | 35~45분 | 완성된 빌드, 장기 자원 관리, 역할 협동과 보스 숙련을 모두 요구한다. |

행성 길이가 달라도 보스 직전에는 각자의 런 빌드가 완성되었다는 느낌이 있어야 한다. 따라서 경험치 요구량, 레벨업 간격과 특성 등급 출현 시점은 고정된 절대 시간이 아니라 행성의 목표 길이에 맞춰 조정한다.

### 4.4 지층 구조 구현 상태 (트랙 C 분기)

**상태: 유한 지층 구조 구현 · 지층 수·스케일 곡선은 튜닝 대상**

무한 하강 런타임을 **유한한 지층 → 중심부 → (선택) 이상지대** 구조로 전환했다. 첫 행성 정의 `INF_PLANET`(퍼플 땅굴, §10의 첫 행성 후보)이 지층 수·지층별 배율·전조 문구·목표 시간을 한곳에 담고, 트랙 B의 예약 지점 `INF_BOSS_TIER.finalDepth`가 이 정의에 연결되었다.

| 구간 | 구성 | 벽 내구도 | 적 체력 | 출현자 |
|---|---|---:|---:|---|
| 지층 1/3 · 표층 지대 | 착륙·적응 | ×1.0 | ×1.0 | 심층 수호자 |
| 지층 2/3 · 균열 지대 | 굴착·빌드 형성 | ×1.35 | ×1.4 | 심층 수호자 |
| 지층 3/3 · 중심부 | 중심부 보스전 | ×1.8 | ×1.9 | 암반 포식자 → 처치 시 탈출 포트 자동 요청 |
| 이상지대 N (엔드게임) | 선택 하강 | ×1.8×1.6ⁿ | ×1.9×1.55ⁿ | 변종 포식자 |

설계 근거:

- 기존 벽 내구도 2ⁿ 지수 곡선은 무한 스케일용이었고, 15~20분 3지층 원정에는 과했다. §4.2의 "길이는 암반 체력 뻥튀기로 만들지 않는다"에 따라 캠페인 구간은 완만한 지층별 배율로 바꾸고, 지수 성장은 이상지대에만 남겼다.
- 배율 계산은 `infInitFloor` 한 곳으로 통일했다(기존에는 하강 코드와 중복 계산).
- 지층 진입마다 이름과 전조 문구를 표시한다(§4.2 "보스의 흔적과 전조", §3.2 예고 원칙). HUD·휴식 화면 제목도 `지층 N/3 · 이름` 표기를 쓴다.
- 중심부 보스 처치 후의 하강 버튼은 `심층 이상지대로 (엔드게임)`으로 명시해, 기본 캠페인의 완결(탈출)과 선택적 엔드게임(§13)을 화면에서 구분한다. 이상지대는 §17.3-6(무한 모드의 최종 위치)의 후보 구현이며 결정 자체는 열려 있다.

튜닝·후속 대상: 지층 수 3의 실측 원정 시간(§17.4-5), 지층별 배율 수치, 지층별 광물 분포·환경 위험 차별화(현재는 배율·전조만), 행성 여러 개로의 확장(INF_PLANET 을 배열로).

## 5. 스테이지 내부 성장 — 3특성 선택

### 5.1 목적

스테이지 내부 성장은 매 원정의 플레이 스타일을 새롭게 만들고, 원정이 진행될수록 눈에 띄게 강해지는 로그라이크 성장이다.

### 5.2 기본 규칙

- 경험치는 파티가 공유하지 않으며, 각 플레이어가 자신의 채굴, 전투, 탐사, 지원과 목표 행동으로 획득한다.
- 각자의 경험치에 따라 서로 다른 시점에 레벨업하고, 무작위 또는 규칙 기반으로 제시된 3개 특성 중 하나를 고른다.
- 직업별 역할 행동에는 기존 방식처럼 서로 다른 경험치 가중치를 적용한다.
- 선택한 특성은 해당 원정에서만 유지한다.
- 여러 특성의 조합으로 직업별 빌드를 형성한다.
- 원정 종료 후 모든 런 특성은 초기화한다.

### 5.3 직업별 개인 경험치 원칙

**상태: 설계 원칙 확정 · 구현 연결 완료(v7.1.8) · 수치 밸런스 검증 필요**

개인 경험치는 모든 플레이어를 같은 속도로 맞추는 장치가 아니라, 각자가 맡은 역할을 적극적으로 수행할 때 자신의 런 빌드가 성장하도록 만드는 피드백이다. 기존에 사용하던 역할별 경험치 가중치 구조를 본편에서도 유지하며, 별도의 팀 경험치나 동시 레벨업 규칙을 추가하지 않는다.

| 직업 | 높은 비중으로 인정할 역할 행동 | 굴착 경험치의 위치 |
|---|---|---|
| 드릴러 | 암반 파괴, 기반암 돌파, 대형 통로 개척, 균열·연쇄 파괴 | 네 직업 중 가장 높은 효율과 성장 고점을 가진다. |
| 스카우트 | 신규 구역 발견, 광맥·위험 탐지, 선행 정찰과 표식 | 기본 굴착은 가능하지만 정찰보다 주력 성장 수단이 되지는 않는다. |
| 엔지니어 | 설치물 배치·가동, 채굴 거점 유지, 방어·운반·전송 지원 | 공학 장비로 보조 굴착하되 굴착 계열의 고점은 드릴러보다 낮다. |
| 거너 | 적 처치·피해·제압, 습격 방어, 위험 구역 확보 | 파쇄 장비로 보조 굴착하되 전투보다 효율적인 성장 수단이 되지 않는다. |

공통 목표 달성, 동료 구조와 생환 기여는 어느 직업에도 의미 있는 경험치를 줄 수 있다. 다만 반복 설치·철거, 안전한 적 무한 생성, 이미 확인한 구역 재탐색처럼 경험치를 인위적으로 반복 생산하는 행동은 제한한다.

현재 프로토타입에서 확인되는 굴착 재질별 경험치, 드릴러의 기반암 돌파 경험치, 스카우트의 신규 구역 탐사 경험치와 경험치 배율 특성은 이 원칙의 기반으로 유지한다.

#### 5.3.1 구현된 획득처와 가중치

이전 빌드의 경험치 획득처는 굴착과 신규 구역 탐사뿐이었다. 그래서 거너와 엔지니어는 자기 역할을 정상 수행해도 런 빌드가 자라지 않았고, 완성되어 있던 직업별 특성 카드 16장이 사실상 사용되지 않았다. 이는 설계 미결정이 아니라 누락된 연결선이었으므로 다음과 같이 구현했다.

모든 개인 경험치는 단일 관문 `infAwardXp(base, kind, opts)` 하나만 통과한다. 획득처를 추가해도 가중치, 상한, 기록이 한곳에서 유지된다.

| 행동 분류 | 구현된 획득처 | 기본값 |
|---|---|---|
| `dig` 굴착 | 일반 블록 파괴, 드릴러 기반암·코어 암반 돌파 | 흙 1 · 암 2 · 광맥 4 · 균열 8 · 코어 균열 12 |
| `combat` 전투 | 적 처치(엘리트 ×1.7, 에이펙스 ×2.4), 보스 격파 | 처치 4 · 보스 45 |
| `support` 지원 | 센트리 처치, 전력망 가동 유지 시간 | 센트리 처치 5 · 전력망 6초당 2 |
| `recon` 정찰 | 스카우트 신규 구역 탐사 | `scoutExploreXp` (기본 2) |
| `objective` 목표 | 예약 — 중간 목표·동료 구조·생환 기여 | 미구현 |

직업별 가중치는 다음과 같다. 표에 없는 직업은 1로 취급하므로 직업을 추가해도 관문이 깨지지 않는다.

| 행동 분류 | 드릴러 | 거너 | 스카우트 | 엔지니어 |
|---|---:|---:|---:|---:|
| 굴착 | 1.00 | 0.70 | 0.80 | 0.80 |
| 전투 | 0.65 | 1.00 | 0.85 | 0.80 |
| 지원 | 0.60 | 0.75 | 0.75 | 1.00 |
| 정찰 | 0.65 | 0.75 | 1.00 | 0.80 |
| 목표 | 1.00 | 1.00 | 1.00 | 1.00 |

이 수치는 기획 확정값이 아니라 **검증을 시작하기 위한 초기값**이다. 드릴러의 굴착 가중치만 1.00으로 두어 기존 감각을 유지했고, 나머지 직업은 굴착 비중을 낮추는 대신 자기 역할 분류에서 1.00을 갖는다.

#### 5.3.2 인위적 반복 생산 제한

지원 경험치는 반복 설치·철거로 양산될 위험이 있으므로 다음 규칙을 적용했다.

- 설치 행위 자체에는 경험치를 주지 않는다. **전력망을 실제로 유지·가동한 시간**에 지급한다.
- 전력 노드에 연결된 센트리만 인정한다. 플레이어가 옆에 서서 임시 급전하는 것으로는 쌓이지 않는다.
- 시간만 흘려 얻는 트리클 경험치는 지층당 상한(기본 60)을 둔다. 상한은 지층 진입마다 회복한다.
- 실제 처치와 굴착처럼 위험을 감수한 행동은 이 상한에 걸리지 않는다.

#### 5.3.3 검증 계측

런 종료 화면에 **역할 행동별 경험치 내역**을 표시한다. 예: `굴착 48 (54%) · 전투 9 (10%) · 지원 32 (36%)`. §17.4-2의 역할별 성장 속도 검증을 감각이 아니라 수치로 수행하기 위한 계측이다.

보스전과 레벨업 모달 중에는 카드 선택 창을 열지 않고 경험치만 적립하며, 구간이 끝나면 밀린 레벨업을 반드시 연다.

### 5.4 설계 원칙

- 단순 수치 증가와 행동 변형을 적절히 섞는다.
- 같은 직업도 원정마다 다른 빌드를 만들 수 있어야 한다.
- 팀원의 빌드를 보고 서로 보완할 수 있어야 한다.
- 직업별 역할 행동이 개인 경험치 획득 기회로 공정하게 연결되어야 하며, 드릴러의 굴착만 가장 효율적인 성장 수단이 되어서는 안 된다.
- 선택 화면이 전투와 협동을 과도하게 중단하지 않아야 한다.
- 영구 노드에서 새 카드나 카드 계열을 해금할 수 있다.
- 행성 환경에 대응하는 상황형 특성을 일부 제공할 수 있다.

### 5.5 명칭

영구 특성 노드와 혼동을 막기 위해 스테이지 내부 선택은 문서와 UI에서 우선 **런 특성** 또는 **전술 카드**로 부른다. 최종 명칭은 추후 확정한다.

### 5.6 카드 획득 속도·선택 규칙 구현 상태 (트랙 D 분기)

**상태: 곡선·리롤·선택 UI 구현 · 수치는 실플레이 튜닝 대상**

실측에서 두 가지 부정합이 드러났다. (1) 지층당 개인 경험치는 수천 단위인데 기존 레벨 곡선(10+5.5L)은 무한 그라인드용이라 유한 행성에서 한 지층 만에 레벨 25를 만든다. (2) 지층 길이를 실질 지배하는 것은 장악도 목표였고, 전역 40%는 지층당 10분 이상을 만들어 §4.3의 15~20분 원정과 맞지 않았다.

구현한 규칙(상수는 모두 `INF_CARDS`와 `INF_PLANET` 에 있음):

| 항목 | 규칙 | 초기값 |
|---|---|---|
| 레벨 곡선 | `xpNeed = 30 + 10L + 8L²` — 첫 카드는 빠르게(48 XP), 후반은 가파르게 | 중심부 목표 레벨 10 |
| 장악 목표 | 전역 40% → 행성 지층 정의로 이관 | 지층별 22 / 26 / 30% · 이상지대 34% |
| 등급 출현 | 절대 레벨이 아니라 **행성 목표 레벨 대비 진행도**로 가중치 계산 (§4.3) | 진행도 1.0에서 1~4등급 = 28/28/24/10 |
| 리롤 | 지층 진입마다 +1 회복, 최대 2 보유. §6.3 영구 노드(리롤·선택 보정)가 확장할 기반 | 시작 1회 |
| 중복 | 한 손패 안 중복 없음(기존 유지) · 획득 상한은 특성별 `ok()` 조건(기존 유지) | — |
| 키보드 선택 | 카드 모달에서 1·2·3 키로 즉시 선택 — 전투 중 마우스 이동 부담 완화 (§17.4-6) | — |
| 풀 소진 대체 | 카드 풀(직업당 8종)이 바닥나면 빈 모달 대신 예비 보급(체력 +25%·코어 +1)으로 대체 | — |

풀 소진 대체는 버그 수정을 겸한다 — 기존 코드는 풀이 비면 **카드 0장 모달이 열려 닫을 방법이 없는 소프트락**이었다.

시뮬레이션 검증(퍼플 땅굴, 드릴러 가중, 굴착+전투 혼합 추정): 지층 종료 시점 레벨 6 → 9 → 10. 중심부 보스 직전에 목표 레벨에 수렴한다. 남은 것은 실플레이 검증이다 — 추정에는 실제 이동·전투 시간과 회피 굴착 비율이 빠져 있다(§17.4-2·5와 함께 플레이테스트).

선택 중 게임 정지(§17.1-3의 미결정 항목): 솔로 런타임은 모달 중 전체 정지를 유지한다. 코옵의 비정지 처리(자동 방어·슬로 모션·선택 대기열)는 F 트랙과 함께 결정한다 — **미결정 유지**.

## 6. 메인 기지 영구 성장 — 캐릭터 노드

### 6.1 목적

영구 성장 노드는 반복 플레이의 축적을 보여주고, 좋아하는 캐릭터를 오래 플레이할 이유와 새로운 빌드를 발견할 이유를 만든다.

### 6.2 기본 규칙

- 영구 노드는 스테이지 안에서 성장시키지 않는다.
- 원정에서 획득하고 생환한 광물과 보스 재료를 메인 기지에서 소비한다.
- 캐릭터는 각자 별도의 성장 노드를 가진다.
- 활성화한 노드는 이후 원정에도 유지된다.
- 노드 구매와 빌드 검토는 출격 전 또는 귀환 후에만 한다.
- v7.3.0의 캐릭터별 8노드와 기지 보관 코어 소비 구조는 저장·정산·효과 적용을 검증한 **기능 기반**으로만 유지한다. 대형 설명 카드 8개를 나열하는 현재 화면은 최종 UX로 사용하지 않는다.
- 성장 지도에 처음 진입하면 캐릭터 문장 주변의 시작 노드 **4개만** 실제 화면에 만든다. 캐릭터 문장은 구매 노드 수에 포함하지 않는다.
- 먼 노드는 딤드 실루엣, 자물쇠, 이름, 연결선으로도 예고하지 않는다. 미발견 노드와 미발견 연결선은 DOM·캔버스 히트 영역·접근성 트리에도 만들지 않는다.
- 발견된 노드의 첫 랭크를 활성화하면 이어진 근거리 노드 1~3개와 연결선이 그때 처음 나타난다. 발견 상태는 해당 캐릭터의 랭크 데이터에서 다시 계산해 다음 접속에도 유지한다.
- 코어는 현재 공용 재화로 유지하되, 보스 재료 등 추가 재화가 도입되어도 지도 상단의 자원 스트립을 확장하는 방식으로 수용한다.

### 6.3 영구 노드가 담당할 효과

- 새로운 런 특성 카드 또는 카드 계열 해금
- 직업 스킬의 선택 가능한 작동 방식 해금
- 시작 장비 및 시작 프리셋 확장
- 리롤, 선택 보정과 빌드 탐색 편의
- 운반, 구조, 생존과 역할 수행의 기초 능력
- 실패 시 일반 광물 확보율 증가
- 희귀 광물 일부 보존 확률 또는 최소 보존량 확보
- 안전 주머니, 원격 전송과 전리품 회수 기능 강화
- 전문 분야와 캡스톤 접근 권한
- 캐릭터 외형, 칭호와 숙련 표현

현재 구현된 역할 장비 위력, 최대 체력, 탄창, 역할 행동 경험치와 그 상위 4종 효과는 새 지도의 초기 데이터와 저장 마이그레이션 재료로 사용한다. 8개 구성과 비용은 전체 영구 트리의 확정안이 아니다.

### 6.4 혼합형 성장 원칙

영구 성장은 수치 성장과 수평 성장을 함께 사용하는 **혼합형**으로 확정한다.

- 초반: 공격, 생존, 채굴과 회수 효율이 눈에 띄게 좋아져 성장 자체를 빠르게 체감한다.
- 중반: 새로운 런 특성 카드, 스킬 변형, 장비 프리셋과 전문 분야를 연다.
- 후반: 단순 수치 누적보다 빌드 선택 폭, 고난도 대응, 자원 보존과 숙련 표현의 비중을 높인다.

수치 성장만으로 고난도 행성을 통과하지 못하게 하고, 역할 숙련, 팀 구성, 런 빌드와 보스 패턴 이해가 계속 중요하게 남아야 한다. 정확한 수치 성장 상한과 수평 성장 비중은 영구 노드 세부 문서에서 결정한다.

기존 프로토타입의 트위닝·회전·색 변화·파편 VFX는 재사용하되, 모든 구매에 같은 강도의 패널 셰이크를 적용하지 않는다. 반복 랭크 강화, 첫 활성화와 새 경로 발견, 캡스톤 해금의 피드백 강도를 분리한다.

#### 6.4.1 화면 구조 — 전체화면 성장 지도

[Keep on Mining의 공식 스토어 이미지와 영상](https://store.steampowered.com/app/3769130/Keep_on_Mining/)에서 확인한 **넓은 트리 캔버스, 작은 아이콘 노드, 직교 연결선, 호버 상세 정보와 지역 단위 진행감**을 화면 문법의 기준으로 삼는다. 단, 멀리 있는 잠금 노드를 미리 보여 주는 방식과 구매 가능 여부를 호버로만 확인하게 하는 약점은 따르지 않는다.

- 귀환 정산 화면은 획득·보존·소실 자원만 요약하고, `성장 지도 열기`로 별도 전체화면에 진입한다. 정산 카드 사이에 노드 트리를 끼워 넣지 않는다.
- 지도는 화면 대부분을 차지하는 이동 가능한 캔버스다. 상단에는 캐릭터 전환, 현재 보관 자원과 닫기 버튼만 작게 둔다.
- 중앙의 캐릭터 문장에서 네 갈래가 시작되지만 완전한 대칭 방사형은 피한다. 발견된 영역은 금속 회로·광맥처럼 꺾이는 직교 연결선과 조밀한 비대칭 군집으로 구성한다.
- 노드는 44~56px 정사각 아이콘을 기본으로 하며 이름과 긴 설명을 상시 노출하지 않는다. 노드 밀도는 아이콘과 연결 관계를 한눈에 읽을 수 있는 수준을 우선한다.
- 배경은 어두운 암반·청사진 계열로 낮추고 활성 경로는 금색 또는 캐릭터 직업색으로 밝힌다. 장식이 연결선과 노드 상태보다 먼저 보이면 안 된다.
- 제작 목표는 캐릭터당 24~32개지만, 다음 수직 슬라이스는 **12개(초기 4 + 중간 6 + 캡스톤 2)**로 세 번의 발견 단계를 먼저 검증한다. 이후 실제 콘텐츠 생산량과 성장 기간에 따라 총량을 확정한다.

#### 6.4.2 분기와 랭크 구조

| 분기 | 담당 경험 | 대표 효과 |
|---|---|---|
| 역할 장비 | 직업의 주 행동과 전투·채굴 고점 | 위력, 범위, 과열·탄약 운용, 작동 방식 변형 |
| 생존·기동 | 위험을 견디고 위치를 바꾸는 능력 | 체력, 보호막, 이동, 구조 보조 |
| 운반·회수 | 전리품을 가지고 살아 돌아오는 능력 | 적재, 안전 주머니, 원격 전송, 실패 보존 |
| 전술 선택 | 다음 원정의 빌드 폭 | 카드 계열, 리롤, 시작 프리셋, 전문 분야 |

- 일반 노드는 최대 3랭크다. 1랭크는 효과를 활성화하고 다음 경로를 발견하며, 2~3랭크는 같은 정체성을 심화한다.
- 행동 변형, 전문 분야와 캡스톤은 원칙적으로 1랭크다. 단순 수치 3랭크를 통과해야만 새 플레이 방식에 접근하는 긴 세금 구간을 만들지 않는다.
- 다음 경로는 첫 랭크 구매 시 열린다. 최대 랭크 달성을 발견 조건으로 사용하지 않는다.
- 네 직업이 같은 분기 이름을 공유해도 효과와 아이콘은 직업 판타지에 맞게 다르게 만든다. 굴착 성능의 최종 고점은 §0.5 원칙대로 드릴러가 가장 높다.

#### 6.4.3 발견과 연결 규칙

1. 첫 진입 시 시작 노드 4개와 그 노드에서 캐릭터 문장으로 이어지는 짧은 연결선만 보인다.
2. 보이는 노드의 첫 랭크를 구매하면 해당 노드가 먼저 활성화된다.
3. 활성 노드에서 바깥으로 연결선이 그려진 뒤, 연결된 신규 노드 1~3개가 70ms 간격으로 출현한다.
4. 신규 노드는 발견 즉시 선택할 수 있지만 선행 조건과 비용을 만족해야 구매할 수 있다.
5. 아직 발견하지 않은 노드·선·이름·비용·아이콘은 어떤 확대 배율에서도 보이지 않는다.
6. 가지 끝의 방향감은 빈 노드 실루엣 대신 배경 광맥, 미세한 분진 흐름과 열린 여백으로만 암시한다.

하나의 구매가 너무 많은 노드를 동시에 드러내지 않도록 기본 공개량은 1~3개로 제한한다. 동일 부모에서 여러 노드가 열리면 가까운 것부터 순차 출현하며, 교차 연결은 양쪽 노드가 모두 발견된 뒤에만 표시한다.

#### 6.4.4 노드 상태와 상세 정보

| 상태 | 화면 표현 | 입력 결과 |
|---|---|---|
| 미발견 | 화면·DOM·히트 영역에 없음 | 선택 불가 |
| 발견·선행 미충족 | 어두운 자주색 금속 프레임, 끊긴 전류 | 선행 조건 안내 |
| 발견·자원 부족 | 저채도 프레임, 비용 숫자 적색 | 부족 재화 안내 |
| 구매 가능 | 금색/청록 외곽 링이 느리게 호흡, 연결선 끝에 미세한 흐름 | 즉시 구매 가능 |
| 보유·강화 가능 | 활성 프레임과 채워진 랭크 핍, 다음 랭크 비용 표시 | 다음 랭크 구매 |
| 최대 랭크 | 직업색 코어 광원, 모든 랭크 핍 점등 | 효과 확인 |
| 신규 발견 | 외곽 발견 헤일로와 작은 `NEW` 표식 | 한 번 상세 확인 후 해제 |

`구매 가능` 상태는 호버하지 않아도 구분되어야 한다. 이는 레퍼런스에서 모든 노드를 일일이 가리켜 비용을 확인해야 하는 불편을 보완하는 필수 규칙이다.

노드 상세는 커서·포커스 옆의 툴팁으로 제공하며 화면 경계에 맞춰 방향을 자동 전환한다. 툴팁에는 이름, 분기·종류, 현재 효과, 다음 랭크 수치, 비용과 자원 아이콘, `랭크 n/최대`, 선행 조건을 순서대로 표시한다. 첫 랭크 구매로 새 길이 열리는 노드는 구체적인 미래 노드 이름을 누설하지 않고 `새 경로 발견`만 알린다.

#### 6.4.5 구매·발견 연출 시퀀스

| 시간 | 반복 랭크 강화 | 첫 활성화·새 경로 발견 |
|---|---|---|
| 0~80ms | 입력 압축, 자원 숫자 선차감 | 동일 |
| 80~220ms | 아이콘 반동 트위닝, 흰색→금색 플래시 | 동일하되 반동 15% 강화 |
| 150~450ms | 자원 파편이 노드로 흡수, 프레임 색 전환, 랭크 핍 점등 | 충격파와 직업색 VFX 추가 |
| 220~650ms | 종료 | 부모에서 바깥으로 연결선 드로잉 |
| 380~850ms | 없음 | 신규 노드가 70ms 간격으로 회전·스케일 업하며 출현 |
| 450~900ms | 없음 | 새 군집을 향해 짧은 카메라 이즈, 국소 미세 셰이크 후 조작권 반환 |

- 반복 랭크 강화는 450ms 안에 끝내고 카메라를 움직이거나 화면 전체를 흔들지 않는다.
- 첫 활성화는 `노드 강화`와 `새 경로 발견`이 한 번의 연속 동작으로 읽혀야 한다. 연결선이 완성되기 전에 자식 노드가 먼저 나타나지 않는다.
- 캡스톤은 900~1,200ms로 확장해 화면 가장자리 광맥 점등, 한 번의 저주파 셰이크와 전용 VFX를 허용한다. 흰색 풀스크린 플래시는 사용하지 않는다.
- 사운드는 금속 입력음 → 자원 흡수음 → 랭크 확정 차임 순으로 겹친다. 새 경로에는 낮은 암반 울림과 높은 발견음을 추가하고 캡스톤은 전용 확정음을 쓴다.
- 자원 차감과 저장 성공은 연출보다 먼저 확정하고, 연속 입력은 시퀀스 종료까지 잠근다. 저장 실패 시 활성 연출을 재생하지 않는다.

#### 6.4.6 카메라·입력·접근성

- 마우스 드래그로 이동하고 휠로 확대·축소한다. 최소 배율에서도 미발견 영역을 드러내지 않으며, 발견 영역과 적정 여백 안에서만 카메라를 이동시킨다.
- 새 경로 발견 때만 짧게 자동 초점을 이동한다. 플레이어가 이미 드래그 입력을 시작했거나 2개 이상을 연속 구매한 경우 자동 이동을 취소한다.
- 캐릭터별 마지막 카메라 위치와 확대 배율을 기억한다. 정산 직후 처음 열 때와 `중앙으로` 버튼을 눌렀을 때만 캐릭터 문장으로 재정렬한다.
- 키보드는 방향키/WASD 이동, `+`·`-` 확대, Tab 포커스 이동, Enter 구매, Esc 닫기를 기본안으로 둔다. 게임패드 포커스 이동은 노드의 화면상 최근접 방향을 기준으로 한다.
- `모션 감소`에서는 회전, 셰이크와 자동 카메라 이동을 끄고 120ms 이내의 불투명도·색 전환만 사용한다. 툴팁 모션도 끌 수 있다.
- 색만으로 상태를 구분하지 않는다. 프레임 형태, 랭크 핍, 연결선 패턴과 `NEW` 표식을 함께 사용한다.

#### 6.4.7 데이터·마이그레이션·완료 조건

노드 데이터는 최소한 `id`, `role`, `branch`, `x`, `y`, `type`, `maxRank`, `costByRank`, `requires`, `reveal`, `effectByRank`, `icon`을 가진다. 화면 좌표와 공개 관계를 분리해, 위치를 바꿔도 저장 데이터가 깨지지 않게 한다.

v7.3.0의 `INF_META.permanentNodes[role]` 배열은 `permanentRanks[role][nodeId] = rank` 형태로 마이그레이션한다. 기존에 구매한 노드는 대응 노드의 1랭크로 자동 전환하고 효과와 소비 재화를 회수하지 않는다. 알 수 없는 옛 노드 ID는 삭제하지 않고 마이그레이션 로그에 남긴 뒤 무시한다.

다음 수직 슬라이스는 아래 조건을 모두 만족해야 완료로 본다.

- 새 캐릭터의 첫 화면에 구매 노드가 정확히 4개만 존재한다.
- 미발견 노드와 연결선이 DOM, 캔버스 히트 영역과 접근성 트리에 존재하지 않는다.
- 첫 랭크 구매 후 지정된 연결선과 인접 노드만 순서대로 발견된다.
- 반복 랭크 강화에서는 카메라 이동과 전체 패널 셰이크가 발생하지 않는다.
- 구매 가능한 노드를 툴팁 없이 식별할 수 있다.
- 툴팁이 화면 밖으로 나가거나 선택한 노드를 완전히 가리지 않는다.
- 캐릭터를 바꿨다가 돌아왔을 때 각 캐릭터의 발견 상태와 카메라 위치가 복원된다.
- 기존 8노드 저장은 손실 없이 1랭크 데이터로 변환된다.
- 모션 감소에서 회전·셰이크·자동 초점이 사라지고 기능 상태는 동일하다.
- 1280×720에서도 아이콘, 비용, 랭크와 닫기 동작을 읽을 수 있다.

### 6.5 기존 특성 노드 기획의 변경

기존 `tunnel-crew-trait-node-system.md`의 다음 항목은 폐기 또는 재설계 대상으로 본다.

- Tab 키로 스테이지 진행 중 언제든 노드 창 열기
- 런 안에서 펄프·블룸·암반 코어를 직접 소비해 노드 구매
- 원정마다 노드 트리 초기화
- 코옵 중 개인 노드 구매를 위해 플레이를 중단하는 흐름

다음 자산은 영구 노드 설계에 재활용할 수 있다.

- 공용 영역과 직업별 전문 분야의 구분
- 인접 노드의 점진 공개
- 행동 변형 중심의 노드 설계
- 여러 경로와 캡스톤 구조
- 드릴러, 거너, 스카우트, 엔지니어별 노드 아이디어와 아이콘

기존 54노드 규모를 그대로 유지할지는 별도 검토가 필요하다. 영구 시스템은 한 런이 아니라 장기간 사용하므로 비용, 공개 속도, 초기화와 캐릭터별 격차를 새로 설계해야 한다.

#### 6.5.1 폐기 실행 상태 (v7.2.0)

폐기 결정 이후에도 런타임에는 두 개의 런 중 노드 구매 화면이 남아 있었다. 보스 처치 휴식 화면의 **코어 브랜치 4계통**(굴진·탄도·동력·장악, 코어 소비)과 **드릴러 특성 트리**(보스마다 지급되는 특성 포인트 소비)다. 이 상태로 플레이테스트를 계속하면 폐기된 설계의 감각을 측정하게 되므로 v7.2.0에서 다음과 같이 제거했다.

- 두 트리의 구매 UI와 특성 포인트 지급을 제거했다. 휴식 화면에는 레전드 카드 선택(런 성장, 유지 대상)과 하강·탈출 선택만 남는다.
- **코어는 소비 재화에서 운반 전리품으로 전환했다.** 런 중에는 쓸 곳이 없고, 탈출 포트로 생환해야 기지에 보관(`INF_META.bankedCores`)되며 쓰러지면 잃는다. §8.2의 확정 원칙(보스 코어는 생환해야 획득)이 이것으로 처음 런타임에 구현되었다.
- 결과 화면은 생환 시 `확보 코어`, 사망 시 `소실 코어`를 표시하고, 메인 메뉴 기록에 누적 보관 코어를 노출한다. 보관 코어는 3순위 작업(캐릭터 영구 노드 소형 프로토타입)의 소비 재화 후보다.
- 두 트리의 노드 데이터(`INF_BRANCHES`, `INF_DRILLER_TREE`)와 효과 함수는 삭제하지 않고 영구 노드 프로토타입의 재료로 코드에 예약해 두었다. 위의 재활용 자산 목록과 같은 취지다.

## 7. 자원과 보상 구조

### 7.1 성장 자원의 구분

| 자원 | 획득 | 사용 | 유지 |
|---|---|---|---|
| 경험치 | 개인별 채굴·전투·탐사·지원·목표 행동 | 스테이지 내부 개인 레벨업 | 원정 종료 시 초기화 |
| 일반 광물 | 채굴 | 영구 노드의 기초 성장 | 생환 정산 후 보관 |
| 행성 희귀 광물 | 특수 광맥·심층 탐사 | 상위 노드·전문 분야 | 생환 정산 후 보관 |
| 보스 코어 | 고유 보스 | 캡스톤·행성 해금·핵심 제작 | 생환 정산 후 보관 |
| 유물 | 비밀 구역·희귀 사건 | 컬렉션·특수 해금 | 영구 보관 |

기존 펄프, 블룸, 암반 코어 명칭은 새 구조에서 각각 일반 광물, 희귀 광물, 보스 또는 심층 재료의 위치로 재배정할 수 있다. 명칭과 정확한 획득처는 추후 확정한다.

### 7.2 채굴 보상의 이중 역할

채굴은 동시에 두 가지 보상을 준다.

- 즉시 보상: 경험치를 얻어 이번 원정에서 강해진다.
- 장기 보상: 광물을 가방에 담아 귀환 후 영구 성장한다.

이 구조를 통해 목표로 향하는 최단 경로와 희귀 광맥을 찾아 우회하는 경로 사이에 선택을 만든다.

### 7.3 코옵 분배 원칙

- 마지막 타격 경쟁을 만들지 않는다.
- 핵심 광물과 보스 코어는 모든 참여자가 의미 있는 보상을 받는다.
- 직접 채굴자의 역할과 기여감은 별도의 소량 보너스 또는 통계로 표현할 수 있다.
- 한 플레이어의 독점이나 고의적인 자원 가로채기를 막는다.
- 광맥을 누가 마지막으로 타격했는지는 영구 광물의 소유권과 정산량을 결정하지 않는다.

개인 가방, 팀 공용 적재함 또는 혼합 방식 중 무엇을 사용할지는 결정이 필요하다.

### 7.4 코옵 채굴 보상 설계 상태

**핵심 원칙 확정 · 세부 정산 방식 검토 중:** 모든 광물의 단순 동일 지급만으로는 충분하지 않다. 드릴러에게 채굴 노동이 집중된 채 보상만 같아지면 역할 기피를 만들 수 있기 때문이다.

확정된 구조:

- 모든 직업이 각자의 장비와 방식으로 굴착하고 노출된 광맥을 채취할 수 있다.
- 드릴러는 광물 소유권이 아니라 기본 굴착 성능, 지형 개척 속도, 성장 폭과 최종 고점에서 우위를 가진다.
- 경험치는 개인별로 쌓이며 파티원 사이에 공유하지 않는다.
- 각 플레이어는 서로 다른 시점에 레벨업하고 각자 3특성 중 하나를 선택한다.
- 다른 직업도 굴착 노드와 3특성을 선택할 수 있지만 굴착 계열의 성장 폭과 고점은 드릴러보다 낮다.
- 영구 광물은 마지막 타격자에게 귀속하지 않는다.

아직 미결정인 것은 영구 광물을 개인 가방, 팀 공용 적재함, 전원 동일 지급 또는 혼합 방식 중 어떤 단위로 정산할지다. 개인 경험치의 귀속과 영구 광물의 정산은 서로 다른 문제로 취급한다.

검증 또는 추가 논의가 필요한 구조:

- 역할 행동은 영구 광물 차등 지급보다 직업 숙련도, 기록, 외형 또는 별도 피드백으로 인정하는 방안을 검토한다.

플레이테스트로 검증할 질문:

- 다른 직업도 광맥을 직접 캐는 순간적인 손맛이 충분한가?
- 드릴러가 없을 때 느리지만 정상적으로 원정을 진행할 수 있는가?
- 드릴러가 있을 때 노동 부담보다 길을 창조하는 재미가 더 크게 느껴지는가?
- 거너의 전투, 스카우트의 발견, 엔지니어의 지원이 팀 성장에 기여한다고 명확히 보이는가?
- 기존 직업별 경험치 가중치가 비전투·비굴착 역할에도 충분한 성장 속도를 제공하는가?
- 동일 보상이 무임승차가 아니라 공동 성과로 받아들여지는가?

## 8. 귀환, 실패와 전리품 보존

### 8.1 귀환의 의미

보스를 처치하거나 목표를 달성한 뒤 살아서 귀환해야 원정에서 확보한 장기 성장 자원이 메인 기지에 정식 보관된다. 귀환은 단순한 결과 버튼이 아니라 한 판의 마지막 긴장 구간이다.

### 8.2 실패 시 기본 방향

실패해도 모든 진행을 완전히 잃게 하지는 않되, 성공적인 생환에는 분명한 가치가 있어야 한다.

기본 방향은 다음과 같이 확정한다.

- 경험치와 런 특성은 성공·실패와 관계없이 초기화한다.
- 일반 광물은 기본 확보율에 따라 일부를 자동 보존한다.
- 가방의 추가 일반 광물은 생환해야 완전히 보존한다.
- 희귀 광물은 기본적으로 생환해야 보존하지만, 영구 노드에 따라 일정량 또는 일정 확률로 보호할 수 있다.
- 보스 코어는 보스 처치 후 탈출에 성공해야 획득한다.
- 영구 노드로 일반 광물 확보율, 희귀 광물 보호, 안전 주머니와 중간 전송 능력을 강화할 수 있다.

정확한 손실 비율은 플레이어가 어려운 행성을 시도하는 것을 포기하지 않도록 조정한다.

### 8.3 광물 회수·보존 노드 원칙

회수 관련 노드는 게임 후반부의 실패 부담을 낮추고 더 어려운 행성을 시도하게 만드는 영구 성장 카테고리다.

검토 효과:

- 실패 시 일반 광물 기본 확보율 증가
- 희귀 광물 최소 보존량 또는 보존 확률 증가
- 안전 주머니 슬롯 확장
- 일정 지층마다 광물 일부를 기지로 원격 전송
- 쓰러진 동료의 가방 회수 시간 또는 범위 개선
- 보스 처치 후 전리품 보호 단계 추가

이 카테고리가 모든 캐릭터의 필수 선행 세금이 되지 않도록 주의한다. 기본 상태에서도 실패 시 일부 일반 광물이 남아야 하며, 회수 노드는 손실을 없애는 필수 기능이 아니라 후반 위험 부담을 점진적으로 완화하는 선택지가 되어야 한다.

### 8.4 탈출 포트 프로세스

**상태: 프로세스 확정 · v7.1.9에 솔로 기준 구현 · 수치 튜닝 필요**

귀환은 결과 버튼이 아니라 한 판의 마지막 긴장 구간이어야 한다(§8.1). 이를 위해 탈출은 다음 5단계 프로세스로 확정한다.

1. **요청과 지점 지정** — 팀원 중 누구든 탈출을 요청해 탈출 포트를 소환할 수 있다. 소환 지점은 붉은색 지면 원(보스 투사체가 사용하는 것과 같은 문법의 위험 지점 표시)으로 플레이어가 직접 지정하며, 캐릭터 주변 반경 안에서만 고를 수 있다.
2. **도착 대기와 생존** — 포트는 즉시 오지 않는다. 도착까지의 시간 동안 살아남아야 한다. 이 구간에서 적 웨이브를 인위적으로 강화하지는 않는다. 땅굴이 깊을수록 도착 시간이 길어진다.
3. **접근과 탑승** — 도착한 포트에 크루 전원이 접근해 탑승해야 한다.
4. **성공 판정** — 생존자 전원이 탑승하면 탈출 성공이며, 이 시점에 §8.2의 생환 정산이 완성된다.
5. **보스 처치 시 자동 소환** — 행성 중심부 보스를 처치하면 탈출 포트가 자동으로 요청된다.

설계 의도:

- 지점 지정이 곧 전술 판단이다. 방어하기 좋은 곳, 지형을 뚫고 나가기 좋은 곳을 팀이 고른다.
- 깊이에 비례하는 대기 시간은 §0.4의 원칙 그대로 심층 도전의 위험 비용을 만든다. 수치는 웨이브 강화가 아니라 시간으로만 조정한다.
- 전원 탑승 조건은 쓰러진 동료 구조(§9.2)에 실질 가치를 부여한다. 생존자 전원 기준이므로 사망자가 있어도 남은 인원 탑승으로 성공한다.

#### 8.4.1 v7.1.9 구현 상태

무한 모드 런타임에 솔로 기준으로 구현했다. 생존자 전원 = 플레이어 1명이며, 코옵 확장 시 탑승 인원 집계 지점이 이미 분리되어 있다.

| 항목 | 구현 | 초기값 |
|---|---|---|
| 요청 | X 키 또는 HUD 버튼 → 지정 모드 진입 | — |
| 지점 지정 | 붉은 지면 원 미리보기 · 좌클릭 확정 · 우클릭/X/Esc 취소 | 반경 6칸 |
| 도착 대기 | 심층 1 기준 20초 + 심층당 7초, 상한 60초 | `INF_ESCAPE` |
| 도착 연출 | 포트가 지형을 뚫고 착륙(반경 1.45칸 파괴) — 벽 위 지정도 유효 | — |
| 탑승 | 포트 1.25칸 안에서 1.2초 채널링, 벗어나면 감소 | — |
| 보스 자동 소환 | 처치 즉시 보스 위치 부근에 자동 요청. 휴식 화면에서 하강과 탈출 중 선택 | — |
| 성공 결과 | 결과 화면 제목·문구 분기, 생환 기록(`INF_META.escapes`) 누적 | — |

무한 모드 특례: 보스 처치 후 휴식 화면에서 `다음 심층으로`를 고르면 요청했던 포트는 두고 간다(하강 시 포트 소멸). 이는 무한 모드가 엔드게임 후보(§13)로 남는 동안의 규칙이며, 본편 행성 원정에서는 보스 처치 후 탈출이 기본 흐름이다.

튜닝·확장 대상: 대기 시간 곡선(20+7/심층), 탑승 채널링 시간, 코옵의 전원 탑승 판정과 대기 UI, 포트 방어 실패(파괴 가능 여부 — 현재는 불괴), 원정 중 탈출 요청 횟수 제한 여부.

## 9. 캐릭터와 4인 협동

### 9.1 기본 역할

| 직업 | 핵심 역할 | 현재 기반 |
|---|---|---|
| 드릴러 | 길 개척과 암반 파괴 | 고압 드릴, 기반암 균열, 돌파 파기 |
| 스카우트 | 시야와 기동 정찰 | 플레어, 그래플 훅, 표식 |
| 엔지니어 | 공간과 방어 거점 구성 | 전력 노드, 센트리, 구조물 |
| 거너 | 적 제압과 화력 지원 | 중화기, 파쇄 발사기, 방어 수단 |

### 9.2 협동의 목표

- 각 직업은 혼자서 기본적인 생존과 진행이 가능하다.
- 함께할 때 이동 속도, 안전성, 탐사 범위와 전투 효율이 크게 좋아진다.
- 한 직업이 없으면 진행이 불가능한 강제 자물쇠보다, 있으면 다른 경로와 보상을 얻는 구조를 우선한다.
- 쓰러진 동료 구조, 광물 운반, 시야 공유와 지형 개척으로 자연스러운 협동 행동을 만든다.
- 드릴러만 채굴 노동을 전담하고 나머지가 기다리는 구조를 만들지 않는다.
- 역할의 필요성은 개인 보상 우대가 아니라 플레이 행동, 경로, 속도, 안전성과 선택 폭으로 체감시킨다.
- 모든 직업이 각자의 방식으로 굴착할 수 있지만, 굴착 관련 영구 노드와 3특성의 성장 폭 및 최종 고점은 드릴러가 가장 높다.

확정된 역할 방향과 세부 검증 대상:

| 직업 | 굴착·광물 과정의 기여 후보 |
|---|---|
| 드릴러 | 단단한 암반 돌파, 최단 통로와 대형 광맥 노출, 보스전 지형 재구성 |
| 스카우트 | 벽 너머 광맥과 위험 탐지, 희귀 광맥 표식, 우회로 선행 정찰 |
| 엔지니어 | 채굴 거점, 운반·정제·원격 전송 장치, 방어 시설 구축 |
| 거너 | 채굴 중 습격 방어, 위험 구역 확보, 파쇄 발사기를 이용한 보조 굴착 |

표의 역할 방향은 확정한다. 각 장비의 기본 굴착 속도, 암반 등급별 효율, 탄약·열·재사용 대기시간과 굴착 노드의 수치 상한은 수직 슬라이스에서 조정한다. 드릴러가 없더라도 일반 행성 진행은 가능해야 하지만, 드릴러가 있을 때는 통로 개척 속도와 경로 선택 폭이 명확하게 넓어져야 한다.

### 9.3 친구와 플레이할 이유

- 혼자보다 더 위험하고 보상이 큰 행성에 도전할 수 있다.
- 서로 다른 직업과 빌드 조합을 실험할 수 있다.
- 희귀 광맥, 비밀 구역과 유물 발견 가능성이 높아진다.
- 고성장 플레이어가 초보 친구의 행성 개척을 도울 수 있다.
- 멘토 플레이에도 별도의 보상과 기록을 제공할 수 있다.

영구 성장 격차가 큰 친구끼리 함께할 때의 능력 보정 규칙은 반드시 별도로 정해야 한다.

### 9.4 솔로 플레이

현재의 보조 드론 구조를 유지·발전시킨다. 선택한 직업이 부족한 역할 일부를 드론이 얇게 보완하되, 4인 파티의 모든 협동 효율을 그대로 대체하지는 않는다.

### 9.5 LAN 코옵 본편 확장 — 1단계 구현 상태 (트랙 F 분기)

**상태: 동기화 경계 확정 · 2~4인 로비와 본편(무한 모드) 코옵 1단계 구현 · 적/보스 동기는 다음 단계**

기존 LAN 기반은 채취 미션 2인 전용(host/guest)이었고 본편 런타임은 코옵을 강제로 껐다. 1단계에서 다음을 구현했다 (서버 `coop/server.mjs` v2 · 클라이언트 `coop/client.js` v2 · 게임 분기 훅).

**동기화 경계 (§17.4-4 점검 결과 — 이 표가 코옵의 기준선이다):**

| 상태 | 방식 | 근거 |
|---|---|---|
| 맵 | 방 시드 배포 → 결정적 생성. 무한 모드 생성기는 `DEMO.seed` 기반이라 전 클라이언트 동일 맵 (실측 해시 일치) | 서버 권위 불필요 |
| 개인 경험치·레벨·카드 | **동기화하지 않음** — 레벨 숫자만 명판 표시용으로 알림 | §5.2 개인 성장 확정 |
| 벽 파괴 | 이벤트 릴레이. 피어의 파괴도 장악도에 기여하되 **내 경험치는 오르지 않음** | §5.3 역할 행동 경험치 |
| 탈출 포트 | 요청자가 지점·대기시간을 브로드캐스트 → 전 클라이언트 동일 재현. 탑승은 board 이벤트 집계 | §8.4-1·2 |
| 전원 탑승 판정 | 각 클라이언트가 '나 포함 생존자 전원 탑승'을 판정. 다운·이탈 크루는 제외 | §8.4-3·4 생존자 전원 |
| 위치·시야 | 20Hz 상태 릴레이 · 다중 피어 FoW 시야 합산 | v1 유지·확장 |
| 적 AI·보스 HP | **아직 로컬(비동기)** — 다음 단계. 릴레이 서버로는 한계가 있어 호스트 권위 방식 검토 필요 | 미해결 위험 |
| 광물·코어 정산 | 미구현 — A 트랙(정산 모델) 머지 후 이관 | §7.3 |

**코옵 카드 선택 처리 (§17.2-5 — 1차 결정):** 솔로는 기존대로 전체 정지. 코옵은 **비정지** — 게임이 계속 도는 동안 카드 모달이 뜨고, 선택은 1·2·3 키로 한다(§5.6의 키 선택 재사용). 모달이 마우스를 덮는 동안에도 이동은 가능하다. 슬로 모션·자동 방어 같은 상위 보호 장치는 실플레이 후 판단한다.

탈출 전원 탑승의 실측 흐름: 1인 탑승 → HUD `탑승 1/2 · 크루 대기 중`, 런 계속 → 2인째 탑승 → 양쪽 모두 `탈출 성공 · 크루 전원 탑승`. 요청 취소는 없고(§8.4), 탑승 확정 후에는 내리지 못한다.

다음 단계 후보: 적 스폰·보스 HP의 호스트 권위 동기, 다운 상태와 구조(§9.2)의 코옵 판정, 광물 정산(A 머지 후), 재접속.

## 10. 행성 고유 콘텐츠

각 행성은 단순 팔레트 교체가 아니라 최소한 하나의 진행 규칙이 달라져야 한다.

행성의 구성 요소:

- 고유 지형과 암반
- 대표 환경 위험
- 고유 광물
- 일반 적과 엘리트 변종
- 비밀 구역 또는 사건
- 수집 유물군
- 중심부 고유 보스
- 보스 전용 전리품

현재 자산의 전환 예시:

- 퍼플 땅굴: 첫 행성 또는 기본 광물 행성
- 청록 염굴: 염수 장판과 부식 환경을 가진 행성
- 붉은 화염룡: 화산 또는 맨틀 행성의 중심부 보스

행성별 고유 보스 제작 비용이 크므로, 일반 행성 수와 보스 재사용·변형 원칙을 제작 범위와 함께 정해야 한다.

## 11. 보스 설계

### 11.1 위계

- 일반 적: 이동과 채굴을 압박한다.
- 엘리트 또는 수호자: 중간 지층의 전투 목표와 보스 예고를 담당한다.
- 행성 보스: 중심부에서 만나는 해당 행성의 최종 목표다.
- 변종 또는 강화 보스: 클리어 후 고난도와 엔드게임에서 등장한다.

현재 무한 모드의 장악도 40%마다 등장하는 보스는 행성 구조에 그대로 반복 배치하지 않는다. 행성 보스의 희소성과 기대감을 지키기 위해 중간 출현자는 수호자로 재분류한다. 이 방향은 검토안에서 **확정**으로 승격하고, 트랙 B에서 구현했다.

### 11.1.1 위계 구현 상태 (트랙 B 분기)

**상태: 위계 규칙 확정 · 분기 파일에 구현 · 수치 튜닝과 수호자 전용 외형은 후속**

장악도 40% 출현자를 심층에 따라 세 티어로 나눈다. 판정은 `infBossTierForDepth(depth)` 한 곳에서 하며, 중심부 심층(`INF_BOSS_TIER.finalDepth`, 임시값 3)은 **C 트랙(지층 구조)이 행성 정의로 연결할 예약 지점**이다.

| 티어 | 출현 심층 | 정체 | 중심부 보스 대비 | 처치 시 |
|---|---|---|---|---|
| 심층 수호자 | 중심부 이전 | 같은 종의 아종 — 작고 빠른 중간 목표 | 체력 38% · 크기 62% · 접촉 65% · 이동 145% · 탄 절반 · 소환 절반 · 돌진 성향 +25% · **장갑·페이즈 없음** | 코어 2+심층 · 탈출 자동 요청 **없음** · "더 깊은 곳의 기척" 전조 |
| 암반 포식자 (중심부 보스) | 중심부 심층 | 행성 최종 목표 — 붉은 화염룡 계열 풀 메커니즘(장갑 2페이즈·브레스·돌진·소환) | 기준 | 코어 6+심층 · 탈출 포트 자동 요청(§8.4-5) |
| 변종 포식자 | 중심부 이후(엔드게임) | 강화 변종 | 체력 112% · 접촉 115% · 이동 105% | 코어 6+심층 · 탈출 자동 요청 |

설계 근거:

- 수호자에게서 장갑 페이즈를 제거한 것이 핵심 차별화다. "벽을 파서 약점을 노출한다"는 채굴 보스전 문법(§11.2)은 중심부 보스의 서명 경험으로 아껴 둔다.
- 수호자 처치가 탈출을 자동 요청하지 않는 것은 §8.4-5의 문구 그대로다 — 자동 요청은 "행성 중심부 보스" 전용이며, 수호자는 원정이 계속되는 중간 목표다.
- 코어 보상 차등(2+심층 대 6+심층)은 §7.1의 "보스 코어는 고유 보스에서"를 위계에 맞게 나눈 것이다.
- BOSS_LAB(보스 테스트 도구)은 항상 중심부 보스를 검사한다. 티어는 랩 수치에 영향을 주지 않는다.

후속 항목: 수호자 전용 스프라이트·외형(현재는 축소·가속된 포식자 몸체 공유), 티어별 수치 튜닝, 수호자 처치 보상에 레전드 카드 3택을 그대로 줄지 하위 등급 카드로 낮출지, 그리고 C 트랙의 finalDepth 연결.

### 11.2 땅굴 크루다운 보스전

- 벽을 파서 안전지대나 공격 경로를 만든다.
- 시야를 확보해야 패턴을 읽을 수 있다.
- 설치물과 지형 제어가 전투에 영향을 준다.
- 화력 역할만 보스를 상대하고 나머지가 구경하는 구조를 피한다.
- 전투 전까지 축적한 런 빌드가 눈에 띄게 폭발하는 절정이 되어야 한다.

## 12. 메인 기지

메인 기지는 복잡한 생활 시뮬레이션이 아니라, 원정 사이의 보상과 다음 목표를 정리하는 짧고 명확한 허브다.

필수 기능:

- 우주 지도와 행성 선택
- 캐릭터 선택 및 상태 확인
- 영구 성장 노드
- 유물 컬렉션과 행성 도감
- 파티 구성과 친구 초대
- 장비 또는 시작 프리셋 설정
- 귀환 전리품 정산

귀환 직후 권장 흐름:

```text
로켓 도착
→ 전리품 하역
→ 새 광물·유물·도감 확인
→ 성장 가능한 노드 알림
→ 원하는 경우 노드 활성화
→ 다음 행성 선택
```

플레이어가 바로 다음 원정을 시작하고 싶을 때는 정산과 노드 구매 화면을 빠르게 건너뛸 수 있어야 한다.

### 12.1 행성 지도·출격 흐름 구현 상태 (트랙 G 분기)

**상태: 허브 메뉴형 1차 확정(§17.3-8) · 지도·출격 흐름 구현 · 컷씬은 임시(영상 슬롯 준비)**

확정 스펙(2026-08-28): 메인 화면 → 행성 지도(팝업이 아닌 풀스크린 씬) → 행성 선택 → 직업 선택 → 출격 컷씬 → 필드 도착 → 게임 시작. 잠긴 행성 10개 노출, 지도는 한눈에 다 보이지 않고 **드래그로 이동할 만큼 넓게** — 우주의 공간감과 행성 간 거리를 시각적으로 연출한다.

| 항목 | 구현 |
|---|---|
| 지도 씬 | 3200×2000 월드 + 드래그 패닝(경계 클램프) + 휠 이동. 별밭 3층 패럴랙스로 깊이감 |
| 행성 | 총 11개 — 퍼플 땅굴(개척 가능) + 잠긴 행성 10개(§10 후보 포함: 청록 염굴·적열 맨틀 등). 개척 경로 점선으로 연결 |
| 정보 패널 (§3.2) | 이름·환경·지층 수·목표 시간·위험·광물·기록. 보스는 **클리어 전 실루엣 문구, 클리어 후 실명 공개**(§3.2 예고 원칙). 잠긴 행성은 환경 키워드와 해금 안내만 |
| 출격 흐름 | 행성 선택 → `출격 준비` → 기존 직업 선택 화면 → 시작 시 컷씬. 뒤로가기는 지도로 복귀 |
| 컷씬 | 임시 코드 연출 ~2.8초(별밭·로켓·행성 접근·착륙 플래시), 클릭/버튼 스킵. `INF_CUTSCENE.videoSrc` 에 영상 경로를 넣으면 영상 재생으로 교체(확정: 추후 영상 제공) |

| 데이터 | `INF_PLANETS` 배열 — 행성 추가는 항목 추가로 끝난다. 활성 행성 전환(2호 행성)은 후속 |

미구현·후속: 실제 해금 로직(§3.3 — 두 번째 플레이 가능 행성이 생길 때 `INF_PLANET` 전환과 함께), 파티 구성 화면(§2 — 코옵 로비와 통합 검토), 유물 컬렉션·도감 메뉴, 정산 화면에서 지도로 직행하는 동선, 행성 일러스트 교체(현재는 코드 드로잉 구체).

## 13. 난도와 엔드게임

기본 캠페인 행성을 클리어한 이후에는 같은 시스템을 다음 방식으로 확장할 수 있다.

- 더 높은 위험 등급의 행성
- 환경 변이가 붙은 행성
- 주간 특수 원정
- 행성 심층 이상지대 또는 무한 굴착
- 강화된 보스와 새로운 패턴
- 특정 직업 조합이나 성장 조건을 요구하는 최고 난도
- 희귀 유물과 외형 보상

현재의 무한 모드는 **클리어한 행성의 심층 이상지대** 또는 별도의 최종 행성으로 전환하는 안을 우선 검토한다.

최고 난도가 단순 영구 공격력 검사만 되지 않도록 역할 숙련, 팀 구성, 런 빌드와 보스 이해도를 함께 요구해야 한다.

최고 난도 행성은 35~45분의 긴 연속 원정이므로, 후반부 회수 노드와 팀의 생환 준비가 실질적인 전략 요소가 된다. 단, 플레이 시간만 늘어지는 구조를 피하기 위해 더 긴 원정일수록 새로운 지층 변화와 위험·보상 선택을 충분히 제공해야 한다.

## 16. 현재 결정 상태 요약

### 16.1 본편 구조 — 확정

1. 행성은 본편의 스테이지이자 장기 진행 지도다.
2. 크루는 우주 지도에서 행성을 고르고, 캐릭터·직업을 선택한 뒤 로켓으로 출격한다.
3. 한 행성은 착륙부터 지층 돌파, 중심부 보스와 탈출까지 한 번의 연속 원정으로 완료한다.
4. 목표 시간은 초반 15~20분, 일반 25~30분, 최고 난도 35~45분이다.
5. 보스 처치만으로 원정을 끝내지 않고, 전리품을 가지고 생환하는 것까지 한 판의 결말로 삼는다.
6. 무한 모드는 기본 캠페인 메뉴가 아니라 행성 심층 이상지대 또는 엔드게임 후보로 재정의한다.
7. 탈출은 요청 → 지점 지정 → 도착까지 생존 → 전원 탑승의 5단계 포트 프로세스를 따르며, 보스 처치 시 포트가 자동 요청된다(§8.4).

### 16.2 런 성장과 영구 성장 — 확정

1. 원정 안에서는 개인 경험치로 레벨업하고 3개의 런 특성 또는 전술 카드 중 하나를 반복 선택한다.
2. 경험치, 레벨업 시점과 3특성 선택은 파티가 공유하지 않으며 플레이어마다 독립적이다.
3. 개인 경험치는 기존 직업별 역할 행동 가중치 구조를 유지한다. 새로운 팀 경험치 시스템은 추가하지 않는다.
4. 런 특성은 해당 원정에서만 유지하고 원정 종료 시 초기화한다.
5. 영구 노드는 원정 도중 구매하지 않으며 귀환 후 메인 기지에서만 성장시킨다.
6. 캐릭터는 각자 별도의 영구 성장치를 가진다.
7. 영구 성장은 초반의 수치 체감과 중후반의 카드·스킬 변형·프리셋 같은 수평 확장을 결합한다.
8. 기존 54노드의 아이디어와 아이콘은 재활용할 수 있지만, 런 중 구매 구조와 원정별 초기화는 폐기한다.

### 16.3 굴착과 직업 정체성 — 확정

1. 드릴러, 스카우트, 엔지니어와 거너 모두 각자의 장비와 방식으로 기본 굴착을 할 수 있다. 단 굴착의 형태가 다르다. 드릴러·스카우트·엔지니어는 드릴과 절삭기로 **연속 굴착**하고, 거너는 파쇄 발사기로 **쿨다운 굴착**한다. 거너에게 연속 굴착 수단이 없는 것은 설계 위반이 아니다.
2. 어떤 직업 구성으로도 일반적인 경로 진행이 가능해야 하며 드릴러가 없다는 이유만으로 원정이 막혀서는 안 된다.
3. 드릴러는 기본 굴착 성능, 단단한 암반 돌파, 장거리 통로 개척, 굴착 노드와 3특성의 성장 폭 및 최종 고점에서 가장 우수하다.
4. 다른 직업에도 굴착 노드와 굴착 관련 3특성을 제공할 수 있지만, 굴착 빌드의 고점은 드릴러보다 낮다.
5. 드릴러의 가치는 광물 소유권이나 추가 정산 보상이 아니라 길을 빠르게 만들고 지형을 재구성하는 행동에서 나온다.
6. 일반 광맥은 간단히 채취하고, 대형·희귀 광맥만 필요에 따라 역할 협동이 발생하는 사건으로 확장한다.

### 16.4 자원, 실패와 코옵 보상 — 확정 및 부분 확정

1. 영구 광물은 마지막 타격자에게 귀속하지 않고 원정 종료 시 별도 규칙으로 정산한다. 이 원칙은 **확정**이다.
2. 마지막 타격 경쟁, 자원 가로채기와 한 플레이어의 독점은 방지한다. 이 원칙은 **확정**이다.
3. 개인 가방, 팀 공용 적재함, 전원 동일 지급 또는 혼합 방식 중 실제 정산 단위는 **미결정**이다.
4. 실패해도 일반 광물 일부는 기본 확보하고, 희귀 광물과 보스 코어는 생환 가치가 더 크도록 한다. 이 원칙은 **확정**이다.
5. 영구 성장에 일반 광물 확보율, 희귀 광물 보호, 안전 주머니와 원격 전송 계열을 둔다. 정확한 수치와 귀속 범위는 **부분 확정**이다.
6. 유물 수집, 고난도 행성, 친구 지원과 미개척 행성이 장기 플레이 동기가 된다. 구체적인 반복 보상은 **미결정**이다.

## 17. 미결정·미확인·추가 논의 목록

이 절은 이미 확정한 방향을 다시 질문하지 않기 위한 작업 목록이다. **미결정**은 선택이 필요한 설계, **미확인**은 현재 구현 또는 플레이 감각을 확인해야 하는 항목, **튜닝 필요**는 방향을 바꾸지 않고 수치로 해결할 항목을 뜻한다.

### 17.1 우선순위 A — 첫 수직 슬라이스 전에 결정할 것

1. **영구 광물의 최종 정산 모델 — 미결정**<br>
   완전 동일 지급, 팀 공용 적재함을 개인별로 복제 정산, 개인 가방과 팀 보너스의 혼합 방식 중 하나를 골라야 한다. 마지막 타격자에게 귀속하지 않는다는 원칙은 바뀌지 않는다.

2. **첫 행성의 지층·중간 수호자·보스·탈출 규칙 — 부분 해소**<br>
   탈출 자체의 규칙은 §8.4의 포트 프로세스로 확정하고 v7.1.9에 구현했다. 남은 것은 지층 수, 지층 전환 방식, 중간 목표, 전리품 운반 방식과 심층별 대기 시간 곡선의 튜닝이다.

3. **3특성 카드의 획득 속도와 제시 규칙 — 부분 해소**<br>
   목표 레벨 곡선, 등급 출현(진행도 기반), 리롤·중복 규칙과 키보드 선택은 §5.6으로 확정·구현했다. 남은 것은 실플레이 수치 튜닝과, 코옵에서의 선택 중 진행 처리(§17.2-5와 동일 항목 — F 트랙과 결정)다.

4. **실패 시 실제 손실·보존 수치 — 튜닝 필요**<br>
   일반 광물 기본 확보율, 희귀 광물 보호량, 보스 코어의 예외 여부와 중간 전송 효율을 정해야 한다.

5. **소형 영구 노드 프로토타입 — 해소(v7.3.0, 트랙 A)**<br>
   직업 공용 8노드(기초 4 + 상위 4, 선행 조건·점진 공개)를 구현했다. 보관 코어를 소비하고 계정에 영속하며 재출격 시 적용된다. 남은 것은 §6.4 혼합형 원칙에 맞춘 노드 확장(카드·스킬 변형 해금 계열), 비용 곡선 튜닝, §17.2-1의 귀속 결정이다.

6. **직업별 굴착 수치와 행동 차이 — 튜닝 필요**<br>
   기본 굴착 속도, 암반 등급별 효율, 범위, 관통, 탄약·열·재사용 대기시간과 굴착 노드의 상한을 조정해야 한다. 전 직업 굴착 가능과 드릴러 최고점 우위는 이미 확정되어 있다.

### 17.2 우선순위 B — 코옵과 계정 성장에서 결정할 것

1. **광물 회수·보존 노드의 귀속 — 미결정**<br>
   캐릭터별, 계정 공용 또는 메인 기지 공용 중 선택해야 한다. 캐릭터별이면 개성이 강해지지만 새 캐릭터 전환 부담이 커지고, 공용이면 고난도 도전 접근성이 좋아진다.

2. **성장 차이가 큰 친구와의 보정 — 미결정**<br>
   고레벨 하향 보정, 저레벨 임시 강화, 행성별 능력 상한 또는 보정 없음 중 원칙을 정해야 한다.

3. **동일 직업 중복 — 미결정**<br>
   자유 선택, 중복 금지 또는 파티 옵션 중 하나를 정해야 한다.

4. **솔로와 협동의 클리어 범위 — 미결정**<br>
   솔로로 모든 일반 행성을 클리어할 수 있게 할지, 일부 최고 난도를 협동 전용으로 둘지 정해야 한다.

5. **개인별 카드 선택 중 코옵 진행 처리 — 1차 결정(비정지)**<br>
   코옵에서는 선택 화면이 다른 플레이어를 멈추지 않는다. 게임이 계속 도는 동안 본인 화면에만 모달이 뜨고 1·2·3 키로 즉시 선택한다(§9.5). 자동 방어·슬로 모션 같은 추가 보호는 실플레이테스트 후 필요하면 얹는다.

### 17.3 우선순위 C — 콘텐츠와 장기 반복 플레이에서 결정할 것

1. **행성 해금 경로와 분기 수 — 미결정**
2. **첫 완성 목표와 출시 목표의 행성 수 — 미결정**
3. **클리어한 행성을 반복할 핵심 이유 — 미결정**<br>
   희귀 유물, 난도 등급, 무작위 변이, 노드 재료와 기록 경쟁 중 주축을 정해야 한다.
4. **유물의 기능 — 미결정**<br>
   컬렉션 전용인지 장착 효과가 있는지 결정해야 하며, 장착 효과가 있다면 영구 노드 및 런 특성과 역할이 겹치지 않아야 한다.
5. **보스 제작과 재사용 원칙 — 미결정**<br>
   행성마다 완전 고유 보스를 제작할지, 골격·패턴을 변형해 재사용할지 제작 범위와 함께 정해야 한다.
6. **무한 모드의 최종 위치 — 부분 확정**<br>
   엔드게임으로 옮긴다는 방향은 정했지만, 특정 행성의 심층 이상지대인지 별도 최종 행성인지 결정하지 않았다.
7. **자원과 카드의 최종 명칭 — 미결정**<br>
   펄프·블룸·암반 코어의 새 획득처와 명칭, `런 특성`과 `전술 카드` 중 최종 UI 명칭을 정해야 한다.
8. **메인 기지와 우주 지도 UX — 1차 확정(메뉴형, v7.3.0-starmap)**<br>
   허브는 메뉴형으로 확정한다 — 메인 메뉴가 기지이고 행성 지도가 출격 동선이다(§12.1). 걸어다니는 공간형 기지는 콘텐츠가 갖춰진 뒤 재검토한다. 남은 흐름 구체화: 정산→지도 직행 동선, 파티 구성 화면.

### 17.4 현재 프로토타입에서 확인해야 할 것

1. **역할별 개인 경험치 연결 — 해소(2026-08-28)**<br>
   점검 결과 v7.1.8의 경험치 획득처는 굴착 2곳과 스카우트 탐사 1곳뿐이었고, 적 처치와 설치물 운용은 개인 경험치에 전혀 연결되어 있지 않았다. 거너와 엔지니어는 자기 역할을 수행해도 레벨이 오르지 않는 상태였다. 단일 관문 `infAwardXp`를 도입해 전투와 지원을 연결하고 직업별 가중치를 적용했다. 상세는 §5.3.1을 따른다. 남은 일은 수치 밸런스 검증이며 아래 2번으로 이어진다.

2. **역할별 성장 속도 — 검증 필요**<br>
   §5.3.1의 초기 가중치로 네 직업을 각각 플레이해, 정상적인 역할 수행 후 보스 직전의 레벨과 카드 수가 지나치게 벌어지지 않는지 확인한다. 네 명의 레벨이 완전히 같을 필요는 없다. 런 종료 화면의 역할 행동별 경험치 내역(§5.3.3)을 근거 자료로 사용하고, 특정 직업의 성장이 여전히 굴착에 과도하게 의존하는지 비율로 판단한다.

3. **전 직업 굴착의 손맛과 드릴러 우위 — 검증 필요**<br>
   드릴러 없이도 일반 진행이 가능하고, 드릴러가 있을 때 길을 만드는 속도와 선택 폭이 확실히 좋아지는지 확인한다.

4. **LAN 코옵의 본편 확장성 — 부분 해소(1단계 구현)**<br>
   동기화 경계를 점검해 §9.5의 표로 확정하고, 2~4인 로비·동일 맵 시드·탈출 전원 탑승·카드 비정지를 구현했다(2인 실측 검증). 남은 것은 적 AI·보스 HP 동기(호스트 권위 검토), 광물 정산 동기(A 머지 후), 다운·구조 판정과 재접속이다.

5. **원정 목표 시간 — 검증 필요**<br>
   15~45분 목표가 실제 지층 밀도, 카드 완성 속도, 보스 준비와 탈출까지 포함했을 때 지루하거나 급하지 않은지 확인한다.

6. **개인 카드 선택 UI의 전투 안전성 — 검증 필요**<br>
   서로 다른 레벨업 시점에 카드 UI가 시야, 이동과 협동을 방해하지 않는지 확인한다.

### 17.5 보류 — 세계관과 메인 스토리

**땅굴 크루가 여러 행성을 파고 중심부의 보스를 상대하는 서사적 이유**는 추후 별도 논의한다. 자원 채굴, 행성 구조, 실종 탐사대 구조, 고대 유물, 더 큰 위협 추적 등의 가능성을 열어두며 현 단계에서는 구현 규칙을 이 설정에 종속시키지 않는다.

| `infEndRun(reason,escaped)` | 런 종료·정산 | A 트랙 소유. 다른 트랙은 훅 한 줄 삽입까지만 |

| keydown·pointerdown 핸들러 | 입력 | 자기 조건문 한 줄 삽입만. 사용 중 키: WASD/Q/E/R/F/X/Space/Esc |
| `#infHud` ihRow 블록, `infPaint` | HUD | 새 요소는 새 id로 행 추가. 기존 행 수정 금지 |
| 결과·휴식 모달 HTML | `infResultModal`, `infRestModal` | id 추가는 자유, 기존 id 삭제·개명 금지 |
| `infAwardXp` 관문 | 경험치 지급 | 모든 새 획득처는 반드시 이 관문 경유. 테이블에 키 추가로 확장 |
| 파일 내 버전 문자열 3곳 | 설정 모달 등 | 머지 담당만 갱신 |

### 19.3 분기 파일과 머지 규약

**파일 규칙**

1. 본선은 한 시점에 하나다. 현재 본선: `tunnel-crew-infinite-mode-v7.3.0.html`. (이전: v7.2.0)
2. 트랙 작업은 본선을 복제한 분기 파일에서 한다: `tunnel-crew-infinite-mode-v7.3.0-<트랙명>.html`. 사운드의 `-sound-polish` 관례와 같다.
3. 분기 파일에서 본선 파일을 직접 수정하지 않는다. 본선의 다음 버전(v7.3.0 등)은 머지 담당만 만든다.
4. **줄바꿈 주의:** 이 파일은 CRLF/LF 혼용이다. 에디터·스크립트가 파일 전체 줄바꿈을 정규화하면 diff 가 16MB 전체로 번져 머지가 불가능해진다. 저장 시 줄바꿈 변환이 꺼져 있는지 반드시 확인한다.
5. 대용량 임베드(base64 스프라이트·오디오) 줄은 절대 재인코딩하지 않는다.

**코드 규칙**

1. 새 런 상태는 `INF.<트랙 네임스페이스>` 아래에만 만든다. 튜닝 상수는 기능 코드 옆에 `INF_<이름>` 상수 오브젝트 하나로 모은다 (`INF_ESCAPE`, `INF_XP_TABLE` 방식).
2. 삭제 대신 예약: 다른 트랙이 쓸 수 있는 데이터·함수는 지우지 말고 주석으로 예약 표시한다 (`INF_BRANCHES` 방식).
3. 기존 함수를 고칠 때는 시그니처를 유지하고 매개변수는 뒤에만 추가한다 (`infEndRun(reason,escaped)` 방식).
4. 완료 기준: 스크립트 블록별 문법 검사 통과 + 스모크(런 시작 → 굴착·전투 → 보스 → 탈출 성공/사망 → 결과·기록) + 콘솔 신규 오류 0 (기존 LAN WebSocket 오류는 무시).

**문서 규칙**

1. 이 기획서는 누적 문서다. 각 트랙은 자기 담당 절과 §19.1 보드의 자기 행만 수정하고, §0.6 경과표에 행을 추가한다. 다른 트랙의 절은 고치지 않는다.
2. 규칙을 바꿀 때는 결론만이 아니라 변경 이유와 남은 위험을 함께 적는다 (문서 말미 원칙과 동일).

**머지 절차** (머지 담당)

1. 트랙 완료 신고: 분기 파일 경로, 수정한 함수·HTML id 목록, 새 상수·네임스페이스, 검증 결과를 §19.1 보드 자기 행에 기록한다.
2. 본선 최신본을 복제해 다음 버전 파일을 만들고, 트랙 변경을 §19.2 접점 지도 순서대로 재적용한다. 접점이 겹치지 않는 트랙은 순서 무관, 겹치는 트랙(A↔E, B↔C)은 보드의 선행 관계를 따른다.
3. 재적용 후 문법 검사와 스모크를 다시 돌리고, 파일 내 버전 문자열 3곳을 새 파일명과 일치시킨다.
4. 병합된 트랙은 보드의 '완료' 표로 옮기고, 분기 파일은 보존한다(롤백 근거). 보존 위치는 루트가 아니라 `backup-YYYYMMDD-versions/` 폴더다 — 루트에는 본선 최신, 직전 본선, 진행 중 분기만 남긴다(2026-08-28 정리 규칙). 구버전 v7.1.2~v7.1.9 와 머지 완료 분기(-settle, -boss-tier)는 `backup-20260828-versions/` 로 이동했다.
