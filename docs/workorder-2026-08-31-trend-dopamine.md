# 작업지시서 — 스팀 트렌드 기반 장단점 개선 & 도파민 콘텐츠 개발

> 작성: 2026-08-31 · 발주: 사용자 요약 지시 → Claude가 세분화
> 목적: 이 문서 하나만 보고 여러 세션에 걸쳐 연속 작업이 가능하도록, 판단 기준·산출물·완료 조건까지 명시한다.
> 원칙: **분석 → 진단 → 개선 → 신규 콘텐츠** 순서를 지키되, 각 단계의 산출물은 즉시 다음 단계의 입력이 된다. 단계를 건너뛰고 콘텐츠부터 만들지 않는다.

---

## 발주 원문 (요약 지시)

> 현재 게임이 가지고 있는 장점과 단점을 최신 스팀 게임 트렌드를 분석한 내용을 기준으로 파악하고, 단점을 개선하고 장점을 부각한다.
> 특히 파티플레이가 가지고 있는 각 유저의 자유도와 최신 게임의 트렌드인 도파민 유발에 대해 심리학적으로 파고들어서 이 게임만의 도파민 매력을 끌어올릴 수 있는 컨텐츠를 만드는데 집중한다.

## 전체 로드맵

```
Phase 0  기준 빌드 확정 + 현황 스냅샷          (산출: 상태 보고)
Phase 1  스팀 트렌드 리서치                    (산출: 트렌드 분석 보고서)
Phase 2  장단점 진단 매트릭스                  (산출: 진단표 + 우선순위)
Phase 3  단점 개선 스프린트                    (산출: 개선 빌드 vX.X)
Phase 4  장점 부각 스프린트                    (산출: 강화 빌드 vX.X)
Phase 5  도파민 심리학 설계서                  (산출: 설계 문서)
Phase 6  도파민 콘텐츠 구현 사이클 (반복)       (산출: 콘텐츠별 빌드)
Phase 7  통합 검증 + 워크로그                  (산출: 검증 보고 + worklog)
```

각 Phase 종료 시 **반드시** ① 산출물 파일 저장, ② worklog에 결정·근거 1줄 추가, ③ 다음 Phase 착수. 사용자 확인이 필요한 항목은 "질문 대기 목록"에 적어두고 **작업은 멈추지 않는다** (기본안을 채택해 진행하고, 목록에 대안을 남긴다).

## Phase 0 — 기준 빌드 확정 + 현황 스냅샷

**목적:** 어떤 파일을 고치는지, 지금 게임에 뭐가 들어있는지를 문서가 아닌 코드로 확정한다.

- [ ] 0.1 기준 파일 확정. 후보: `tunnel-crew-infinite-mode-v7.7.0.html`(본선), `tunnel-crew-infinite-mode-v7.7.0-ui-develop.html`(UI 분기). 두 파일의 diff 규모와 최근 커밋 메시지로 본선을 판정하고, 판정 결과를 memory(`main-game-target-file.md`)에 갱신한다. 이후 모든 작업은 **새 버전 파일로 복사 후** 진행 (기존 파일 직접 수정 금지, 프로젝트 관례 유지).
- [ ] 0.2 현재 시스템 인벤토리 작성: 코드에서 실제 동작을 확인해 다음 목록을 표로 정리 — 직업 4종 스킬, 런 특성 카드 풀(직업당 종수), 영구 노드 수, 유물(relic) 종수, 보스 티어, 지층 구조, AI 크루 행동 종류, 사운드/연출 훅(paintUI 래핑 포함).
- [ ] 0.3 실플레이 계측 1회: 브라우저 pane으로 솔로+AI크루 3인 원정 1회를 자동 스텝핑(rAF 정지 시 update 직접 호출 — memory `tunnel-crew-browser-verify.md` 방식)으로 돌리고 다음을 기록 — 지층별 소요시간, 레벨업 횟수·간격, 카드 선택에 걸린 시간, 사망/위기 횟수, 정산 화면 체류 시간.
- [ ] 0.4 산출물: `docs/analysis/00-current-state.md` (인벤토리 표 + 계측 수치 + "코드로 확인 못 한 항목" 목록)

**완료 조건:** 기준 파일이 확정되고, 인벤토리에 "문서상 존재하지만 코드에 없음" 항목이 전부 표시됨.

## Phase 1 — 스팀 트렌드 리서치

**목적:** '내 감'이 아니라 근거 자료 기준으로 장단점을 판정할 잣대를 만든다.

- [ ] 1.1 웹 리서치 (WebSearch/WebFetch): 2024–2026 스팀에서 성공한 **협동 PvE / 익스트랙션 / 로그라이트** 게임의 공통점을 조사한다. 최소 조사 대상: Deep Rock Galactic(+Survivor), Lethal Company, R.E.P.O., Content Warning, Helldivers 2, Vampire Survivors 계열, Balatro, Core Keeper, Dome Keeper, 33 Immortals 등 + 2025~2026 신작 중 동접·리뷰 급상승 사례.
- [ ] 1.2 각 게임에서 추출할 항목(고정 양식): ① 세션 길이 ② 도파민 트리거(잭팟/변동 보상/근접 실패/연출) ③ 파티 내 개인 자유도 장치 ④ 웃음·소셜 바이럴 장치(클립 유발 요소) ⑤ 실패의 처리 방식 ⑥ "한 판 더" 루프의 마감 위치.
- [ ] 1.3 트렌드 종합: 위 표에서 반복 등장하는 패턴을 5~8개 명제로 압축한다. 예상 축 — "실패가 웃기면 리텐션이 된다", "보상은 예측 불가하게, 피드백은 즉시", "개인 순간(클러치)을 시스템이 목격하게 하라", "정산 화면이 두 번째 게임이다" 등. **실제 리서치 결과로 대체할 것.**
- [ ] 1.4 산출물: `docs/analysis/01-steam-trends.md` (게임별 표 + 종합 명제 + 출처 링크)

**완료 조건:** 종합 명제 각각에 최소 2개 게임의 근거가 붙어 있음.

## Phase 2 — 장단점 진단 매트릭스

**목적:** Phase 1의 명제를 잣대로 현재 빌드를 채점하고, 개선 우선순위를 확정한다.

- [ ] 2.1 Phase 1의 각 명제에 대해 현재 게임을 3단 평가(충족/부분/미충족)하고 근거를 코드·계측(Phase 0.3)에서 인용한다.
- [ ] 2.2 장점 후보 검증 (문서상 강점이 실제로 체감되는지 코드/플레이로 확인):
  - 직업 4종의 "없으면 불편" 상호의존
  - 런 성장(3특성 카드) ↔ 영구 성장(노드 지도)의 이중 루프
  - 유한 원정 + 탈출 긴장 구조
  - AI 크루로 솔로에서도 4인 감각 재현
  - 어둠/시야(FoW)의 발견 연출
- [ ] 2.3 단점 후보 검증 (아래는 초기 가설 — 실측으로 확정/기각):
  - 정산·성장 지도 화면의 도파민 밀도 부족 (숫자 나열 vs Balatro식 점수 연출)
  - 보상의 예측 가능성 과다 (광맥 = 정직한 수확, 잭팟 순간 부재)
  - 개인 활약이 기록·과시되지 않음 (클러치 순간이 휘발)
  - 파티 내 자유도가 "역할 분담"에 갇힘 (일탈적 플레이·리스크 베팅 수단 부족)
  - 실패가 그냥 손실 (웃음도, 서사도, 보상 변형도 없음)
  - 사운드·화면 피드백의 타격감 편차 (드릴은 좋고 나머지는 밋밋한지 확인)
- [ ] 2.4 우선순위 매김: 각 항목에 [체감 임팩트 1-5] × [구현 비용 1-5 역산] 점수. 상위 항목부터 Phase 3/4/6에 배정한다.
- [ ] 2.5 산출물: `docs/analysis/02-strength-weakness.md` (매트릭스 + 우선순위 + Phase 배정표)

**완료 조건:** 모든 장단점 항목에 "코드 근거" 또는 "계측 근거"가 붙어 있고, 감상만 있는 항목이 0개.

## Phase 3 — 단점 개선 스프린트

**목적:** Phase 2 우선순위 상위의 단점을 빌드에 반영한다. **새 시스템 추가 최소화, 기존 시스템의 마찰 제거 우선.**

작업 방식 (모든 개선 공통):
1. 새 버전 파일 복사 (`-improve` 접미사 분기)
2. 항목당 커밋 1개 단위로 구현
3. 브라우저 스텝핑 검증 + 스크린샷
4. 시네마틱/연출 추가 시 paintUI 페이드 래퍼 규약(memory) 준수
5. AI 크루 관련 수정은 `crew-ai.js` + 주입 스크립트 경로로만 (HTML 직접 수정 금지)

예상 개선 항목 (Phase 2 결과로 대체·재정렬):
- [ ] 3.1 정산 화면 리듬 개선: 획득 자원이 한 번에 뜨지 않고 항목별 카운트업 + 사운드 틱, 희귀 획득은 별도 비트로 지연 공개 (Balatro/슬롯의 순차 공개 문법)
- [ ] 3.2 피격·처치·채굴 피드백 균질화: 히트스톱, 화면 셰이크 강도 테이블화, 직업별 타격 SFX 편차 보정
- [ ] 3.3 위기 가시화: 체력 임계 시 화면 연출 + 동료(AI 포함) 구조 시스템의 보상·연출 강화
- [ ] 3.4 실패 정산의 재해석: 전멸 시에도 "이번 원정의 기록"(최심 도달, 최다 처치, 웃긴 사인(死因) 문구)을 남겨 실패가 이야기가 되게 함
- [ ] 3.5 카드 선택 순간의 정보 부담 축소: 시너지 하이라이트(이미 가진 특성과 조합되는 카드에 표시)

**완료 조건:** 배정된 항목 전부 구현+검증, 각 항목 전후 비교 스크린샷/수치가 worklog에 기록됨.

## Phase 4 — 장점 부각 스프린트

**목적:** 이미 좋은 것을 플레이어가 더 자주, 더 크게 느끼게 한다.

- [ ] 4.1 역할 상호의존의 가시화: 다른 크루(AI 포함)의 기여가 내 화면에 보이게 — 스카우트의 표식이 내 시야에 반짝, 엔지니어 발판을 밟는 순간 이펙트, "OO 덕분에" 어시스트 토스트
- [ ] 4.2 이중 성장 루프의 연결 연출: 정산에서 "이번에 캔 코어 → 노드 지도에서 뭘 살 수 있는지" 프리뷰를 한 컷 보여주고 지도로 직행하는 동선
- [ ] 4.3 탈출 시퀀스 증폭: 카운트다운, 조명 변화, 전원 탑승 순간의 발사 연출을 원정의 클라이맥스로 격상 (paintUI 래퍼 규약 준수)
- [ ] 4.4 어둠·발견의 극대화: 대형 공동(空洞)/희귀 광맥 첫 조우 시 시야 개방 연출 + 전용 사운드 스팅
- [ ] 4.5 AI 크루 개성 표출: 직업별 대사·리액션(위기, 잭팟, 탈출)을 소량 추가해 "동료와 함께"라는 감각 강화

**완료 조건:** 각 항목이 실플레이 스텝핑에서 1회 이상 실제 발화(트리거)되는 것을 확인.

## Phase 5 — 도파민 심리학 설계서 (핵심 국면 1/2)

**목적:** 구현 전에, 심리학 근거 → 이 게임의 고유 자산 → 콘텐츠 스펙으로 이어지는 설계 문서를 만든다. **여기가 발주의 핵심이므로 리서치를 아끼지 않는다.**

- [ ] 5.1 심리학 프레임 정리 (웹 리서치 + 문헌): 각 이론을 1문단 + "이 게임 적용점" 1문단으로.
  - **변동비율 강화계획(VR schedule)** — 예측 불가 보상이 가장 강한 반복 행동을 만든다 → 채굴 보상의 분산 설계
  - **보상 예측 오차(도파민은 '예상보다 좋음'에서 분비)** — 기대치 관리와 서프라이즈 설계
  - **근접 실패(near-miss) 효과** — 아깝게 놓친 잭팟이 재도전을 만든다
  - **자기결정이론(SDT: 자율성·유능감·관계성)** — 파티플레이 자유도는 '자율성', 클러치는 '유능감', 어시스트 가시화는 '관계성'
  - **몰입(Flow)과 난이도 곡선** — 지층별 압박 상승과의 정합
  - **절정-종결 법칙(peak-end rule)** — 탈출(절정)과 정산(종결)에 도파민 예산 집중
  - **사회적 목격(social witnessing)** — 내 활약을 남이 봐야 완성되는 보상
- [ ] 5.2 "이 게임만의" 도파민 자산 매핑: 위 프레임을 범용 슬롯머신化하지 않도록, 반드시 **채굴·어둠·협동·탈출**이라는 이 게임 고유 동사에 결합한다. (예: 잭팟은 뽑기가 아니라 '파고 있던 벽 너머'에서 나와야 한다)
- [ ] 5.3 콘텐츠 후보 목록 작성 후 각각 스펙 1페이지: 아래 초안에서 시작하되 5.1~5.2 근거로 추가·삭제.

  | # | 후보 콘텐츠 | 심리 프레임 | 고유 동사 결합 |
  |---|---|---|---|
  | A | **광맥 잭팟**: 낮은 확률로 일반 광맥이 '노다지 광맥'으로 — 화면 전체 연출 + 파낼수록 커지는 보상, 단 적 웨이브 동반 | VR + 예측오차 | 채굴 |
  | B | **니어미스 유물**: 탈출 직전에만 감지되는 고가치 유물 신호 — 가져갈까 말까의 도박, 놓치면 정산에 '두고 온 것' 표시 | 근접실패 + 손실회피 | 탈출 |
  | C | **크루 하이라이트 릴**: 정산에서 플레이어별 최고 순간(최다 연쇄 굴착, 클러치 구조, 최후의 일격)을 개인 카드로 시상 | 유능감 + 사회적 목격 + peak-end | 협동 |
  | D | **피버 드릴(연쇄 균열)**: 연속 굴착 콤보 게이지 — 가득 차면 짧은 무한관통 피버, 직업별 피버 변형 | Flow + 즉시 피드백 | 채굴 |
  | E | **어둠 속 이상 신호**: 지층당 0~1회, 시야 밖에서 들리는 소리/빛 — 따라가면 보물 또는 함정 (파티가 갈지 말지 갈라질 자유) | VR + 자율성 | 어둠 |
  | F | **개인 사이드 계약**: 원정 시작 시 각자 비밀 보너스 목표 1개(예: 전투 없이 지층 통과, 광맥 5연속 선점) — 달성 시 개인 보상, 공개 시점은 정산 | 자율성 + 개인 자유도 | 협동 내 개인 |
  | G | **도박 제단/수상한 상인**: 지층 사이 휴식 구간에서 코어를 걸고 카드 업그레이드·변형 뽑기 | VR + 손실회피 | 성장 루프 |

## Phase 6 — 도파민 콘텐츠 구현 사이클 (핵심 국면 2/2, 반복)

**목적:** Phase 5 스펙을 우선순위대로 하나씩 구현한다. **콘텐츠 1개 = 1사이클**, 사이클마다 아래 6단계를 완주한 뒤 다음으로 넘어간다.

```
사이클 (콘텐츠 1개당):
 ① 분기 파일 생성 (버전 넘버 + 콘텐츠명 접미사)
 ② 데이터·로직 구현 (기존 단일 관문 구조 준수: 경험치는 infAwardXp, 상수는 INF_* 정의 객체에)
 ③ 연출 구현 (사운드 스팅 + 화면 연출, paintUI 래퍼 규약)
 ④ AI 크루 대응 (AI도 해당 콘텐츠에 반응하는가 — crew-ai.js 경로로)
 ⑤ 검증: 스텝핑으로 트리거 강제 발화 → 정상 동작 + 엣지(중복 발동, 사망 중 발동, 코옵 비정지 중 발동) 확인, 스크린샷 기록
 ⑥ 밸런스 셀프 리뷰: "이 콘텐츠가 없던 판과 비교해 어떤 판단이 새로 생겼나" 1문단 — 답이 없으면 수치 재조정 후 ⑤ 재실행
```

- [ ] 6.1 사이클 1: (Phase 5.4 1순위)
- [ ] 6.2 사이클 2: (2순위)
- [ ] 6.3 사이클 3: (3순위)
- [ ] 6.4 사이클 4~5: 토큰·시간 여유 시 (4~5순위)
- [ ] 6.5 사이클 간 통합: 콘텐츠 2개 이상이 같은 순간(예: 정산)에 겹칠 때의 연출 우선순위 정리

**완료 조건(사이클당):** ⑤ 검증 통과 + ⑥ 리뷰 문단 작성. **완료 조건(Phase):** 최소 3콘텐츠가 한 빌드에 공존하며 통합 원정 1회가 무결하게 완주됨.

## 작업 규약 (전 Phase 공통)

1. **파일 규약**: 기준 HTML 직접 수정 금지, 항상 버전 접미사 분기 복사 후 작업. AI 크루는 `crew-ai.js` + 주입 스크립트.
2. **검증 규약**: 브라우저 pane 숨김 시 rAF 정지 → update 함수 직접 스텝핑으로 검증 (memory 참조).
3. **연출 규약**: update 정지형 연출은 반드시 paintUI 페이드 래퍼 사용.
4. **의사결정 규약**: 막히면 기본안 채택 + "질문 대기 목록"에 기록하고 전진. 파괴적 변경(기존 시스템 삭제)만 사용자 확인 대기.
5. **기록 규약**: Phase 종료마다 worklog 갱신. 커밋 메시지에 Phase 번호 포함.
5-1. **커밋 규약**: 항목 1개 구현+검증 완료 시점마다 로컬 커밋 (깨진 중간 상태는 커밋하지 않음). push는 사용자 지시 없이는 하지 않는다. 장시간 작업의 유실 방지가 목적이므로, 검증까지 오래 걸리는 항목은 "동작하는 중간 단계"를 쪼개서라도 커밋 주기를 30~40분 이내로 유지한다.
5-2. **작업 시간 규약**: 사용자가 마감 시각을 지정한 경우, 각 작업 단위(Phase 착수, 사이클 착수, 커밋 시점) 직전에 `Get-Date`로 로컬 시각을 확인한다. 마감을 넘었으면 새 작업을 시작하지 않고 즉시 ① 현재 상태 커밋 ② worklog에 진행상황·중단 지점·재개 방법 기록 ③ 사용자 보고 후 종료한다. 마감 직전(15분 이내)에는 긴 항목을 새로 시작하지 않는다.
6. **윤리 규약**: 도파민 설계는 5.5 가드레일 안에서만. 현금성·사행성 연결 금지.
