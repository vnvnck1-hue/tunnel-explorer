# FTUE 스토리 연출 확장 콘티 — 「응답 없는 4번 갱도」

> 기준 구현: `FtueDirector`의 4개 컷만화와 플레이어블 프롤로그
>
> 방향: 컷씬 자체를 길게 늘이기보다 플레이 중 상호대사를 촘촘히 넣고, 현재의 “생존자 셋”을 메인 미스터리로 승격한다.

## 1. 한 줄 피치

사흘 전에 끊긴 구조 신호를 따라 4번 갱도로 내려간 신입과 베테랑 스카우트 모래는, 구조 신호가 사람을 찾는 신호가 아니라 **사람의 목소리를 익혀 다음 구조대를 부르는 미끼**였다는 사실을 알아낸다.

## 2. 확장 목표

- 현재 5~7분인 첫 원정을 **7~9분**으로 확장한다.
- 컷만화는 약 40초에서 **55~65초**로만 늘리고, 추가 서사의 대부분은 이동·굴착·전투 중 재생한다.
- 현재 14컷·약 11개 대사를 **18~20컷·약 30개 대사**로 확장한다.
- 컷만화와 인게임의 모든 말풍선에 타이핑·속도 변화·단어별 색·움직임·왜곡을 사용하는 **다이나믹 텍스트 연출**을 적용한다.
- 컷만화는 자동으로 넘어가지 않는다. 플레이어가 문장을 읽고 **클릭·Enter·패드 A로 직접 다음 비트를 진행**한다.
- 컷만화·플레이·장비 선택 사이를 세계관 안의 신호·충격·해치 모티프로 연결해 갑작스러운 화면 교체를 없앤다.
- 플레이어는 계속 말이 없는 주인공으로 둔다. 성격을 강요하지 않고 행동이 대답이 되게 한다.
- 캐릭터 관계는 `모래 ↔ 관제`, `모래 ↔ 신입`, `선발대장 ↔ 선발대원`의 세 축으로 보여 준다.
- 모든 대사는 정보 전달, 관계 표현, 다음 행동 암시 중 최소 두 가지 역할을 동시에 수행한다.

## 3. 이야기의 질문과 회수

| 시점 | 플레이어가 품을 질문 | 제시 정보 | 회수 |
|---|---|---|---|
| 강하 직전 | 사흘 지난 신호에 정말 생존자가 있나? | 관제는 생체 신호 3개를 확신한다. | 실제로 발견되는 사람은 모래 한 명뿐이다. |
| 모래 구조 | 나머지 두 명은 어디 있나? | 관제 화면에는 여전히 두 신호가 남는다. | 신호 둘은 지하 생명체와 동기화되어 움직인다. |
| 블랙박스 | 선발대는 무엇을 발견했나? | 선발대 역시 자기들 아래에서 “세 명”의 신호를 들었다. | 생명체는 당시 선발대의 수와 말을 복제했다. |
| 탈출 | 지금 들리는 모래와 관제는 진짜인가? | 같은 문장이 서로 다른 위치에서 반복된다. | 가짜 관제의 잘못된 복귀 지시를 모래가 알아챈다. |
| 엔딩 | 사건은 끝났나? | 강하선은 이륙하지만 신호 3개는 지하에 남는다. | 본편 행성 원정의 장기 미스터리로 이어진다. |

## 4. 캐릭터 대사 규칙

| 인물 | 말투와 기능 | 금지 |
|---|---|---|

| **흉내 신호** | 이미 들은 문장만 정확히 재사용한다. 새 문장을 만들지 않는다. 어순·간격·발신 위치가 비정상이다. | 괴물의 독백, 직접적인 악의 표현 |

## 6. 상세 콘티와 대사

### 장 0. 구조 신호 / 강하

목적은 세계관 설명이 아니라 세 가지 사실만 심는 것이다. `4번 갱도`, `사흘 전`, `생체 신호 셋`.

| 컷 | 화면·카메라 | 대사 | 사운드·전환 |
|---:|---|---|---|
| 0-1 | 검정 화면. 낡은 CRT 파형 세 줄이 같은 간격으로 깜빡인다. 각 파형의 끝은 미세하게 어긋난다. | **???**: “여기… 세 명 살아 있어.” | 현재 `mimic` 음형을 아주 약하게 사용. 문장 후 긴 정적. |
| 0-2 | 기존 강하선 안전봉 클로즈업. 기체가 크게 흔들릴 때 손이 봉을 다시 쥔다. | **관제**: “4번 갱도 구조 신호 확인. 생체 반응 셋.” | 관제 2음. 엔진 저역 위로 신호 세 번. |
| 0-3 | 기존 모래 좌석 컷. 모래는 창밖이 아니라 신입의 장비 체결 상태를 본다. | **모래**: “사흘 지난 신호잖아.”<br>**관제**: “71시간 18분. 구조 규정은 유효하다.” | 두 대사를 한 컷에서 순차 표시. 모래가 안전 고리를 한 번 당겨 확인. |
| 0-4 | 계기판 경고등. 고도 수치가 급락하고 파형 세 줄이 잠깐 한 줄로 겹친다. | **모래**: “그럼 셋 데리고 올라가자. 신입, 고개 숙여.” | 경보음이 대사를 먹지 않게 BGM 덕킹. |
| 0-5 | 기존 충돌 와이드 컷. 강하선이 암벽을 긁으며 추락한다. | 대사 없음. | 충돌 직전 0.12초 무음 → `impact`. 흰 플래시 뒤 검정. |

연출 메모: 첫 문장의 화자는 밝히지 않는다. 당시 선발대가 남긴 평범한 생존 보고를 생명체가 구조 신호로 재사용한 것으로만 암시한다. 이후에는 플레이어가 직접 들은 문장만 흉내 내도록 해 모방 규칙을 공정하게 보여 준다.

### 장 1. 충돌 / 비상 장비 선택

기존 역할 선택을 메타 메뉴가 아니라 파손된 강하선의 **비상 장비함을 직접 여는 짧은 플레이 장면**으로 바꾼다. 별도의 검은 선택 화면과 네 장의 카드는 사용하지 않는다.

| 순서 | 화면·행동 | 대사·전환 |
|---:|---|---|
| 1 | 충돌 컷에서 플레이어가 클릭한다. 흰 충격 플래시가 번진 뒤 노출이 내려오면, 같은 구도의 강하선 내부가 1인칭 시점으로 이어진다. | **모래**: “들리면 움직여. 왼쪽 비상함은 살아 있어.” |
| 2 | 카메라가 쓰러진 좌석 높이에서 왼쪽으로 천천히 돌아간다. 벽에 고정된 비상 장비함 네 칸이 순서대로 스파크와 함께 켜진다. | **관제**: “주 장비 응답 없음. 대체 장비 하나를 승인한다.” |
| 3 | 네 슬롯에는 직업 카드 대신 `드릴 헤드`, `파쇄 발사기`, `플레어 리그`, `전력 제어기`가 실제 물건처럼 걸려 있다. 커서나 패드 포커스로 장비를 가리키면 해당 슬롯의 작업등만 켜지고 짧은 기능 문구가 헬멧 HUD에 투영된다. | 이름·기능은 장비함의 닳은 명판과 HUD 한 줄로만 보여 준다. 전신 초상화와 스탯 표는 FTUE에서 숨긴다. |
| 4 | 원하는 장비를 클릭·Enter·패드 A로 선택한다. 장갑 낀 손이 잠금 레버를 당기고 장비가 앞으로 빠져나온다. 별도 확인 버튼은 없다. | 선택한 직업에 따라 아래 모래 대사를 재생한다. |
| 5 | 뽑힌 장비가 화면 전경을 가로질러 짧게 암전시킨다. 암전 중 장착음, 다시 밝아질 때는 같은 방향의 강하선 해치가 열리며 플레이 월드가 보인다. | **모래**: “좋아. 출구부터 만든다.” |

상호작용 원칙:

- 마우스 호버는 장비를 4~6px 앞으로 당기고 슬롯 조명을 밝힌다. 키보드 숫자 1~4와 패드 좌우도 같은 포커스를 사용한다.
- 최초 포커스는 드릴러에 있지만, 실제 선택 입력 전에는 자동 확정하지 않는다.
- 기능 설명은 `길을 연다`, `적을 지운다`, `어둠을 연다`, `공간을 만든다` 한 줄까지만 표시한다.
- 선택 후 0.45초의 기계 동작 동안 입력을 잠그고 곧바로 게임으로 연결한다. 다시 메타 UI처럼 보이는 확인 팝업은 띄우지 않는다.

역할별 반응:

| 선택 | 모래 대사 |
|---|---|
| 드릴러 | “드릴. 좋아. 오늘은 문보다 벽이 많겠어.” |
| 거너 | “파쇄탄이네. 안전거리는 내가 정할게.” |
| 스카우트 | “내 예비 장비야. 플레어 아껴 쓰진 마.” |
| 엔지니어 | “전력이 불안정해. 네 장비로 살려 써.” |

### 장 2. 잔해 밖 통로

대사는 이동을 막지 않는다. 플레이어가 목표 행동을 하면 남은 대사는 즉시 다음 장으로 넘기고, 뒤늦게 재생하지 않는다.

| 트리거 | 발화 | 대사 | 기능 |
|---|---|---|---|
| 역할 확정 후 0.8초 | 모래 | “일어나. 출구는 암반 반대쪽이야.” | 이동 목표 |
| 3칸 이동 또는 4초 | 관제 | “강하선 추진부 정지. 귀환 전 수동 점화가 필요하다.” | 탈출 목표 선행 제시 |
| 관제 직후 | 모래 | “먼저 살아서 돌아오면 고치지.” | 관계·톤 |
| 첫 벽 접근 | 모래 | “금 간 곳을 노려. 벽 전체랑 싸우지 말고.” | 굴착 힌트 |
| 첫 벽 파괴 | 관제 | “외부 통로 확보. 구조 신호는 동쪽 31미터. 전방 통로로 진행.” | 방향 제시·후반 모방 대사 심기 |
| 0.7초 후 | 모래 | “내 신호도 거기 잡혀?” | 미스터리 |
| 0.8초 후 | 관제 | “긍정. 동일 반응 세 개가 같은 방향이다.” | ‘셋’ 재강조 |
| 0.8초 후 | 모래 | “난 혼자인데.” | 이상 징후 |

### 장 3. 두드림 / 모래 구조

| 트리거 | 화면·연출 | 대사 |
|---|---|---|
| 어두운 구역 진입 | 램프가 꺼지고 벽 너머에서 두 번, 잠시 뒤 두 번 두드린다. | **모래**: “빛을 앞에 던져. 네 몸 말고.” |
| 플레어 착탄 | 플레어가 벽을 비추면 먼지가 박자에 맞춰 떨어진다. | **관제**: “생체 반응 둘은 벽 후방. 하나는 네 바로 앞이다.” |
| 0.9초 후 | 두드림이 한 번 더 들린다. | **모래**: “앞의 하나가 나야. 나머지 둘은 소리도 없어.” |
| 구조벽 체력 50% | 벽 틈으로 모래의 램프가 보인다. | **모래**: “좋아, 계속. 천장은 건드리지 마.” |
| 벽 파괴 | 모래가 비틀거리며 나온 뒤 신입 장비를 빠르게 훑는다. | **모래**: “신입? 오늘부터라며. 운도 없네.” |
| 0.8초 후 | 모래가 자신의 송신기를 두드려 켠다. | **관제**: “스카우트 모래 확인. 생존자 한 명. 잔여 반응 둘.” |
| 0.7초 후 | 모래가 텅 빈 굴을 돌아본다. | **모래**: “여기 한 명 살아 있어. 나.” |
| 0.9초 후 | HUD 생체 신호 3개 중 하나만 청록, 둘은 진홍색으로 순간 점멸. | **관제**: “불일치 기록. 잔여 신호를 추적한다.” |

핵심 연기: 모래는 “구해 줘서 고맙다”고 말하지 않는다. 대신 다음 교전에서 바로 신입 앞을 막아 서며 감사를 행동으로 보여 준다.

## 7. 다이나믹 텍스트 연출 문법

카타나 제로의 핵심을 ‘글자가 한 글자씩 나오는 효과’로만 보지 않는다. **발화의 속도, 멈춤, 강조, 감정 변화가 글자의 시간과 형태를 바꾸고, 플레이어 입력이 그 리듬에 참여하는 방식**을 가져온다. 다만 TunnelCrew에서는 대화 분기나 무례하게 끊기 시스템을 복제하지 않고, 읽기 완료와 컷 진행에 사용한다.

### 적용 범위

| 대상 | 적용 | 비고 |
|---|---|---|
| FTUE 만화 컷 말풍선 | 전체 효과 | 작가가 문장 안에 의미 태그를 지정한다. |
| FTUE 플레이 중 말풍선 | 전체 효과 | 전투 중에는 이동 폭과 흔들림을 60%로 낮춘다. |
| AI 크루 머리 위 말풍선 | 타이핑 + 캐릭터 프로필 | AI 시스템 문구에는 위험·감정 태그를 넣을 수 있다. |
| 플레이어·코옵 채팅 말풍선 | 중립 타이핑만 | 사용자 문자열은 태그를 해석하지 않고 반드시 이스케이프한다. |
| 좌하단 채팅 로그·목표 HUD | 미적용 | 기록과 조작 정보는 즉시 읽혀야 하므로 정적 텍스트를 유지한다. |

### 기본 타이핑

- 기본 속도는 한글 기준 초당 18~22글자, 영문·숫자는 초당 24~28자로 한다.
- 쉼표 `,`는 0.08초, 마침표는 0.16초, 말줄임표 `…`는 0.28초 자동 정지한다.
- 새 글자마다 작은 무전 블립을 내되 공백과 구두점에는 재생하지 않는다. 같은 음형의 피치만 화자별로 바꾼다.
- 줄바꿈 위치가 타이핑 도중 움직이지 않도록 전체 문장을 먼저 레이아웃하고, 아직 나오지 않은 글자의 알파만 0으로 둔다.
- 한 말풍선에서 동시에 움직이는 강조는 최대 두 구간으로 제한한다. 모든 글자를 계속 흔들어 피로하게 만들지 않는다.

### 작가용 의미 태그

대사 원문에는 렌더러 전용 대괄호 태그를 사용하고, 저장 로그·접근성 텍스트에서는 태그를 제거한다.

| 태그 예시 | 화면 효과 | 사용처 |
|---|---|---|
| `[wait=.18]` | 지정 시간만큼 타이핑 정지 | 망설임, 문장 반전 |
| `[speed=.65]…[/speed]` | 해당 구간을 느리게 타이핑 | 경고, 낮게 말하는 문장 |
| `[tint=signal]…[/tint]` | 청록 신호색으로 변화 | 수치·좌표·생체 신호 |
| `[tint=danger]…[/tint]` | 암버에서 진홍으로 짧게 번짐 | 위험 단어, 이상 징후 |
| `[jitter=.7]…[/jitter]` | 글자별 위치가 작게 불규칙 진동 | 공포, 불안정한 무전 |
| `[wave=.5]…[/wave]` | 기준선을 따라 느리게 출렁임 | 살아 움직이는 광맥 |
| `[slam]…[/slam]` | 125%로 튀어나왔다 제자리로 충돌 | 짧은 명령, 충격어 |
| `[echo]…[/echo]` | 원문 뒤에 반투명 복제 글자가 1~2회 지연 | 흉내 신호 |
| `[erase=4]` | 직전 글자를 빠르게 지우고 수정 문장을 입력 | 관제가 판정을 정정하는 순간 |

### 화자 프로필

| 화자 | 타이핑 리듬 | 색·움직임 | 음형 |
|---|---|---|---|
| 관제 | 일정한 속도, 숫자 앞 0.08초 정지 | 기본 정렬 고정, 수치만 청록 | 정확한 2음 |
| 모래 | 글자 속도 ±8% 편차, 명령어는 빠르게 | 핵심 동사만 1~2px 아래로 찍힘 | 낮고 짧은 3음 |
| 선발대장 | 초반 일정, 후반으로 갈수록 구두점 정지 증가 | 기록 노이즈에 맞춘 미세 수평 흔들림 | 중저음 + 테이프 노이즈 |
| 선발대원 | 빠르게 시작해 이상 징후 앞에서 느려짐 | 위험 단어가 암버에서 진홍으로 변화 | 짧은 불안정 펄스 |

|---|---|---|

## 8. 클릭 진행형 컷만화

컷만화에는 시간 기반 자동 진행을 사용하지 않는다. 각 `ComicBeat`는 `컷 이미지 + 한 번의 발화 또는 무언 장면 + 진입 효과`로 구성하며, 플레이어 입력으로만 다음 비트에 진입한다.

### 한 클릭의 의미

1. 글자가 타이핑 중이면 첫 클릭은 **현재 문장을 즉시 완성**한다.
2. 문장이 모두 보인 상태에서 다음 클릭은 **다음 대사 또는 다음 컷**으로 진행한다.
3. 같은 원화에서 화자만 바뀌는 경우도 별도 비트로 취급한다. 컷은 그대로 두고 말풍선 위치와 화자만 전환한다.
4. 대사가 없는 충돌·각성 와이드 컷도 최소 0.45초 동안 보여 준 뒤 클릭 표시를 켠다. 자동으로 넘기지 않는다.
5. 클릭을 누른 채 진입했거나 더블클릭한 입력이 두 비트를 건너뛰지 않도록 컷 진입 후 0.18초 동안 새 입력을 받지 않는다.

지원 입력은 마우스 왼쪽 클릭, Enter, Space, 패드 A다. Esc 또는 패드 B 길게 누르기의 전체 컷씬 건너뛰기는 유지한다.

### 첫 컷의 초간단 튜토리얼

- 첫 말풍선 아래 오른쪽에 작은 마우스 버튼 아이콘과 `클릭하면 문장 완성`을 표시한다.
- 문장이 완성되면 같은 자리가 `클릭하여 다음 컷`으로 바뀌고 아이콘 외곽선이 한 번만 부드럽게 맥동한다.
- 첫 번째 컷을 성공적으로 넘기면 문구는 사라지고 아이콘만 남는다.
- 두 번째 컷을 넘긴 뒤에는 아이콘도 사라진다. 이후에는 화면 우하단의 작은 `●` 점멸만 사용한다.
- 키보드나 패드를 먼저 사용하면 아이콘과 문구를 즉시 해당 장치의 `Enter — 계속`, `A — 계속`으로 바꾼다.

튜토리얼은 별도 팝업이나 확인 창으로 띄우지 않는다. 말풍선과 같은 레이아웃 안에서 보여 줘 첫 클릭이 곧 학습이 되게 한다.

## 9. 컷씬·게임 전환 문법

현재 메타 화면에는 약 0.64초의 가로 와이프가 이미 있다. 이를 버리지 않고 FTUE 전환의 공통 기반으로 확장한다. 전환은 장면마다 새 효과를 남발하지 않고 `신호`, `충격`, `해치` 세 모티프만 반복한다.

| 전환 | 방식 | 길이 | 오디오 브리지 |
|---|---|---:|---|
| 메인 메뉴 → 첫 컷 | CRT 가로 와이프가 지나가며 화면을 검게 덮고, 주사선 세 줄이 구조 신호 파형으로 변한다. | 0.64초 | 로비 BGM을 먼저 덕킹하고 `mimic` 신호가 검은 화면에서 선행한다. |
| 컷 → 다음 컷 | 클릭 지점에서 얇은 먹선이 번지고 새 패널이 92% 크기에서 안착한다. 이전 패널은 현재 페이지에 남는다. | 0.18~0.24초 | 종이 타격음 대신 현재 `panel` 음형 사용. |
| 충돌 컷 → 비상 장비함 | 충돌 플래시로 완전히 하얗게 덮은 뒤 노출이 내려오며 같은 강하선 내부의 1인칭 시점으로 매치 컷한다. | 0.55초 | 충돌 저역을 이어 가고 청각이 먹먹해지는 0.25초 저역 통과. |
| 장비 선택 → 플레이 | 장착한 장비가 카메라 앞을 가로질러 암전하고, 같은 방향으로 강하선 해치가 열리며 월드를 드러낸다. | 0.45~0.60초 | 래치·천 마찰 → 실제 월드 앰비언스 순으로 연결. |
| 플레이 → 블랙박스 기록 | E 입력 후 0.18초 동안 월드가 감속되고 카메라가 블랙박스로 당겨진다. 붉은 LED가 화면을 채우면 RGB가 어긋나며 검은 컷만화 배경으로 넘어간다. | 0.55~0.70초 | 블랙박스 테이프 노이즈를 전환 0.15초 전에 시작. |
| 기록 → 지층 각성 | 마지막 기록 컷의 붉은 반사가 화면 밖으로 번져 각성 컷의 지층 맥으로 이어진다. 완전 암전은 하지 않는다. | 0.35초 | `captain` 노이즈가 `beacon` 음형으로 변형. |
| 각성 컷 → 복귀 플레이 | 모래가 가리킨 방향으로 패널을 확대해 붉은 점 하나를 화면 가득 채우고, 같은 위치의 월드 비상등으로 매치 컷한다. | 0.45초 | 심박 저역을 월드 추격 박자로 연결. |
| 강하선 도착 → 탈출 컷 | 플레이어가 진입 범위에 들어오면 해치 프레임이 양옆에서 닫혀 화면을 덮고, 클릭 후 첫 탈출 컷에서 다시 열린다. | 0.45초 | 실제 해치 모터음과 `door` 음형 동기화. |
| 마지막 컷 → 메인 메뉴 | 로고가 나온 뒤 CRT 신호가 수평 한 줄로 접히고, 그 선이 행성 지도의 스캔 라인으로 펼쳐진다. | 0.70초 | `title` 음형의 마지막 음을 로비 BGM 첫 음과 맞춘다. |

공통 규칙:

- 플레이 중 컷씬 진입은 화면이 70% 이상 덮인 시점에 입력과 시뮬레이션을 잠근다. 입력 즉시 세계가 멎는 느낌을 피한다.
- 컷씬 종료는 월드가 보이기 시작하기 0.1초 전에 앰비언스를 복원하고, 전환이 끝난 다음 프레임부터 입력을 받는다.
- 감속 모드에서는 흔들림·RGB 분리·확대 이동을 제거하고 0.18초 크로스페이드로 대체한다.
- 광과민 접근성 모드에서는 흰 충격 플래시를 35% 회색으로 낮추고 반복 점멸을 한 번의 밝기 변화로 바꾼다.

## 10. UI 구조와 구현 경계

현재 `CrtGui` 호출은 `CrtSurface`가 유지하는 Screen Space Camera uGUI Canvas와 `UnityEngine.UI.Text`로 출력된다. FTUE만 별도 Canvas로 다시 만들지 않고 기존 계층을 확장한다.

- 공용 `DynamicDialogueText` 경로를 두어 `FtueDirector`의 만화·플레이 말풍선과 `TeamOverlay`의 머리 위 말풍선이 같은 파서와 글자 효과를 사용하게 한다.
- CRT 전체 텍스트를 한꺼번에 TextMeshPro로 이전하지 않는다. 말풍선에만 글자별 정점 이동·색·알파를 적용하는 uGUI 메시 효과를 붙이는 작은 변경으로 시작한다.
- 말풍선 인스턴스에는 안정적인 `dialogueId`와 시작 시각을 전달한다. 프레임마다 재사용되는 UI 요소가 타이핑을 처음부터 다시 시작하지 않게 한다.
- 타이핑 중에도 전체 문장으로 레이아웃 높이를 계산해 말풍선 크기와 줄바꿈을 고정한다.
- 사용자 채팅은 의미 태그를 절대 실행하지 않는다. `<color>`와 대괄호 태그를 포함한 입력은 일반 문자로 처리해 색 주입과 레이아웃 훼손을 막는다.
- 설정에 `텍스트 속도: 기본 / 빠르게 / 즉시`를 추가한다. `즉시`에서도 강조 단어의 색은 남기되 이동·타이핑은 생략한다.

## 11. 대화 재생 규칙

대사가 늘어도 조작감이 나빠지지 않으려면 다음 규칙이 필요하다.

1. 플레이 중 대사는 최대 두 줄, 한 발화는 2.2~3.4초로 제한한다.
2. 대화 묶음 사이에는 최소 1.2초의 무음 구간을 둔다.
3. 새 목표가 시작되면 이전 장의 미재생 잡담은 폐기한다. 튜토리얼 안내를 뒤늦게 말하지 않는다.
4. 적이 플레이어 3.5칸 안에 있거나 HP가 35% 미만이면 비필수 대사를 보류한다.
5. 목표 입력 안내와 말풍선이 겹치면 입력 안내를 위로 올리고, 대사 때문에 입력 안내가 사라지지 않게 한다.
6. 동일 화자의 연속 두 문장은 한 말풍선에서 교체하되, 화자가 바뀌면 0.18초의 무전 전환 노이즈를 둔다.
7. 흉내 신호의 자막 화자는 끝까지 `???`로 유지한다. 색상은 모래·관제 색을 쓰지 않고 진홍 테두리만 사용한다.
8. 재도전에서는 컷만화를 건너뛰어도 핵심 플레이 대사 네 개는 유지한다: `잔여 반응 둘`, `불일치 기록`, `교전 개체와 동기화`, `말을 배운 거야`.

## 12. 화면·사운드 연출 우선순위

### 기존 자산으로 바로 가능한 항목

- 기존 4개 원화를 그대로 사용하면서 한 컷 안의 대사를 순차 교체한다.
- 생체 신호 3개를 CRT 파형 또는 작은 HUD 점으로 표시한다.
- 현재 `control`, `morae`, `captain`, `mimic`, `beacon`, `door`, `impact` 음형을 재사용한다.
- 복귀 구간의 가짜 웨이포인트, 발신 위치 3개, 비상등 경로 강조를 런타임 UI로 처리한다.
- 기존 직업 배지와 역할색은 비상 장비함의 작은 명판·슬롯 조명으로 재사용한다.

### 새 원화가 있으면 효과가 큰 항목

1. **송신기 파형 클로즈업 1컷** — 레버를 내려도 LED가 다시 켜지는 장면.
2. **모래가 신입을 잡아끄는 1컷** — 각성 직후 두 인물의 관계를 한 이미지로 전달.
3. **문 틈의 붉은 점 세 개 1컷** — ‘셋’ 미스터리를 가장 명확하게 회수.
4. **강하선 비상 장비함 1장** — 1인칭 구도에서 네 장비 슬롯과 해치가 함께 보이는 전환용 배경.

서사 컷 세 장은 별도 풀 페이지를 늘리기보다 기존 `sequence_record`, `sequence_awake`, `sequence_escape`의 개정판에 한 컷씩 추가한다. 비상 장비함만 선택 상호작용과 전환에 계속 쓰이므로 별도의 1인칭 배경 한 장으로 제작한다.

## 13. 구현용 대사 상태 최소안

현재 단일 `Say()` 호출은 새 대사가 들어오면 앞 대사를 덮어쓴다. 이 콘티를 구현할 때는 다음 정도의 작은 큐가 필요하다.

- 항목: `dialogueId`, `speaker`, `textScript`, `cue`, `priority`, `expiresAt`, `cancelOnStageChange`, `advanceMode`
- 우선순위: 위험 경고 > 입력 안내 연계 > 핵심 서사 > 관계 잡담
- 장면 전환 시 `cancelOnStageChange`인 미재생 대사는 폐기
- 흉내 신호는 원문 문자열을 직접 복사해 오탈자까지 동일하게 유지
- 역할 선택 반응만 `selectedRole` 분기, 나머지 핵심 서사는 모든 직업에서 동일
- 컷만화의 기존 `Start`·`Hold` 자동 타이머는 제거하고 `Typing → Ready → Transition → Typing` 입력 상태로 교체
- 말풍선 종료 시간은 타이핑이 끝난 뒤부터 계산하며, 전투 때문에 보류된 시간은 만료 시간에 포함하지 않음

## 14. 제작 순서

1. **공용 다이나믹 텍스트 렌더러**를 기존 FTUE 말풍선 하나에 연결해 한글 줄바꿈·색·글자 이동·즉시 표시를 검증한다.
2. 컷만화를 클릭 진행 상태로 바꾸고 첫 두 컷의 입력 튜토리얼과 더블클릭 방지를 검증한다.
3. 같은 렌더러를 FTUE 플레이 말풍선과 `TeamOverlay` 머리 위 말풍선으로 확장한다.
4. 기존 메타 와이프를 공용 전환 기반으로 분리하고 블랙박스 진입·복귀 매치 컷을 붙인다.
5. 비상 장비함 선택을 기존 직업 선택 로직에 연결한다. 역할 데이터와 실제 런 준비 경로는 바꾸지 않는다.
6. **대사 큐 + 기존 원화 버전**으로 전체 플레이 테스트한다.
7. `생체 신호 셋 → 모래 한 명 → 잔여 둘 → 지하에 셋`이 첫 플레이에서 이해되는지 확인한다.
8. 이해가 약한 지점에만 HUD 파형과 붉은 핑을 추가한 뒤 신규 원화 4컷을 제작한다.
9. 숙련 플레이 7분, 첫 플레이 9분을 넘으면 잡담부터 줄이고 핵심 미스터리 대사는 유지한다.

## 15. 반드시 지킬 것

- 괴물의 정체나 목적을 FTUE에서 전부 설명하지 않는다. “목소리를 배워 부른다”까지만 확정한다.
- 선발대의 시신이나 고어를 직접 보여 주지 않는다. 빈 장비와 끊긴 기록이 더 오래 남는다.
- 모래를 구조 대상에 머물게 하지 않는다. 구조 직후부터 전투·길 안내·후방 엄호로 능력을 보여 준다.
- 관제를 배신자처럼 보이게 하지 않는다. 가짜 관제 신호는 음형과 화면 노이즈로 공정하게 구분한다.
- 추가 서사는 튜토리얼 입력을 설명하는 별도 강의가 아니라, 플레이어가 방금 한 행동에 대한 반응으로 들려준다.
- 다이나믹 텍스트는 정보를 가리는 장식이 아니다. 핵심 단어를 읽기 어렵게 만들거나 글자 위치를 말풍선 밖으로 밀어내지 않는다.
- 컷은 자동으로 넘어가지 않는다. 유일한 예외는 클릭으로 시작된 0.18~0.24초의 컷 진입 애니메이션이다.
- 직업 선택은 물리적 장비를 고르는 장면으로 유지한다. 전신 카드 네 장과 스탯 비교표 형태로 되돌리지 않는다.

## 16. 1차 구현 반영 상태 (2026-09-14)

- 기존 컷 원화 4장은 수정하지 않고 런타임 컷 배치와 빈 말풍선/텍스트 레이어를 분리했다.
- `DynamicDialogueText`가 타이핑, 구두점 대기, 속도, 색, 흔들림, 웨이브, 강타, 에코 태그를 해석한다. 전체 문장을 먼저 레이아웃하고 아직 나오지 않은 글자의 정점 알파만 0으로 두므로 타이핑 중 줄바꿈이 변하지 않는다.
- 컷만화 진행은 자동 타이머를 제거했다. 첫 입력은 현재 문장을 완성하고, 다음 입력은 다음 대사 비트 또는 컷으로 넘어간다. 비대사 컷도 최소 0.45초 뒤 입력을 기다린다.
- 첫 두 번의 입력에는 `클릭하면 문장 완성` → `클릭하여 다음 컷` 안내를 표시하며, 이후에는 축약 도움말로 바뀐다.
- 컷씬, FTUE 플레이 대사, 크루 머리 위 채팅 말풍선이 같은 렌더러를 사용한다. 사용자 채팅은 마크업을 비활성화한다.
- 충격 플래시, 신호 주사선, 해치 개폐 전환을 연결했다. 감속/포토센서티브 모드에서는 플래시와 글자 이동을 줄인다.
- 직업 선택은 새 `equipment_locker` 1인칭 배경의 네 실제 장비 베이에 역할 로직을 매핑했다. 숫자키는 즉시 장착, 방향키/패드는 탐색 후 확인, 마우스는 해당 장비를 한 번 클릭하면 장착한다.
- 선발대 기록과 모래·관제 대사를 늘려 `신호 셋 → 모래 한 명 → 적성체와 동기화 → 모래 목소리 복제`가 플레이 흐름에서 이어지도록 했다.
