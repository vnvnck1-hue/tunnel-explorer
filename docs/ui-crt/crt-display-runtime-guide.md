## 2026-09-12 재설계: 효과 6종 × 기존 곡률 5종

사용자 선택 시안은 [셰이더 시안 기록](crt-shader-studies.md)이다. 종전 5종이 곡률 외에는 비슷해 보인다는 피드백에 따라, 신호 효과를 아래 6종으로 교체하고 이전 `CRT_*.asset` 5개는 변경하지 않고 유리 형상 프리셋으로 분리했다. 아래의 **이전 구현 기록**에 있는 5종 효과/이전 성능 수치는 새 버전의 검증 결과가 아니다.

구현은 Unity 셰이더이며 생성 이미지를 게임 화면 위에 덮지 않는다. 새 효과 자산은 `FX_*.asset`. 비교 캡처는 `CrtRuntimeCapture.Run -crtStudies 1`로 `img/runtime-six-effects`에 따로 저장해 과거 검증 자료와 섞지 않는다.

## 조작

- **F6 / Shift+F6**: 다음 / 이전 모니터.
- **F7**: 최종 CRT 효과 Off / On. 황색 UI 레이아웃은 유지한다.
- **F10** 또는 우상단 모니터 버튼: 표시 장치 설정.
- **패드 Select+Start**: 표시 장치 설정 열기/닫기.
- 설정에서는 ↑↓ / Tab / 패드 십자키로 이동, 좌우로 5% 조절, Enter / A로 선택, Esc / B로 닫는다. 마우스 선택과 슬라이더도 지원한다.
- 입력 장치가 바뀌면 스킬 키캡도 키보드/현재 패드 매핑으로 바뀐다.
- **F8 / F9** 투영 프리셋은 CRT와 다른 시스템이다. 투영 수치는 변경하지 않았다. 투영 디버그 문구는 기본 숨김이며 **F4**로 표시한다.
- 채팅 입력 중에는 모니터 단축키와 설정 버튼을 잠그고, 시간 지터와 노이즈를 완화한다. 채팅을 끝낸 뒤 표시 장치 설정을 연다.
- 표시 장치 설정 중에는 원정 시뮬레이션 입력/진행이 멈추지만 CRT의 비게임 시간 신호는 계속 움직인다. 설정을 닫으면 전환 감쇠 후 복귀한다.

## 다섯 가지 모니터

| 모니터 | 구조와 분위기 | 대표값 |
|---|---|---|
| Surveyor · 굴착선 관제관 | Strong− 기준의 둥근 관제관, 미세 주사선과 가장자리 색수차 | 곡률 .052, RGB .95px, 주사선 .095 / 2.5px |
| Broadcast · 방송 정밀관 | 평평한 유리, 수직 aperture grille, 안정적인 방송 신호 | 곡률 .018, grille .16, 상시 지터 0 |
| Arcade · 광산 오락실 | 돔 유리, 점형 shadow mask, 밝기에 따라 두꺼워지는 빔 | 곡률 .072, mask .19, 빔 반응 .55 |
| Relay · 장거리 수신기 | 낮은 수평 대역폭, 지연 에코, 느린 동기 띠 | 수평 번짐 .28, 에코 .09 / 6px, 롤 .028 |
| Abyss · 심층 음극관 | 교차 주사, 긴 인광 감쇠, 두꺼운 어두운 외곽 | 교차 주사 .12, persistence .24, 비네트 .40 |

강도 1~5가 아니다. 모니터 구조를 고른 뒤 전체 강도, 주사선, 곡률, RGB 분리, 노이즈/지터, 외곽 암부를 개별 조절한다. 선택과 조절값은 `tc.crt.*` PlayerPrefs에 저장한다.

세부 미술 조정은 각 `CRT_*.asset`의 `parameters`에서 한다. 곡률·주사선 주기·빔 두께·마스크 형태, 수평 번짐·에코·교차 주사·롤·잔상, 밝기·대비·검정 하한, 노이즈 갱신 속도·지터 밴드 수·발생 간격을 분리했다. `jitterFrequency`는 이름과 달리 Hz가 아닌 **동기선 발생 간격(초)**이며 기본 5.7초다. 기본 밝기/대비는 1, 검정 하한은 0으로 월드의 색조를 바꾸지 않는다. 잘못된 NaN/무한대 입력도 런타임에서 안전 범위로 제한한다.

접근성은 별도 축이다. **편안하게**는 곡률·RGB·노이즈를 약화하고 잔상/지터/교차 주사/롤을 끈다. **광과민 배려**는 시간 변화형 표시 장치 효과, RGB 분리, 곡률, 피격/보스 등장 화면 플래시를 끈다. 게임 전체의 모든 애니메이션이나 위험 연출을 제거한다는 뜻은 아니다. 필요하면 CRT 자체를 Off로 할 수 있다.

## 렌더와 자산

`URP 월드 → 지층 Volume → UI 전용 CameraSpace Canvas → CRT 최종 합성` 순서다. UI용 Overlay **Camera**와 ScreenSpaceOverlay **Canvas**는 다르며, 일반 게임 UI는 CRT를 우회하지 않는다. 전용 UI 카메라에는 후처리를 중복 적용하지 않는다. CRT가 켜진 동안에만 평가된 월드 Film Grain을 억제하며 Volume 원본 자산은 보존한다.

- `Assets/_Project/Presentation/UI/CRT/Runtime/`: 컨트롤러, 카메라 스택, RenderGraph 기능, UI 테마/안전 영역, 풀링된 UGUI 표면, 패널/픽토그램, 곡면 포인터 입력.
- `Assets/_Project/Presentation/UI/CRT/Shaders/`: 최종 유리 효과와 UI 아이콘 전용 인광 변환. 월드 전체를 황색으로 바꾸는 LUT는 없다.
- `Assets/_Project/Data/Resources/CRT/`: 모니터 5개와 공통 테마 ScriptableObject.
- `Assets/_Project/Presentation/Bootstrap/RunCrtHud.cs`: 런 HUD 표현. 기존 Sim 규칙은 변경하지 않는다.
- `Assets/_Project/Data/Resources/Fonts/`: 한글 Pretendard와 짧은 계기 표기용 IBM Plex Mono Medium. 폰트와 OFL 원문을 함께 포함한다.

## 검증 산출물

`img/runtime`에 기본 1080p, 해상도 하위 폴더에 각 화면비의 검토용 JPG와 `capture-report.json`을 저장한다. 픽셀 검사용 무손실 PNG는 같은 위치에 로컬 보존하되 Git에는 넣지 않는다. 생성 시의 정확한 코드/검증 상태는 작업 기록을 따른다.

최종 자동 검증(2026-09-12): **EditMode 431/431, PlayMode 9/9 통과**, 7개 해상도 **212개 화면 캡처 / 게임·캡처 오류 0**. 실제 High 32-bit HDR의 Abyss glass+잔상 복사 중앙값 합산 참고치는 **1080p 0.346ms / 4K 1.747ms**였다. 4K 잔상은 **7.91MiB**다. 기기·측정 범위와 미검증 항목은 아래 및 작업 기록을 따른다.

QA 자동화는 `CrtRuntimeCapture.Run`이며 제품명에 `CRT Validation`이 있는 격리 프로젝트에서만 작동한다. 사용자의 게임 저장을 테스트 데이터로 덮어쓰지 않는다. 캡처의 GPU 시간은 Editor/D3D12의 해당 출력 포맷에서 측정한 CRT 패스 비용이며, 전체 게임 프레임 성능이나 다른 GPU의 보장은 아니다.

### 성능 정책과 검증 범위

- 현재 프레임의 월드/UI/CRT 출력은 항상 원래 해상도다. 기본 인광은 수평 2탭을 사용해 RGB 분리 포함 소스 샘플 5회이며, Arcade의 넓은 빔 또는 Relay의 전송 에코는 추가 2회를 사용한다.
- 노이즈는 정수 해시, 빔 두께와 동기 띠·외곽 인광은 가벼운 다항식 포락선으로 계산한다. 잔상의 프레임 간 감쇠 상수는 CPU에서 프레임당 한 번 계산해 픽셀마다 같은 지수 계산을 반복하지 않는다.
- Abyss만 선택적으로 이전 인광을 저장한다. 2560×1440보다 픽셀 수가 많은 출력에서는 **잔상 버퍼만 가로·세로 절반**으로 줄이고 선형 보간한다. 현재 글자와 주사선 해상도는 낮추지 않는다.
- 잔상은 지원되는 경우 32-bit RGB HDR, 아니면 원본 컬러 포맷을 사용한다. 지원 조회는 설치된 URP 17.3의 `Blend` 기준과 맞췄다. 초기 `Render/Linear` 조회에서는 불필요한 64-bit 폴백이 선택됐으나, URP와 같은 기준에서는 검증 기기의 32-bit RGB HDR을 사용할 수 있었다. Off·접근성·모니터 전환 시 불필요한 잔상 버퍼를 해제/초기화한다.
- Renderer Feature 비활성 또는 Shader 누락 시에는 최종 CRT 패스를 생략하고 UI 포인터도 평면 좌표로 복귀한다. 단순히 화면만 평면으로 바꾸고 hit test를 곡면으로 남기지 않는다.
- 캡처용 HDR 읽기에는 명시적 sRGB 변환을 적용한다. 검토 JPG/PNG가 어둡게 저장되는 문제를 게임의 밝기나 월드 색보정으로 보상하지 않는다.
- QA 기본값 `-crtHdr 2`는 설치된 URP의 실제 포맷 선택 함수를 호출해 High 설정과 같은 타깃을 만든다. `-crtHdr 1`은 강제 DefaultHDR(이 기기에서는 64-bit) 스트레스 검사, `-crtHdr 0`은 LDR 스모크 검사다. 리포트에는 요청 모드뿐 아니라 실제 CRT 소스/출력/잔상 포맷도 기록한다. **원본 High 품질 설정을 낮추지 않았다.**
- 자동 테스트의 한글 검사는 확정된 유니코드 편집·삭제·커서·제출·재진입이다. 실제 Windows IME 조합/후보창의 수동 검증은 별도로 남아 있다.
