## 프리셋 설계

1. **굴착선 관제관 / Surveyor** — Strong− 기준. 둥근 관, 조밀한 주사선, 가장자리 RGB 분리, 약한 빔 번짐.
2. **방송 정밀관 / Broadcast** — 평평한 유리, 수직 aperture grille, 안정적인 신호, 정밀한 밝은 윤곽.
3. **광산 오락실 / Arcade** — 곡면 shadow mask, 넓은 주사선, 밝은 빔의 두께 변화, 온화한 광 번짐.
4. **장거리 수신기 / Relay** — 수평 대역폭 번짐, 지연 에코, 간헐적 동기 오류와 느린 밝기 롤.
5. **심층 음극관 / Abyss** — 긴 인광 감쇠, 교차 주사, 어두운 유리 외곽, 낮은 빈도의 신호 변동.

이들은 강도 1~5 단계가 아니다. Off, Comfort, Photosensitive는 모니터 종류와 별도 제어한다. Strong− 기본 persistence는 명세 §7에 따라 Off, 시간 잔상은 Abyss에서 선택적으로 사용한다. 기존 Volume 노이즈·비네트와의 중복은 구현 시 실제 화면으로 검증한다.

## 검증 메모 · 03:28 KST

- 실제 High 자산(`UniversalRP.asset`)은 HDR 32-bit, Render Scale 1이다. 초기 QA의 `RenderTextureFormat.DefaultHDR`은 이 GPU에서 64-bit RGBA를 강제했다. 설치된 URP 17.3의 `UniversalRenderPipelineCore.CreateRenderTextureDescriptor`는 외부 RT 포맷이 내부 설정을 덮어쓴다고 명시한다. 따라서 초기 HDR64 측정을 실제 High 기본 포맷과 동일한 조건으로 해석하면 안 된다.

- URP 소스의 UUM-41070 주석을 근거로 잔상 포맷 지원 검사도 `Blend` 기준으로 맞췄다. 별도 `Render/Linear` 조회의 불필요한 폴백 대신 `B10G11R11_UFloatPack32`를 실제 사용할 수 있음을 렌더로 확인했다.
- 첫 4K 추가 최적화 실행은 `boss-rail.png` 원자적 교체의 일시적 IO 오류로 중단됐다. 제한된 5회 재시도(총 대기 최대 500ms)를 추가했으며 영구 잠금은 여전히 실패로 보고한다. 다음 실행은 30개 캡처를 만들었으나 Package Manager 창의 오프라인 취소 2건 때문에 실패 판정됐다. 해당 정확한 Editor 취소 메시지만 `editorIssues`에 원문 보존하도록 분리했다. 일반 패키지/컴파일/셰이더 오류는 무시하지 않는다.
- **재실행 HDR64 스트레스: 4K 30개 캡처, 게임/캡처 오류 0.** CRT 소스 `R16G16B16A16_SFloat`, 잔상 `B10G11R11_UFloatPack32`; Abyss glass 중앙값 **1.015808ms** + history copy **0.410624ms** = **1.426432ms**. 각각 P95 1.029120 / 0.411648ms이며 합산 P95를 뜻하지 않는다. 잔상 **8,294,400B(7.91MiB)**. Setup/Graph 워밍업 후 관측 최대 각각 0B.
