# 땅굴 크루 황색 CRT UI 리뉴얼 기획서

문서 상태: 콘셉트 방향 승인 · 구현 기준 확정  
대상: `unity/TunnelCrew/`  
작성 기준: Unity 6.3.15f1, URP 17.3.0, 2D Renderer  
승인 레퍼런스: [`img/crt-intensity-02-strong.png`](img/crt-intensity-02-strong.png)  
실제 상시 목표: 승인 레퍼런스의 화면 효과를 약 15~20% 낮춘 `Strong−`

> 2026-09-12 후속 요청: 실제 모니터 선택은 단순 강도 단계 대신 서로 다른 신호/인광 구조의 5종(Surveyor, Broadcast, Arcade, Relay, Abyss)으로 구현한다. Surveyor가 Strong− 기준을 계승하며, Off·Comfort·Photosensitive는 별도 설정이다. 이 문서의 초기 강도 표와 승인 시안은 미술 기준으로 보존한다. 현재 구현 및 검증 상태는 [작업 기록](implementation-worklog.md)을 참조한다.

## 1. 목표

땅굴 크루의 화면을 “낡은 탐사선/광산 장비의 황색 CRT 관제 화면”으로 재구성한다. UI 장식만 바꾸는 것이 아니라 월드, HUD, 메뉴, 전환 화면에 같은 표시 장치의 규칙을 적용해 하나의 제품처럼 보이게 만든다.

핵심 목표는 다음 세 가지다.

1. 한 장면만 보아도 땅굴 크루의 고유 UI로 인식되는 황색 인광 언어를 만든다.
2. 스캔라인, 색수차, 곡률, 비네트, 노이즈/지터를 실제 런타임 효과로 구현한다.
3. 전투 판독성과 광과민 접근성을 해치지 않고 1080p 기준 60fps를 유지한다.

## 2. 콘셉트 문장

> 크루가 직접 보는 게임 화면이 아니라, 낡은 굴착선의 CRT 관제 장치가 크루의 탐사를 중계하는 화면.

### 시각 원칙

- **Amber phosphor:** 핵심 정보는 밝은 황색, 보조 정보는 번트 오렌지, 비활성 정보는 갈색 회색으로 제한한다.
- **Industrial terminal:** 둥근 카드 대신 얇은 프레임, 절단 모서리, 눈금, 좌표, 파형을 사용한다.
- **Signal imperfection:** 깨끗한 디지털 글로우가 아니라 미세한 번짐, 주사선, 고정되지 않은 신호를 느끼게 한다.
- **Gameplay first:** 캐릭터, 공격 텔레그래프, 체력, 탄약, 스킬 쿨다운은 어떤 효과보다 앞선다.
- **One device:** 타이틀, HUD, 팝업, 결과 화면이 서로 다른 스킨처럼 보이지 않도록 공통 토큰을 사용한다.
- **One final glass:** 월드와 HUD는 하나의 최종 CRT 패스를 통과한다. HUD만 곧고 깨끗하게 남는 예외 합성은 허용하지 않는다.

## 3. 화면 적용 범위

### 3.1 월드 화면

- **월드에는 황색/세피아 컬러 그레이딩을 적용하지 않는다.** 지층, 캐릭터, 텔레그래프의 원래 색상과 색 대비를 유지한다.
- 곡률, 스캔라인, 색수차, 비네트, 노이즈, 지터는 화면 전체에 적용해 하나의 CRT 화면처럼 보이게 한다.
- 황색 인광 팔레트는 HUD 그래픽과 HUD 패널 안의 표시 정보에만 사용한다.
- 플레이어와 위험 텔레그래프는 기존 색상 규칙을 그대로 유지한다.
- CRT 곡률로 잘리는 영역은 실제 플레이 안전 영역에서 제외한다.

### 3.2 HUD

- 정보 우선순위는 `생존 > 즉시 행동 가능 여부 > 진행도 > 보조 자원` 순서다.
- 좌하단 바이탈은 초상/직업 아이콘, 하트, 탄환, 열 아이콘과 막대·숫자만 남긴다.
- 상단 장악도는 크루 아이콘과 보스 아이콘을 잇는 신호 레일로 표현하며 긴 라벨을 쓰지 않는다.
- 우하단 스킬은 기능 픽토그램, 키캡, 쿨다운 셔터만 표시한다. 스킬명과 설명문은 제거한다.
- XP는 하단 눈금 레일과 현재/목표 숫자만 남긴다.
- 좌상단 상시 조작 가이드와 우상단 렌더/투영 디버그 문구는 일반 플레이 HUD에서 제거한다.
- 직업명, 자원명, 상태 문장은 아이콘만으로 구분할 수 없는 상황에만 한시적으로 표시한다.

### 3.3 메뉴와 오버레이

- 메뉴 버튼은 터미널 행 선택 구조로 통일한다.
- 특성 카드, 제작 휠, 채팅, 관전 HUD도 같은 프레임/색/타이포 토큰을 사용한다.
- 보스 등장과 신호 이상 상태에서는 짧은 동기 불량 연출을 허용하지만 조작 피드백을 가리면 안 된다.

## 4. 컬러와 타이포그래피

초기 디자인 토큰:

| 용도 | 색상 | 비고 |
|---|---|---|
| Phosphor 100 | `#FFD65A` | 제목, 현재 값, 선택 상태 |
| Phosphor 70 | `#E8A92E` | 프레임, 보조 라벨 |
| Phosphor 35 | `#7A4A13` | 눈금, 비활성 선 |
| Panel | `#120C07` / 82% | 반투명 패널 |
| Screen black | `#050302` | 외곽과 빈 영역 |
| Critical | `#FF6A3D` | 위험/치명 상태에만 제한 |
| Cool accent | `#70D7C3` | 아군/회복 등 필수 구분에만 제한 |

- 본문 한글은 현재 프로젝트의 Pretendard를 유지한다.
- 숫자, 키, 좌표, 짧은 영문 라벨은 라이선스가 명확한 모노스페이스 폰트를 추가한다.
- 픽셀 폰트는 장식 제목에만 쓰고 작은 한글 본문에는 쓰지 않는다.
- 최소 본문 크기는 1080p에서 18px, 핵심 수치는 22px 이상을 목표로 한다.

## 5. 필요한 리소스

### 필수 아트

- 9-slice 패널 3종: 일반, 강조, 위험
- 절단 모서리/브래킷/볼트/눈금 장식 아틀라스
- 스킬 슬롯 프레임과 쿨다운 마스크
- 체력/탄약/열/XP용 막대 캡과 틱 마크
- CRT 외곽 안전 프레임 16:9, 16:10, 21:9 대응형
- 직업/보스 아이콘의 단색 인광 변형 또는 셰이더용 마스크
- 메뉴 선택 커서, 경고, 통신, 신호 상태 아이콘

### 필수 기술 자산

- `CRTDisplay.shader`와 머티리얼 프리셋
- 청색 노이즈 또는 저해상도 아날로그 노이즈 텍스처 1장(절차 노이즈로 대체 가능)
- HUD 전용 황색 인광 그라디언트/LUT 1종. 월드 컬러 버퍼에는 적용하지 않는다.
- CRT 설정용 `ScriptableObject` 프리셋 6종: Off, Comfort, Strong−, Strong, Event Heavy, Photosensitive
- 해상도/화면비별 안전 영역 가이드 오버레이

### 선택 리소스

- 전원 켜짐, 릴레이 클릭, 짧은 신호 불량 UI 사운드
- 메뉴 배경용 파형/스펙트럼 애니메이션 데이터
- 아주 약한 유리 얼룩/먼지 마스크. 반복이 보이면 사용하지 않는다.

## 6. 기술 방향

현재 프로젝트에는 URP Volume 기반 Bloom, Film Grain, Vignette, Color Adjustments가 이미 있다. 그러나 스캔라인, 곡률, 지터와 UI까지 포함한 색수차는 별도 최종 합성 패스가 필요하다.

권장 구조:

1. 기존 지층 Volume은 월드 조명과 Bloom을 담당한다.
2. HUD를 현재 IMGUI에서 UGUI `Screen Space - Camera`로 옮긴다.
3. URP 2D Renderer의 `Full Screen Pass Renderer Feature`에 전용 HLSL 머티리얼을 연결한다.
4. 월드와 HUD가 합쳐진 뒤 단 한 번 CRT 패스를 적용한다.
5. 캡처, 접근성 안내, 플랫폼 오버레이처럼 왜곡되면 안 되는 요소만 별도 최상단 Canvas로 둔다.

현재 `RunBootstrap`, `MetaScreens`, `TeamOverlay`의 HUD는 `OnGUI` 기반이다. 이 상태에서는 카메라의 최종 패스가 HUD를 함께 처리하지 못하므로, “화면 전체가 CRT”라는 목표를 달성하려면 UGUI 전환이 기능 선행 조건이다. URP 17.3.0에는 `FullScreenPassRendererFeature`가 실제로 포함되어 있으며, 현재 `Renderer2D.asset`에는 Renderer Feature가 0개다.

## 7. 강도 정책과 접근성

CRT 효과는 하나의 ON/OFF가 아니라 항목별 강도를 가진다.

| 프리셋 | 스캔라인 | 색수차 | 곡률 | 비네트 | 노이즈/지터 | 용도 |
|---|---:|---:|---:|---:|---:|---|
| Off | 0 | 0 | 0 | 기존 Volume만 | 0 | 완전 비활성 |
| Comfort | 25% | 15% | 25% | 25% | 10% | 장시간 플레이/효과 완화 |
| Strong− | 43% | 28% | 39% | 38% | 22% | **상시 기본값** |
| Strong | 55% | 35% | 45% | 50% | 35% | 승인 레퍼런스 비교값 |
| Event Heavy | 75% | 65% | 60% | 65% | 75% | 짧은 상태/전환 연출 |
| Photosensitive | 15% | 0 | 0 | 20% | 0 | 흔들림/플래시 억제 |

- 상시 기본 프리셋은 `Strong−`로 확정한다.
- 곡률은 CRT 정체성을 만드는 핵심이라 승인안 대비 약 13%만 낮춘다. 색수차, 스캔라인 대비, 노이즈는 20~30% 낮춰 눈의 피로를 먼저 줄인다.
- 지터는 상시 최대 0.35px, 이벤트 피크 1.5px 이하로 제한한다.
- 화면 전체 점프는 사용하지 않고 UV의 좁은 가로 밴드만 순간 이동시킨다.
- 색수차는 중앙부보다 외곽에서 강해지며 HUD 본문에는 상한을 둔다.
- 광과민 모드에서는 지터, 플래시성 노이즈, 고주파 밝기 변화를 0으로 만든다.

## 9. 성공 기준

- 무효과 화면과 비교했을 때 1초 안에 CRT 콘셉트가 인지된다.
- 전투 중 플레이어, 위험 텔레그래프, HP, 탄약, 스킬 준비 상태의 오독률이 기존보다 높지 않다.
- 1080p 그래픽 품질 High 기준 CRT 패스 GPU 비용이 목표 0.7ms, 최대 1.0ms 이하다.
- 16:9, 16:10, 21:9에서 핵심 정보가 곡률/비네트 안전 영역 밖으로 나가지 않는다.
- Photosensitive 프리셋에서 시간 변화형 지터와 플래시가 모두 비활성화된다.
- 기존 지층별 조명과 어둠 골격이 황색 등급 때문에 서로 같은 장면처럼 뭉개지지 않는다.

## 10. 콘셉트 시안 해석

[`crt-intensity-02-strong.png`](img/crt-intensity-02-strong.png)의 화면 구조와 HUD 구성을 승인 기준으로 사용한다. 다만 시안은 효과 차이를 보여 주기 위해 과장되어 있으므로 실제 기본 프리셋은 아래 `Strong−` 값으로 시작한다.

| 항목 | 승인 시안 Strong | 구현 시작값 Strong− | 조정 의도 |
|---|---:|---:|---|
| 곡률 | 0.060 | 0.052 | 화면 휨의 정체성은 유지 |
| 색수차 | 1.20px | 0.95px | 캐릭터·아이콘 가장자리 피로 감소 |
| 스캔라인 명암 | 0.120 | 0.095 | 필드 재질과 작은 아이콘 보존 |
| 노이즈 | 0.025 | 0.018 | 정지 화면의 자글거림 완화 |
| 상시 지터 | 0.50px | 0.35px | 신호 감각은 남기고 조준 방해 감소 |
| 비네트 | 0.45 | 0.36 | 이미 어두운 필드 외곽 정보 보존 |
| 인광 잔상 | 0.16 | 0.11 | 밝은 캐릭터의 이중상 완화 |

유지해야 하는 요소는 둥근 화면 실루엣, 월드와 HUD의 동일 곡률, 화면 전역 스캔라인, 외곽 RGB 번짐, 아이콘 중심 HUD다. 줄여야 하는 요소는 스캔라인의 검은 대비, 상시 노이즈, 지속적인 동기선, 밝은 오브젝트의 잔상이다.
